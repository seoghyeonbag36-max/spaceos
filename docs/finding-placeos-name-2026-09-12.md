# PlaceOS 이름 — 도메인·충돌 재조사 (2026-09-12)

브랜드를 `SpaceOS` → `PlaceOS` 로 바꾼 뒤(커밋 c94adcb), **이 이름을 실제로 쓸 수 있는지**
다시 판정한 결과다. `docs/plan-domain-candidates-2026-09-07.md` 를 **대체한다** — 그 문서는
옛 이름 기준이고, 심지어 §3 에서 `placeos` 를 후보에서 **제외**하고 있었다(§5).

- 프로브: **레지스트리에 직접 질의.** `.com/.net/.org/.io/.ai` 는 RDAP, `.kr` 계열은 KISA `whois.kr:43`
- 대조군: TLD 마다 반드시 등록돼 있는 도메인을 함께 질의해 프로브가 살아 있는지 먼저 확인 — **6/6 통과**
- 기계가 읽을 값: `reports/domain_probe_2026-09-12.json`
- 재현: `python scripts/probe_domains.py --json <경로>` (부록 A)

---

## 0. 한 줄 결론

**도메인은 열려 있다. 이름은 붐빈다. 상표는 아직 모른다.**

`placeos.kr` · `placeos.co.kr` · `placeos.io` · `placeos.ai` 는 **전부 미등록**이라 오늘 잡을 수 있다.
그러나 `placeos.com` 은 **같은 업종**(스마트빌딩 OS)의 시드니 회사가 2020 년부터 쥐고 있고,
국내에서는 **네이버 플레이스**와 이름이 겹친다 — 하필 우리가 지도를 빌려 쓰고 M&A 타깃으로
적어 둔 그 네이버다. 상표 선등록 여부는 이 프로브로 **확정하지 못했다**(§4).

## 1. 도메인 — 실측 (2026-09-12)

이 표는 검색이 아니라 **레지스트리의 답**이다. 09-07 문서가 "어느 도메인도 비어 있다고
확인하지 않았다"고 적었던 자리를 여기서 채운다.

| 도메인 | 상태 | 비고 |
|---|---|---|
| **placeos.kr** | ✅ **미등록** | 1순위. 이메일 `@placeos.kr` 10자 |
| **placeos.co.kr** | ✅ **미등록** | 법인 신호가 필요할 때 |
| **placeos.io** | ✅ **미등록** | 옛 이름의 충돌 상대였던 `spaceos.io` 와 달리 비어 있다 |
| **placeos.ai** | ✅ **미등록** | AI 엔진(LSTM·GNN)이 제품 핵심이라 의미가 어긋나지 않는다 |
| placeos.net · .org · .or.kr | ✅ 미등록 | 방어등록용 |
| **placeos.com** | ❌ **등록됨** | 2020-10-27 등록 · 2026-10-27 만료 · Squarespace Domains II LLC → §2 |
| placetwin.kr · .co.kr | ✅ 미등록 | 대안 |
| spacetwin.co.kr | ✅ 미등록 | 09-07 B군 #8 — 여전히 비어 있다 |
| streetos.kr | ✅ 미등록 | 09-07 B군 #6 — 여전히 비어 있다 |
| ~~twinmap.kr~~ | ❌ **등록됨** | 09-07 B군 #5 **탈락** — 그때는 확인하지 않았던 자리다 |
| ~~gongsil.kr~~ | ❌ **등록됨** | 09-07 B군 #7 **탈락** — 같은 이유 |

⚠ **미등록 ≠ 써도 된다.** 도메인 등록과 상표는 별개 절차이고, 동일 업종에 상표가 있으면
도메인이 비어 있어도 쓸 수 없다. §4 를 먼저 읽을 것.

⚠ `.co` 는 whois 서버가 해석되지 않아 **미확인**으로 남겼다. 국내 B2B 후보가 아니라 더 보지 않았다.

## 2. 이름 충돌 — PlaceOS (시드니)

| 항목 | 내용 |
|---|---|
| 이름 | **PlaceOS** — `placeos.com` · `place.technology` |
| 주체 | Place Technology Group (호주 시드니) |
| 무엇 | "The Operating Layer for Intelligent Buildings" — HVAC·출입통제·AV·재실센서를 API 로 묶는 스마트빌딩 통합 레이어 |
| 규모 | 자사 표기 기준 **13년 상용 운영 · 50개국 이상 · 일 27,500+ 공간** |
| 도메인 | `placeos.com` 2020-10-27 등록 (§1) |

**이건 작은 선점자가 아니다.** 09-07 문서가 `spaceos` 를 위험하다고 본 이유가
"`spaceos.io` 가 **인접 업종**(빌딩·부동산 SaaS)이라 M&A 실사에서 걸린다"였는데,
`PlaceOS` 는 **같은 업종의 더 큰 상대**다. 옛 이름에서 새 이름으로 오면서
이 축의 위험은 **줄지 않았다 — 커졌다.**

갈라지는 지점은 있다. 저쪽은 **건물 한 채 안의 설비**를 묶고, 우리는 **상권 단위의 공실·입점**을
읽는다(건물주가 아니라 입점 기업이 고객이다). 시장이 실제로 겹치지는 않는다. 다만
**이름이 같으면 실사·검색·상표에서 그 차이를 매번 설명해야 한다.**

## 3. 국내 충돌 — 네이버 플레이스 (새로 잡힌 것)

09-07 조사에는 없던 항목이다. 옛 이름(`space`)에는 없고 새 이름(`place`)에만 생긴 위험이라
따로 적는다.

**네이버 플레이스**는 네이버 지도에 붙어 가게·업체 정보를 보여주는 국내 대표 서비스다
(사장님용 도구는 '네이버 스마트플레이스'). 겹치는 방식이 셋이다:

1. **같은 화면.** 우리 제품은 **네이버 지도** 위에 상권과 점포를 그린다(`lib/naverMap.ts`).
   그 지도에서 "플레이스"는 이미 네이버의 단어다.
2. **같은 대상.** 네이버 플레이스도 우리도 "이 자리에 어떤 가게가 있나"를 다룬다.
   B2B 미팅에서 `PlaceOS` 는 **"네이버 플레이스 관련 도구"로 먼저 들린다.**
3. **M&A 타깃과 겹친다.** `CLAUDE.md` 의 Exit 목표는 **네이버**/카카오/직방이다.
   인수 후보의 간판 서비스와 이름이 겹치는 것은 협상에서 양날이다 — 설명이 쉬워지는 대신,
   상표 정리 부담을 인수자가 떠안는다.

⚠ 이건 상표 침해 주장이 아니다. "플레이스"는 일반명사에 가까워 네이버가 단독으로 막기 어렵다.
**시장에서의 혼동 위험**을 적은 것이다.

## 4. 상표 — 이 프로브가 확정하지 못한 것

**하지 않았다. 할 수 없었다.** KIPRIS·USPTO·IP Australia 는 모두 브라우저 세션이나 API 키를
요구해서 여기서 프로그램으로 조회할 수 없었다. 웹 검색으로는 `PLACEOS` 등록 기록을 찾지
못했지만, **그건 "없다"가 아니라 "이 경로로는 안 보인다"** 이다. 09-07 문서 §0 이 같은 말을
했고 그 제약은 그대로다.

**사람이 해야 할 조회** — 아래를 끝내기 전에는 명함·제안서·발표자료에 `PlaceOS` 를 확정
브랜드로 적지 않는다.

| 확인할 것 | 어디서 | 무엇을 |
|---|---|---|
| 국내 상표 선등록 | [KIPRIS](https://www.kipris.or.kr) | `PLACEOS` · `플레이스오에스` · `플레이스OS` — **제9류**(소프트웨어)·**제42류**(SaaS)·**제35류**(광고·사업정보)·**제36류**(부동산) |
| 미국 | [USPTO 상표검색](https://www.uspto.gov/trademarks/search) · [TSDR](https://tsdr.uspto.gov/) | 같은 표장. Place Technology 명의 출원이 있는지도 |
| 호주 | IP Australia 상표검색 | `PLACEOS` — §2 의 선점자 본거지다. **여기가 제일 중요하다** |
| 국제 | WIPO Global Brand Database | 마드리드 출원으로 한국을 지정한 건이 있는지 |

## 5. 09-07 문서와의 관계 — 그 문서는 placeos 를 **제외**하고 있었다

기록으로 남긴다. `docs/plan-domain-candidates-2026-09-07.md` §3 의 표에는 이 줄이 있다:

> | ~~placeos~~ | **PlaceOS** ([placeos.com](https://www.placeos.com/)) — 시드니, 스마트빌딩 OS |
> 🔴 **후보에서 제외했다.** 이름·업종이 정면 충돌한다 |

즉 **저장소는 이미 이 이름을 검토했고 탈락시켰다.** 그럼에도 2026-09-12 에 `PlaceOS` 로 간 것은
도메인·상표가 아니라 **의미** 때문이다 — Space 는 물리적 공간 자체, Place 는 사람이 경험하고
의미를 부여한 공간. 빈 공간(공실)에 의미를 더해 place 로 만드는 것이 파는 가치라서 이름을
가치에 맞췄다(커밋 c94adcb).

**그 판단을 뒤집자는 게 아니다.** 다만 09-07 이 🔴 로 본 근거는 §2 에서 확인된 대로
**사실이고 지금도 유효하다.** 이름을 유지하려면 그 비용을 알고 치러야 한다.

## 6. 권고

**지금 (도메인 — 비용이 작고 되돌릴 수 있다)**

1. **`placeos.kr` + `placeos.co.kr` 을 함께 등록한다.** 국내 B2B 가 1차 시장이고 둘 다 비어 있다.
2. **`placeos.ai` 를 방어등록한다.** 국제 노출용이자, `.com` 을 못 쓰는 대체재다.
   `placeos.io` 도 비어 있지만 **빌딩 OS 업계가 `.io` 를 쓰는 관행**(옛 충돌 상대 `spaceos.io`)이라
   오히려 §2 와 더 가깝게 읽힌다 — 둘 중 하나면 `.ai` 다.
3. **`placeos.com` 은 포기한다.** 선점자가 현역이고 같은 업종이라 협상가가 높고,
   설령 사더라도 §2 의 혼동은 남는다.

**그 다음 (상표 — 여기가 진짜 관문이다)**

4. **§4 의 네 곳을 조회한다.** 특히 **IP Australia**. 호주에 `PLACEOS` 등록이 살아 있으면
   국내 사용은 가능해도 **글로벌 확장·M&A 실사에서 반드시 걸린다.**
5. 조회가 깨끗하면 **국내 제9·42류를 즉시 출원한다.** 도메인은 동명 해외 브랜드를 막지 못한다.
6. 조회에서 충돌이 나오면 **식별력을 덧붙이는 쪽**을 먼저 본다 — 단독 `PlaceOS` 대신
   한글 병기나 수식어를 붙인 결합표장. 이름을 통째로 버리는 것보다 싸다.

**막혔을 때 (여전히 비어 있는 대안)**

7. `placetwin.kr` · `spacetwin.co.kr` · `streetos.kr` — 셋 다 §1 에서 미등록을 확인했다.
   `placetwin` 은 **Place 의 의미를 지키면서** §2·§3 의 `OS` 충돌을 피한다.
   09-07 B군의 `twinmap.kr` · `gongsil.kr` 은 **이제 등록돼 있어 탈락**이다.

## 부록 A — 재현

```bash
# 기본 후보 목록 전체
python scripts/probe_domains.py --json reports/domain_probe_2026-09-12.json

# 임의 도메인
python scripts/probe_domains.py placeos.kr placeos.com
```

출력 첫 블록이 **대조군**이다. TLD 마다 반드시 등록돼 있는 도메인을 함께 물어
`registered` 가 나오는지 본다. 하나라도 아니면 그 TLD 의 결과는 판정이 아니다.

⚠ **이 절차가 실제로 오답을 잡았다.** 처음에는 `rdap.org` 하나로 전부 물었는데
`.kr` · `.io` · `.co` 를 모르는 채 404 를 돌려줬고, 그대로 믿었으면 **등록된 도메인을
"미등록"으로 적을 뻔했다**(`twinmap.kr` · `gongsil.kr` 이 실제로 그 경우다).
두 번째로 `urllib` 이 User-Agent 없이 403 을 받았을 때도 대조군이 잡았다.
**음성 결과는 대조군 없이 믿지 않는다.**
