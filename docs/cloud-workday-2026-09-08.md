## A1~A6 공통 실행 계약

각 Cloud 프롬프트에서 이 문서의 해당 ID와 공통 계약을 적용하라고 명시한다. 공통 계약과 ID별 지시를 합쳐 하나의 실행 명세로 사용한다.

### 시작과 인계

1. `AGENTS.md`, `docs/papers/AGENTS.md`를 읽고 저장소와 현재 브랜치·SHA·작업트리 상태를 확인한다. origin에서 `chore/cloud-page-2026-09-08`의 최신 커밋을 확인한다. 선택된 컨테이너의 HEAD가 원격 최신이 아니면 작업 전에 안전하게 동기화한다. 다른 미커밋 변경이 있으면 덮어쓰지 않는다.
2. 첫 작업에는 P0의 조건 D 결과·진행 안내·이 실행표가 존재해야 한다. 이후에는 직전 ID의 원고 내용과 게시 커밋을 확인한다. 없으면 선행 작업의 PR/원격 SHA를 보고하고 해당 집필은 시작하지 않는다.
3. 원격 브랜치가 다른 작업으로 진전했다면 최신 내용을 먼저 읽는다. non-fast-forward 푸시를 강제로 해결하지 않는다. 내용 충돌이나 연구 판단이 필요하면 보고한다.

### 입력과 금지

- 공통 입력은 GitHub에 게시된 `docs/papers/evidence-index.md`의 **조건 D**, `page-study/design-and-variables.md`, `page-study/README.md`, `page-study/reading-ledger.md`, `page-study/evidence-verification.json`, 현재 원고다.

- 새 외부 인용은 추가하지 않는다. 필요한 문헌은 구체적인 `TODO(문헌)`으로 남긴다. GitHub에 읽기 장부가 있다는 사실만으로 이번 Cloud가 원문 전체를 읽었다고 하지 않는다.

- 저자 원문 재배포, 원천 API 재수집, 비용이 드는 LLM 호출, 데이터 재빌드, 비밀정보 게시, 강제 푸시·보호 규칙 우회는 금지한다.

### 문서 통과 조건

아래는 `docs/papers/AGENTS.md`에 따른 **문서 검수명**이며, 기존 pytest 함수가 아니다. 각 항목을 실제로 대조하고 통과·실패·미실행을 구분한다.

- `SECTION_SCOPE`: 이번 diff가 해당 ID의 허용 파일·절 안에만 있다. 지정 절 밖의 기존 글·수치·FILL을 바꾸지 않았다.
- `EVIDENCE_MATCH`: 새 본문에 사용한 수치마다 조건 D 근거 ID·원천·모집단·분모·해석 제한이 맞는다. 숫자 문자열 검색만으로 통과시키지 않는다. 수치가 없으면 미사용으로 적는다.
- `NO_NEW_CITATION`: 새 외부 인용·미확인 저자/연도·미확인 문헌 주장이 없다. 미확인 문헌은 TODO로 남았다.
- `FILLS_AND_LIMITS`: FILL을 제거한 자리에 실제 본문이 있으며 기각·한계·미측정이 보존됐다. 현실 정답 부재, 전체 파이프라인·클라우드·독립 팀 재현 미평가를 성공으로 바꾸지 않았다.
- `LINKS_AND_DIFF`: 변경 문서의 로컬 링크·앵커가 존재하고 `git diff --check`가 통과했다.
- `REMOTE_HANDOFF`: 이번 커밋이 지정 원격 브랜치에 포함되고 기존 draft PR이 같은 head를 가리킨다. 로컬 커밋만으로 푸시 완료를 선언하지 않는다.

### 커밋·푸시·PR·머지

- 필요한 변경을 명시 경로로 stage하고 한국어 커밋 후 `chore/cloud-page-2026-09-08`에 푸시한다. 같은 draft PR의 제목·본문을 최종 산출물 중심으로 다시 쓴다. 줄바꿈이 있는 PR 본문은 구조화된 인자 또는 body-file을 사용한다.
- PR을 준비 완료로 전환한다. 이미 열린 해당 PR을 재사용하고 중복 PR을 만들지 않는다.
- 최종 검수한 PR head SHA를 기록하고 머지 직전에 다시 대조한다. 머지 요청에도 그 SHA가 일치해야 한다는 조건을 걸 수 있는 GitHub 기능을 사용한다. 그 사이 head가 바뀌면 새 커밋을 재검수하고 현재 SHA의 CI·리뷰를 확인한 뒤 진행한다.
- 최신 head의 검수·CI·필수 리뷰·충돌 조건이 충족되면 main으로 머지한다. 가능하면 merge commit 방식을 사용해 절별 커밋을 보존한다. 저장소가 rebase merge만 허용하면 검수한 각 절의 커밋 경계를 보존하는 방식으로 진행한다. squash만 허용되어 절별 이력을 보존할 수 없다면 정책을 바꾸거나 우회하지 말고 충돌하는 요구를 보고한다.
- force push, main 직접 푸시, 관리자 우회, 리뷰/체크 무시는 금지한다. 이 PR 이외의 다른 PR은 머지하지 않는다.
- 요청한 머지가 실제로 완료됐는지 GitHub의 merged 상태·merge SHA와 origin/main 반영을 확인한다. auto-merge 예약 또는 merge queue 대기만이면 '머지 대기'로 보고한다.
- main 변경에 따른 기존 CI·Deploy 실행 상태를 확인한다. 워크플로 설정을 바꾸거나 수동 재배포하지 않는다. 머지 완료와 배포 완료를 구분한다. 배포가 진행 중이면 그 상태를 적는다.
- 실패·권한 부족·필수 리뷰 대기라면 가능한 작업과 PR까지 보존하고 정확한 차단 단계, PR URL, 필요한 사용자 조작만 남긴다. 추가 승인이 필요 없는 범위는 끝까지 수행하되, 미완료를 완료로 표시하지 않는다.

최종 응답 형식: 작성 완료 절 / 남은 절·자료 / 검수와 CI / 원격 커밋 SHA / PR URL / 머지 여부와 merge SHA / 후속 CI·배포 상태.
