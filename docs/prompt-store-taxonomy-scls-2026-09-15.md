## 왜 이 작업이 남았나

`편의점` · `약국` · `커피전문점` 세 라벨은 **소분류(`indsSclsNm`)로만 갈린다.**
중분류로는 가를 수 없다 — `종합 소매`(483건) 안에 편의점·슈퍼·잡화가 같이 있고,
`의약·화장품 소매`(443건) 안에 약국·화장품 가게가 같이 있다. 중분류를 그 라벨로
사상하면 슈퍼와 화장품 가게까지 편의점·약국이 된다.

그런데 **소분류 표본이 저장소에 없다.** Bronze(`stores_raw.json`)는 커밋되지 않고,
커밋된 Gold(`vacant_units.grp`)는 중분류만 담는다. 그래서 이 세 규칙은 지금
**미검증 문자열 추측**으로 돌고 있다(`"편의점"` · `"약국"` · `"카페"/"커피"/"다방"/"찻집"`).

**Bronze 가 있는 데서만 확정된다.** 그 실행이 이 프롬프트다. API 콜은 0이다.

## 확정된 사실 (다시 규명하지 말 것)

1. 소스는 소상공인 상가(상권)정보 `bronze/{거점}/{날짜}/stores_raw.json` 이다.
   응답 필드 39개는 확정돼 있다 — `data/logs/probe_d1_2026-07-07.log` (2026-07-07 실측).
   업종 계층은 `indsLclsNm`(대) / `indsMclsNm`(중) / `indsSclsNm`(소) 셋이다.
2. 계층별 클래스 수도 확정이다(2026-08-17 실측,
   `docs/finding-sequence-and-accuracy-2026-08-17.md` §6):
   대분류 **10** / 중분류 **75** / 소분류 **247** / KSIC 306.
3. **중분류는 이미 실측해 규칙에 반영했다**(2026-09-15, finding §7-2-5).
   커밋된 Gold 135파일에서 실제 중분류 65종을 뽑아 쟀다:
   - 어휘 기준 사상 3.1% → **23.1%**(15/65종) · 등장 기준 6.6% → **47.0%**
   - 사상되는 중분류: 한식·주점·기타 간이·서양식·일식·중식·동남아시아·구내식당뷔페
     (→음식점) · 의원·병원·기타 보건(→병원) · 비알코올(→카페) ·
     일반 숙박·기타 숙박(→숙박) · 도서관·사적지(→문화시설)
   - 그 감사가 오사상 1건을 잡았다: `'음료'` 로 카페를 판정해 **'음료 소매'(26건)**
     가 카페가 됐다. `RETAIL_MARKER`("소매") 로 막아 뒀다.
   **중분류 상수(MCLS_*)를 다시 만들지 말 것.** 이미 있고 테스트가 고정하고 있다.
4. 라벨 어휘는 **7종이고 문자열까지 고정**이다 — 음식점·카페·편의점·병원·약국·
   숙박·문화시설. 서빙 체크포인트(`ml/artifacts/industry_gnn.pt` 의 `classes`)와
   같아야 하므로 **이름을 바꾸면 안 된다.**
5. 공방·배달전문은 **분류체계에 아예 없다**(mcls 75·scls 247·ksic 306 전수 검색 0건).
   찾지 말 것 — `UNMAPPABLE_DEMAND` 에 그 사실이 적혀 있다.

## 해야 할 일

1. 전 거점 감사를 돌리고 출력을 **그대로** 파일로 남긴다.

       mkdir -p reports/logs                     # gitignore 대상이라 새 클론에는 없다
       PYTHONIOENCODING=utf-8 python -m data.config.store_taxonomy --audit \
         > reports/logs/taxonomy_audit_$(date +%Y%m%d).log 2>&1

   ⚠ `PYTHONIOENCODING=utf-8` 는 생략하지 말 것 — Windows 기본 cp949 에 `—`(em dash)가
   없어 리다이렉트 시 UnicodeEncodeError 로 죽는다(CLAUDE.md, 08-19 실측).

   이 출력이 근거다. 사상률·미사상 대분류 상위 10·미사상 소분류 상위 25 가 찍힌다.

2. **미사상 소분류 상위 25 를 보고** 7종에 속하는 것을 골라낸다. 특히 이 셋의
   **실제 문자열**을 확정한다(지금은 추측이다):
   - 편의점  — 중분류 `종합 소매` 하위. 소분류가 정확히 무엇인가
   - 약국    — 중분류 `의약·화장품 소매` 하위. 소분류가 정확히 무엇인가
   - 커피전문점 — 중분류 `비알코올` 하위. `커피전문점/카페/다방` 인지 다른 표기인지

   ⚠ 추측을 코드에 넣지 말 것. 감사 출력에 그 문자열이 **보이는 것만** 넣는다.
   보이지 않으면 `--audit garosugil` 로 한 거점만 좁혀 다시 보고, 그래도 없으면
   "그 소분류는 이 표본에 없다"를 결론으로 적는다.

3. `data/config/store_taxonomy.py` 에 소분류 상수를 중분류와 같은 모양으로 추가한다.

       SCLS_CVS = (...)        # 편의점 — 실측 문자열
       SCLS_PHARMACY = (...)   # 약국
       SCLS_CAFE = (...)       # 커피전문점·다방·찻집

   주석에 **출처를 남긴다**: 어느 감사 로그·어느 날짜·등장 몇 건인지.
   (중분류 상수가 이미 그 양식이다 — 그대로 따를 것.)

4. 판정 순서를 유지한다. `to_category_group` 은 **좁은 것부터** 본다 —
   ① 약국 ② 편의점 ③ 카페 ④ 병원 ⑤ 숙박 ⑥ 문화시설 ⑦ 음식점.
   순서를 바꾸면 카페가 음식점으로, 약국·편의점이 소매로 접힌다(2026-08-17 실측).

5. 테스트를 추가한다 — `data/tests/test_store_taxonomy.py` 에 **실측 문자열**로:
   - `test_real_sub_category_vocabulary_maps` — 감사에서 확인된 소분류 → 7종
   - `test_convenience_store_and_pharmacy_need_sub_category` — 중분류만 오면
     `종합 소매`·`의약·화장품 소매` 가 **None** 이고, 소분류가 붙으면 편의점·약국이 된다
   기존 오사상 차단 테스트(`test_real_vocabulary_that_must_not_map` ·
   `test_retail_marker_blocks_cafe_and_hospital`)를 **약화시키지 말 것.**

6. 재측정하고 **전수 사상률**을 기록한다. 이게 이 작업의 산출물이다 —
   지금까지 남은 수치(47.0%)는 공실·저활성 건물 표본이라 전수가 아니다.

7. 결과를 문서에 남긴다:
   - `docs/finding-map-provider-google-2026-09-15.md` §7-2-5 에 전수 수치를 추가
   - 소분류 어휘 목록이 길면 `docs/finding-store-taxonomy-scls-{날짜}.md` 로 분리
   - `data/config/store_taxonomy.py` 머리말의 "⚠ 소분류 어휘는 아직 실측하지 못했다"
     문단을 **실측 결과로 교체**한다(지우지 말고 경위를 남길 것)

## 금지 사항

- **7종 라벨 문자열 변경 금지** — 체크포인트 `classes` 와 어긋나면 서빙이 깨진다
- **중분류를 편의점·약국으로 사상 금지** — `종합 소매`→편의점은 슈퍼·잡화까지,
  `의약·화장품 소매`→약국은 화장품 가게까지 접는다. 소분류로만 가른다
- **유원지·오락(299) · 스포츠 서비스(279) 를 문화시설에 넣지 말 것** —
  카카오 CT1 의 모집단은 박물관·미술관·영화관·공연장이다
- **`RETAIL_MARKER` 차단을 풀지 말 것** — '음료 소매' 오사상이 되돌아온다
- **`build_gold` 를 돌리지 말 것** — 이 작업은 규칙만 고친다. Gold 재생성은
  finding §7-2-2 런북의 별도 단계다(program_content_context 66개를 통째로 다시 쓴다)
- **`train_gnn` 재학습 금지** — 라벨 어휘가 7종→8종으로 움직이고 기준선이
  89.7%↔69.9% 로 갈린다(finding §7-2-3). 값을 보고 결정할 **별도 판단**이다
- **카카오 로컬을 되살리지 말 것** — 응답 저장은 약관 위반이다(finding §7-2).
