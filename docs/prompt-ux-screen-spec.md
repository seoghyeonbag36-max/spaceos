# UX/UI 화면설계서 프롬프트 양식 (지도 고정 셸 · 거점 선택)

> 용도: **화면설계서를 뽑아내는 프롬프트**의 양식이다. 코드를 짜라는 프롬프트가 아니라,
> 코드로 넘기기 전 단계인 *화면설계서(레이아웃·상태·데이터 바인딩·통과조건)*를 받는다.
> 붙여넣는 곳: Claude Code(`claude`) 또는 Cursor Composer. 형제 문서: [DESIGN-VIBE-PROMPTS.md](DESIGN-VIBE-PROMPTS.md)
>
> 이 양식에는 **불변 조건 2개**가 박혀 있다(§1). 슬롯(§2)만 갈아끼우고 §3을 통째로 복사한다.

---

## 0. 어휘 — PPPP 는 4P 와 1:1 이다 (2026-09-05 재정의)

설계서에 트랙 이름을 쓸 때는 이 대응을 그대로 쓴다. **종전 라벨(`Product/Price → Page`,
`Promotion → Posting`)을 다시 쓰지 않는다.**

| 전환 | 탭 | 그 화면이 답하는 질문 |
|------|----|----------------------|
| **Place ▶ Platform** | Platform | 이 입지·상권은 **어떤 플랫폼인가?** (SNS·디지털 관점의 공간) |
| **Product ▶ Page** | Page | 이 platform 안에 **어떤 page 가 만들어져야 하는가?** |
| **Price ▶ Posting** | Posting | **어떤 가격대의 page** 가 이 platform 에 posting 되어야 하는가? |
| **Promotion ▶ Program** | Program | posting 한 page 를 **어떤 홍보 program** 으로 돌릴 것인가? |

화면 문구를 정할 때 이 질문이 곧 그 탭의 헤드라인이다 — 정본은 `CLAUDE.md` §PPPP Framework.

## 1. 불변 조건 — 지우거나 완화하지 않는다

### C1. 중앙은 네이버 지도 전체 화면으로 고정한다

- 지도는 **배경**이고 나머지는 전부 그 위에 뜬 오버레이다. 패널이 지도를 밀어내면 위반.
- 지도 컨테이너: `position: fixed; inset: 0 0 0 var(--rail-w)` — 좌측 아이콘 레일(64px,
  모바일 52px) 오른쪽 전부. 이미 `apps/frontend/src/pages/MapShell.css` 가 이 규칙 위에 서 있다.
- **지도 인스턴스는 앱 수명 동안 하나다.** 탭(서울·거점·Platform·Page·Posting·Program — §0 의 4P 대응)을
  바꿔도 지도를 언마운트·재생성하지 않는다. SDK 재초기화 비용도 문제지만, 더 큰 손실은
  사용자가 맞춰 둔 카메라(중심·줌)가 사라지는 것이다. 탭은 **오버레이 세트만 갈아끼운다.**
- 지도 캔버스에 `inset:0` 만 주지 말 것 — SDK 가 컨테이너 position 을 relative 로 덮어써서
  높이가 0 으로 접힌다(2026-08-01 실측). `width/height:100%` 를 같이 준다.
- z 축은 셋뿐이다: **지도 0 · 오버레이 5 · 모달 20.**

### C2. 거점 탭에서 거점 하나를 고르면, 지도 전체화면 안에서 경계 + 요약이 나온다

- 거점 선택은 **화면 전환이 아니다.** 같은 지도 위에서 (a) 카메라가 그 거점으로 날아가고,
  (b) 경계가 그려지고, (c) 요약 오버레이가 뜬다. 별도 페이지로 나가면 위반.
- 거점 수는 **하드코딩하지 않는다.** 서빙 목록은 `data/config/page_hubs.ACTIVE_HUBS`
  (2026-09-05 기준 66) 이고, 프론트는 `GET /api/v1/commercial-districts` 응답 길이로 센다.
  화면 문구에 "66"을 박으면 거점이 늘 때 조용히 거짓말이 된다.
- 경계는 **근거를 골라 화면에 밝힌다** — §6. 근거 없는 예쁜 폴리곤은 금지.

## 2. 채워 넣는 슬롯

| 슬롯 | 뜻 | 예 |
|------|----|----|
| `{{화면명}}` | 설계서 대상 화면 | 거점 탐색(Hub Explorer) |
| `{{진입점}}` | 어느 탭/경로에서 오는가 | 좌측 레일 「거점」 |
| `{{주사용자}}` | 누가 무엇을 결정하려고 보는가 | 프랜차이즈 출점팀 — 다음 출점 후보 거점 3곳 추리기 |
| `{{한 화면의 결론}}` | 이 화면을 닫을 때 손에 남는 것 | "이 거점은 들어갈 만한가"에 대한 예/아니오와 근거 |
| `{{경계 근거}}` | §6 에서 A·B·C 중 택1 | B — 실측 커버리지 외곽 |
| `{{요약 지표}}` | 요약 패널에 실을 필드(§5에서 고른다) | vacancy_rate · building_count · anchor_gap_pp · predicted_* |
| `{{제외}}` | 이번 설계서에서 다루지 않을 것 | 층별 목록·거리뷰(별도 화면) |

# 먼저 읽기 (추측하지 말고 실제 파일을 읽는다)
- apps/frontend/src/pages/MapShell.tsx / MapShell.css   ← 지도 셸의 현재 골격
- apps/frontend/src/pages/PageDashboard.tsx             ← 지금의 「거점」 탭(카드 보드)
- apps/frontend/src/components/DistrictPicker.tsx       ← 거점 선택 + 예외(caveat) 표식

화면명: {{화면명}} / 진입점: {{진입점}}
주사용자: {{주사용자}}
이 화면의 결론: {{한 화면의 결론}}
이번에 다루지 않는 것: {{제외}}

# 불변 조건 (완화 금지 — 어길 수밖에 없다면 설계서를 내지 말고 먼저 그 이유를 보고한다)
C1. 중앙은 네이버 지도 전체 화면 고정.
    - 지도는 배경(fixed, inset:0 0 0 var(--rail-w)), 나머지는 전부 오버레이.
    - 패널·리스트·시트가 지도를 밀어내거나 지도 폭을 줄이지 않는다.
    - 지도 인스턴스는 앱 전체에서 1개. 탭 전환 시 언마운트/재생성 금지, 오버레이만 교체.
    - z 축 3단: 지도 0 / 오버레이 5 / 모달 20.
C2. 「거점」 탭에서 거점 하나를 고르면 같은 지도 안에서 세 가지가 동시에 일어난다.
    (a) 카메라 이동: 그 거점 center 로 fitBounds(경계 + 패딩). 애니메이션 400ms 이내.
    (b) 경계 표시: 근거 = {{경계 근거}} (docs/prompt-ux-screen-spec.md §6 의 정의를 그대로 쓴다).
        경계에는 근거 배지를 반드시 붙인다. 근거 없는 폴리곤 금지.
    (c) 요약 오버레이: 그 거점의 전반 정리. 실을 필드는 {{요약 지표}}.
    거점 선택으로 다른 페이지로 넘어가지 않는다. 거점 수는 API 응답 길이로 센다(하드코딩 금지).

# 데이터는 실제 계약만 쓴다
- 거점 목록/요약: GET /api/v1/commercial-districts → DistrictSummary
- 거점 상세(구역·POI): GET /api/v1/commercial-districts/{id} → DistrictDetail.zones (행정동 실측 구역)
- 공실 격자: GET /api/v1/heatmap/vacancy?district={id}
- 건물 폴리곤: GET /api/v1/heatmap/buildings?district={id}
없는 필드를 상상해서 쓰지 말 것. 필요한데 없으면 "없음 — 신설 필요"로 적고 어느 파일에
무엇을 더해야 하는지 명시한다(백엔드 스키마 경로까지).

# 값의 성격을 화면이 숨기지 않는다 (SpaceOS 고유 규칙)
- vacancy_source: "gold"(실측) / "synthetic"(합성) 을 배지로 가른다.
- vacancy_rate === null 은 두 뜻이다. vacancy_withheld=false → 재지 않았다,
  true → 쟀지만 거점을 대표하지 못해 내렸다. 문구를 갈라 쓴다.
- caveat 가 있으면 "다른 거점과 나란히 비교하지 말라"는 뜻이다. 표식(▣ 단일시설 /
  ▤ 계획상가 밀집 / ▨ 대표값 미제공)과 전문을 같이 보여준다.
- 감성 s·d·r 은 null 이다(미측정). 0 으로 그리지 말고, 공실률을 감성 자리에 옮겨 그리지 말 것.
- 해상도(집계구/행정동/TRDAR)와 출처(R-ONE 등)는 범례 배지로 밝힌다.

# 산출 형식 (이 목차 그대로, 표는 표로)
1. 화면 목적 — 한 문장. 이 화면이 못 하게 막는 오해도 한 줄.
2. 레이아웃 맵 — ASCII 와이어프레임 1장. 좌측 레일 / 지도 / 오버레이 슬롯(top·left·bottom·
   legend)의 좌표·크기·z-index 를 숫자로. 데스크톱(≥1024) + 모바일(<768) 2벌.
3. 상태표 — 각 상태에서 지도·오버레이가 어떻게 보이는지 행으로:
   초기 / 거점 미선택 / 로딩 / 거점 선택됨 / 경계 없음 / 데이터 결손(withheld) /
   예외 거점(caveat) / API 실패 / 지도 인증 실패. "빈 화면"은 상태가 아니다 — 문구를 적는다.
4. 상호작용 — 트리거 → 반응 → 소요시간 목표. 지도 카메라·경계·요약·URL 해시 동기화 포함.
   키보드(Tab/Esc/↑↓)와 포커스 이동도 적는다.
5. 데이터 바인딩 표 — 화면 요소 | API 필드 | 없을 때 문구 | 출처 배지.
6. 근거 표기 규칙 — 어떤 배지를 어디에 붙이는가.
7. 토큰 — 쓰는 색·간격·radius 를 토큰 이름으로만. 하드코딩 hex 금지.
8. 접근성 — 대비 AA, 지도 위 텍스트 가독성, 스크린리더에서 거점 선택 알림(aria-live).
9. 통과 조건 — 사람이 눌러서 확인할 수 있는 문장으로 5~8개.
10. 미해결 — 결정이 필요한 것과 누가 정해야 하는지.

## 4. 왜 이런 목차인가

- **2번(레이아웃 맵)을 숫자로 받는 이유**: "지도를 크게"는 검증할 수 없다. `inset: 0 0 0 64px`
  는 검증할 수 있다.
- **3번(상태표)이 통과조건의 절반**: 이 프로젝트에서 화면이 거짓말하는 지점은 거의 전부
  *값이 없을 때*다(미측정·미제공·예외). 상태를 먼저 적게 하면 그 자리가 빈칸으로 남지 않는다.
- **5번(데이터 바인딩)이 상상 필드를 막는다**: 없는 필드를 쓴 설계서는 코드 단계에서
  조용히 더미로 채워진다.

## 5. 요약 오버레이에 쓸 수 있는 실제 필드 (`DistrictSummary`)

`GET /api/v1/commercial-districts` 한 방으로 서빙 거점이 전부 온다. 거점 하나 요약은 이 안에 있다.

| 필드 | 뜻 | 화면에서 주의 |
|------|----|---------------|
| `name` · `gu` · `city_name` | 거점명 · 자치구 · 도시 | 도시가 섞이므로 `city` 로 묶는다 |
| `vacancy_rate` | 거점 대표 공실률(%) | **null 이 두 뜻** — `vacancy_withheld` 와 함께 읽는다 |
| `vacancy_withheld` | 쟀지만 대표성이 없어 내렸다 | true 면 "대표값 미제공"으로 적는다 |
| `vacancy_source` | `gold`(실측) / `synthetic`(합성) | 배지 필수 |
| `building_count` · `precision_pct` | 집계에 쓴 건물 수 · 마스터 전체 대비(%) | Gold 경로에서만 채워진다 |
| `inventory_coverage_pct` | 분모가 상업 재고에서 차지하는 비율(호실 기준) | 낮을수록 대표값을 믿을 이유가 준다 |
| `vacant_units` · `store_count` · `cell_count` | 공실 호실 · 점포 · 격자 셀 | |
| `anchor_pct` · `anchor_gap_pp` | R-ONE 중대형상가 대비 격차(%p) | 모집단이 달라 **격차 0 이 정상은 아니다** — 거점 간 비교용 |
| `predicted_rate` · `predicted_delta` · `predicted_direction` | LSTM 다음 분기 예측 | 미배포 시 null |
| `tier_mix` | premium/value/factory 구성 | |
| `caveat` · `measured_only` | 예외 사유 · 시드 없이 Gold 만으로 선 거점 | 있으면 비교 금지 표식 |
| `sentiment` · `reviews` · `risk_zones` | 감성 축 | **전 거점 null(미측정)** — 0 으로 그리지 말 것 |
| `rec_top` · `note` · `center` · `type` | 추천 업종 · 메모 · 중심좌표 · 유형 | |

구역 단위(행정동 실측)는 `GET /commercial-districts/{id}` 의 `zones[]` —
`n`(행정동명) · `stores` · `buildings` · `capacity` · `active` · `vacancy_rate`, 그리고
`s`/`d`/`r`=null. 구역 수는 거점마다 1~11개로 다르다(중앙 3).

## 6. 경계(boundary) 근거 — 셋 중 하나를 고르고, 화면에 밝힌다

**지금 시스템에 "거점 경계 폴리곤"이라는 데이터는 없다.** `district_zones.json` 은
행정동 *이름과 중심점*만 갖는다. 그러니 경계는 셋 중 하나를 골라 만들고, 무엇으로 그린
선인지 화면이 말해야 한다.

| 안 | 무엇으로 긋나 | 필요한 것 | 정직한 라벨 |
|----|---------------|-----------|-------------|
| **A. 수집 반경 원** | `page_hubs` 의 `cx/cy` + `radius_m`(거점당 200~800m) | 백엔드가 `radius_m` 을 `DistrictSummary` 에 실어야 한다(현재 없음) | "수집 반경" — 상권 경계가 아니다 |
| **B. 실측 커버리지 외곽** ⭐ | `/heatmap/vacancy` 의 값 있는 셀 유니온 외곽선, 또는 `/heatmap/buildings` 폴리곤의 외곽 | **추가 수집 없음.** 프론트에서 계산 가능 | "실측 범위 — 이 안이 실제로 재어진 곳" |
| **C. 행정동 경계** | `zones[].n` → SGIS/V-World 행정동 폴리곤 조인 | 행정동 경계 신규 수집 + Gold 산출물 1종 | "행정동 경계(실측 구역)" |

**권장: 지금은 B, 목표는 C.** B 는 오늘 그릴 수 있고 "재어진 범위"라는 참말을 한다.
A 는 수집 파라미터를 상권 경계처럼 보이게 해서 가장 위험하다 — 쓰려면 라벨을 반드시 "수집 반경"으로.
C 로 갈 때는 `/verify` 로 A·B 와의 면적 차이를 재고, 대표 공실률의 분모가 바뀌는지 먼저 확인한다.

> 경계선 스타일도 근거를 따른다: 실측(B·C)은 실선, 근사(A)는 파선. 색은 토큰
> `brand.primary`(#0EA5B7) 계열 — 공실 색계열(vacancy)을 경계에 쓰면 값과 경계가 섞여 읽힌다.

## 7. 통과 조건 양식 (설계서 9번에 이 형태로 쓴다)

사람이 눌러서 참·거짓을 가릴 수 있는 문장만 쓴다.

```
- [ ] 「거점」 탭에서 다른 탭으로 갔다 돌아와도 지도 중심·줌이 그대로다(재생성 없음).
- [ ] 거점을 고르면 400ms 안에 카메라가 멈추고, 경계와 요약이 같이 떠 있다.
- [ ] 경계 옆 배지가 A/B/C 중 무엇으로 그린 선인지 말한다.
- [ ] vacancy_withheld=true 인 거점(예: banpo)에서 요약이 "0%"가 아니라 "대표값 미제공"을 낸다.
- [ ] caveat 가 있는 거점에서 비교 금지 표식과 문구 전문이 보인다.
- [ ] 1024px 이하로 줄여도 오버레이가 지도를 밀어내지 않는다(지도 폭 = 뷰포트 − rail).
- [ ] 거점 목록 개수가 API 응답 길이와 같다(문구에 상수 없음).
- [ ] 지도 인증 실패 시 회색 빈 화면이 아니라 원인·조치 문구가 뜬다.
```

검증은 `/verify` — `npm run build`(타입체크) + 로컬 앱을 띄워 지도 픽셀까지 본다.
