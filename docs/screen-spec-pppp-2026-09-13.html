흐름과 인계

공통 프레임

네 화면이 같은 틀 위에 선다. 여기 적은 규칙은 트랙마다 반복하지 않는다.

불변 조건 양식 §1

C1 · 지도는 배경이고 하나다

  • 네이버 지도 캔버스가 뷰포트 전체(position:fixed; inset:0)를 쓰고, 나머지는 전부 그 위 오버레이다. 패널이 지도를 밀어내면 위반.
  • 지도 인스턴스는 앱 수명 동안 하나. 탭을 바꿔도 언마운트·재생성하지 않고 오버레이만 갈아끼운다.
  • 캔버스는 width/height:100% 를 같이 준다(SDK 가 position 을 덮어써 높이가 0 이 되는 함정).

C2 · 상권 선택은 화면 전환이 아니다

  • 상권을 고르면 같은 지도 안에서 카메라 이동 · 트랙별 표식 · 패널 내용이 함께 바뀐다. 다른 페이지로 넘어가지 않는다.
  • 상권은 네 트랙이 공유한다(인계 표 첫 줄).
  • 거점 수·건물 수 같은 가변 숫자는 문구에 박지 않고 API 응답에서 센다.

공통 통과 조건 양식 9번

  1. 레일에 PlaceOS 로고와 Platform · Page · Posting · Program 네 버튼만 있다.
  2. 네 탭을 오가도 지도가 깜빡이거나 다시 만들어지지 않는다(표식만 바뀐다).
  3. 트랙 패널의 ‹ 를 누르면 지도가 화면 전체가 되고 포커스가 「☰ …」 버튼에 있다. 다시 누르면 패널이 열리고 포커스가 ‹ 에 있다.
  4. 검색칸·입력칸에서 Esc 를 눌러도 패널이 닫히지 않는다.
  5. 상권을 바꾸면 스크린리더가 상권 {이름} 선택됨 을 읽고, 다른 탭을 열어도 같은 상권이다.
  6. 지도 인증 실패 시 회색 빈 화면이 아니라 원인·등록할 origin 문구가 뜨고 패널은 계속 쓸 수 있다.
  7. 768px 이하에서 패널은 하단 시트가 되고 지도 폭이 줄지 않는다.

통과 조건 양식 9번

  1. 상권의 공공 문화행사가 지도 칩과 「오프라인 홍보 장소」 목록에 같은 수로 뜨고, 종료일이 지난 행사는 둘 다에서 빠진다(뺀 수를 적는다).

  3. 가게명을 검색하면 후보가 목록과 지도 칩으로 함께 뜨고, 어느 쪽을 눌러도 같은 가게가 채워진다.
  4. 「예시 채우기」 → 「마케팅 솔루션 생성」 → 결론 줄이 온라인·오프라인 건수를 말한다.
  5. LLM 을 타지 못하면 결론 줄에 규칙 기반 스텁 이 남는다(상세를 접어도).
  6. 상용 온보딩은 API 키와 네 동의를 모두 채워야 생성 버튼이 켜진다.
  7. Posting 에서 넘어오면 「입점 예정 자리」 안내·지도 핀이 뜨고, 「비우기」를 누르면 둘 다 사라진다.
