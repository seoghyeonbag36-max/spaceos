# 인프라 층 — 결정이 필요한 것 (2026-08-25)

> **이 문서는 진행률 보고가 아니라 결정 요청이다.** PPPP 게이트 22개는 **분석
> 파이프라인**만 센다. 그 22개가 전부 100% 가 되어도 아래 층은 0% 인 채로 남는다 —
> 덜 한 것이 아니라 **아직 시작하지 않은 트랙**이기 때문이다.
>
> 진행률(`scripts/pppp_status.py`)로는 이 사실이 절대 드러나지 않는다. 그래서 따로 적는다.

## 1. 지금 실제로 서 있는 것 / 아닌 것

전부 이 저장소를 직접 세어 확인한 값이다(2026-08-25).

| 층 | 실태 | 근거 |
|---|---|---|
| **서빙 API** | ✅ 선다 | FastAPI + Gold 파일 직독. Vercel 서버리스 1함수(`api/index.py`) |
| **프론트** | ◐ 선다 | 화면 4개(MapShell·PageDashboard·ProgramStudio·SeoulDashboard). **라우터 없음** — `App.tsx` 가 상태로 화면을 가른다 |
| **DB** | ⛔ **없다** | `app/models/` 에 `__init__.py` 뿐. ORM 모델 0개 · 마이그레이션 0건 |
| **PostgreSQL/PostGIS·Redis·Celery** | ⛔ **코드에 없다** | `requirements.txt` 에만 있다. `app/` 전체에서 import 0건 |
| **파이프라인 오케스트레이션** | ⛔ 없다 | Airflow DAG **0건**. 수집·가공이 전부 수동 스크립트 |
| **CI/CD** | ◐ **CI 만 섰다**(2026-08-25 오후) | `.github/workflows/ci.yml` — 백엔드·데이터 pytest + 프론트 tsc/빌드. CD 는 여전히 없다(`infra/k8s/` 는 `.gitkeep` 만) |
| **인증·테넌시** | ⛔ 없다 | JWT/OAuth 0건. 계정·권한·조직 개념 자체가 없다 |
| **과금** | ⛔ 스텁 | `api/v1/payments.py` 의 reserve/apply 가 전부 `TODO` 주석 |

### ⚠ 함정 하나 — compose 는 있는데 앱이 안 쓴다

`infra/docker/docker-compose.yml` 은 **postgis 16-3.4 + redis 7** 을 띄우고 backend 에
`DATABASE_URL`·`REDIS_URL` 을 넣어 준다. 그런데 **앱은 그 두 변수를 읽지 않는다.**
`docker compose up` 은 성공하고, DB 는 뜨고, 아무것도 그 DB 를 쓰지 않는다.

이건 "설정이 있으니 됐다"로 읽히기 쉬운 상태다 — 이 저장소가 반복해서 잡아 온 실패
양식(게이트는 100% 인데 산출물이 제품에 안 닿는다 · 폴백이 고장을 가린다)과 **같은
모양**이다. 인프라 층에서 그 양식이 아직 안 잡혔다.

## 2. 왜 지금 결정해야 하나 — Exit 실사의 순서

목표는 18~24개월 내 M&A(네이버·카카오·직방)다. 인수 실사에서 **분석 정확도보다 먼저**
확인하는 것이 아래다. 지금은 넷 다 "없다"로 답해야 한다.

| 실사 항목 | 지금 답 | 없을 때 생기는 일 |
|---|---|---|
| 고객 데이터가 어디 있나 | 파일(Gold JSON/parquet) | 멀티테넌시·감사추적·삭제요구(개인정보) 대응 불가 |
| 누가 무엇을 봤나 | 기록 없음 | B2B 계약의 기본 조항을 못 맞춘다 |
| 배포가 재현되나 | 수동 | 인수 후 이관 비용이 그대로 할인 요인 |
| 매출이 어떻게 걷히나 | 스텁 | **DaaS 월 500만원 모델이 코드에 없다** |

특히 마지막이 크다. 사업계획의 수익 모델(DaaS 구독)이 제품에 **한 줄도 구현돼 있지
않다.** B2B 파일럿 5~10건을 6개월차에 받기로 되어 있는데, 파일럿을 받으면 즉시
계정·권한·과금이 필요해진다.

## 3. 선택지

### A. 파일 서빙을 유지하고, 계정 층만 올린다 (권장)

DB 를 **분석 데이터용이 아니라 사용자 데이터용**으로만 도입한다. Gold 파일 직독은
그대로 둔다 — 지금 잘 돌고 있고, 분석 데이터는 읽기 전용·배치 갱신이라 파일이 맞다.

- 새로 짓는 것: `users`·`orgs`·`memberships`·`api_keys`·`audit_log` + Alembic + JWT
- 안 건드리는 것: Gold 파이프라인 전부, 서빙 경로 전부
- 비용: 1~2주
- 푸는 것: 파일럿 온보딩 · 실사 항목 1·2 · 과금의 전제

### B. 전면 DB 이관 (PostGIS 로 Gold 를 옮긴다)

`requirements.txt` 가 원래 의도한 모습이다.

- 비용: 4~6주 + 파이프라인 전면 재작성
- 얻는 것: 공간질의 유연성
- ⚠ 지금 **필요하지 않다.** 서빙 질의가 거점·건물 단위 조회라 파일로 충분하고,
  p95 <200ms 목표도 현재 만족한다. 지금 하면 분석 트랙이 4~6주 멈춘다.

### C. 아무것도 안 하고 PPPP 를 마저 닫는다

- 남은 게이트는 Platform off-prior 하나뿐인데, 그건 **천장이 확인된 문항**이다
  (08-24 ablation: 어떤 조기종료 기준으로도 37%대). 감성 채널이 선행이고 그것도
  개선폭이 작을 것으로 이미 예고돼 있다.
- 즉 C 는 "가장 안 움직이는 것에 시간을 더 쓰는" 선택이다.

## 4. 권장 — A, 그리고 순서

1. **CI 먼저 (반나절).** `infra/github/` 이 비어 있어 지금은 테스트가 사람 손에만
   달려 있다. 백엔드 pytest + 프론트 `tsc -b` 를 PR 에 거는 것부터.
   **측정 완료(2026-08-25)**: 백엔드 스위트 **204 passed · 6 skipped · 약 4분 20초**
   (posting 계열 52건 1분 57초 + 나머지 152건 2분 22초). 프론트 `tsc -b` 는 수 초.

   (앞서 한 번 5분 타임아웃에 걸려 "완주 못 함"으로 남았던 것은 다른 작업과 CPU 를
   나눠 쓰던 중이었기 때문이다. 스위트 자체는 문제가 없다.)

   ✅ **착수·완료(2026-08-25 오후) — `.github/workflows/ci.yml`.** 잡 셋을 병렬로
   돌린다: 백엔드 pytest(약 1분 30초) · 데이터 파이프라인 pytest(38건 4초) ·

   `SPACEOS_LIVE_LLM=1` opt-in 이라 CI 에서 skip 된다. 포크 PR 에서도 그대로 돈다.

   ⚠ **워크플로는 `infra/github/` 이 아니라 `.github/workflows/` 에 있다.** Actions 는

   `.gitignore` 에 걸려 **추적되지 않고 있었다** — 형제 세 파일에는 전부 `!` 예외가
   있는데 이것만 빠져 있었다. 새로 클론한 환경(CI·Vercel)에는 파일이 없어

   실물이 아니었다"며 기각한 모델이다). 로컬에는 파일이 있어 **개발 기계에서는
   영원히 안 드러난다.** 예외를 추가해 추적으로 돌렸고,

## 8. KPI② (PMF) 축 착수 — 파일럿 접근·계측 (2026-08-27)

Platform off-prior 축이 완전히 닫히면서(`feature-platform.md` §0-N·§0-O) KPI①(기술
완성도)에 살 것이 없어졌다. 남은 유일한 미착수 축이 KPI②(B2B 파일럿 5~10건)이고,
`docs/README.md` 가 지적한 대로 **이를 재는 게이트가 0개**였다. 그 축을 시작했다.

### 한 것

| # | 작업 | 무엇을 푸는가 |
|---|---|---|
| 1 | **prod 비밀값 가드** (`core/config.py`) | `JWT_SECRET` 이 개발 기본값이면 prod 기동 실패(fail closed). `APP_ENV` 미지정 시 `VERCEL` 표식으로 자동 판정 |
| 2 | **API 키 발급·목록·폐기** (`/api/v1/auth/api-keys`) | B2B 연동의 표준 접근 수단. 조직 단위라 담당자가 바뀌어도 안 끊긴다 |
| 3 | **선택적 인증 + 사용량 계측** (`api/deps.track_access`) | 파일럿이 무엇을 얼마나 썼나 = KPI② 의 원천 데이터 |
| 4 | **관측 창구** (`GET /api/v1/admin/usage`) + `pppp_status` KPI② 블록 | 재는 자리를 만들고, 진행률이 KPI 절반만 말한다는 사실을 출력에 드러냈다 |

### 설계에서 갈린 판단 셋

**① 분석 API 를 인증 뒤로 숨기지 않았다.** 전부 잠그면 공개 데모가 죽는데, 그 데모가
파일럿 영업의 입구다(지금 프론트는 로그인을 하지 않는다). 대신 **자격증명이 오면
신원을 밝히고 기록**한다 — 익명은 그대로 통과. 잠그는 것은 파일럿 계약 시점 판단으로
남긴다.

**② 익명 요청은 DB 를 건드리지 않는다.** 분석 API 는 Gold 파일 직독이라 DB 없이 도는
것이 현재 동작인데, 계측을 붙이면서 그걸 깨면 DB 없는 배포에서 분석 API 가 통째로
죽는다. `get_optional_principal` 이 자격증명 없을 때 즉시 반환하고, 세션은 지연 연결
(`core/db.py`)이라 커넥션이 안 열린다. **연결 불가능한 DB 를 물려 놓고 익명 요청이
200 인지 보는 테스트**가 이 성질을 고정한다(`test_usage_tracking.py`) — 누가
`track_access` 에 질의를 하나 넣으면 거기서 터진다.

**③ 잘못된 자격증명은 익명으로 강등하지 않고 401.** 조용히 강등하면 키가 폐기된
파일럿이 계속 200 을 받으면서 사용량 집계에서만 사라진다 — 고장이 지표로 안 보이는
모양이라, 이 저장소가 반복해 잡아 온 실패 양식과 같다.

부수 결정: API 키 해시는 bcrypt 가 아니라 **SHA-256** 이다. 비밀번호와 위협이 달라서다
— 키는 256비트 난수라 사전공격 대상이 아니고, 반대로 이 해시는 **요청마다** 돌아가므로
bcrypt 를 쓰면 p95 <200ms 목표를 API 키 경로에서 혼자 깎는다. 근거는
`core/security.generate_api_key` 주석에 남겼다.

### 계정층 배선이 프로덕션을 18시간 죽였다 (2026-08-27 발견·복구)

같은 커밋(`1979bb4`, 08-26 23:04)이 **프로덕션 API 를 통째로 내렸다.** 08-27 오후에
`https://spaceos-sandy.vercel.app` 을 눌러 보고 처음 알았다 — 프론트 정적 파일은 200 이고
`/api/*` 와 `/health` 만 전부 500(`FUNCTION_INVOCATION_FAILED`)이었다. **화면은 멀쩡해
보인다.** 지도가 비어 있는 것이 데이터 문제인지 API 문제인지 화면만 봐서는 구별되지 않는다.

원인이 셋 겹쳐 있었고, 셋 다 "로컬과 CI 에서는 안 보이는" 종류였다.

| # | 원인 | 왜 안 잡혔나 |
|---|---|---|
| 1 | 루트 `requirements.txt` 에 `sqlalchemy`·`bcrypt`·`pyjwt`·`email-validator` 없음 | 백엔드 CI 는 `apps/backend/requirements.txt`(전부 포함)로 돈다. **배포 최소 셋으로 import 해 보는 자리가 없었다** |
| 2 | `core/db.py` 가 모듈 최상위에서 `create_engine()` 호출 | 파일 주석은 "지연 연결이라 괜찮다"고 적혀 있었고 **절반만 맞았다** — 커넥션은 안 열지만 DBAPI 드라이버(`psycopg2`)를 그 자리에서 import 한다. 로컬·CI 에는 psycopg2 가 깔려 있어 구멍이 안 보였다 |
| 3 | Vercel 에 `JWT_SECRET` 미등록 | `_guard_prod_secrets` 가 설계대로 fail-closed. 가드는 제 일을 했는데 **아무도 값을 넣지 않았다** |

②는 `get_optional_principal` 이 주장하던 "익명 요청은 DB 를 건드리지 않는다"와도 어긋나
있었다. 엔진 생성을 늦추기만 하면 실패 지점이 import 에서 **요청마다로** 옮겨갈 뿐이라
(`track_access` 가 `Depends(get_db)` 로 매 요청 세션을 만든다), `Session.get_bind()` 를
오버라이드해 **질의하는 순간까지** 엔진을 미뤘다. 이제 익명 요청은 드라이버 없이도 돈다 —
문서가 주장하던 성질이 처음으로 실제로 성립한다.

재발 방지는 `.github/workflows/ci.yml` 의 **`서버리스 임포트` 잡**이다. 루트
`requirements.txt` **만** 깔고 Python 3.14(=Vercel 빌드 버전)로 `api/index.py` 를 import 한
뒤 익명 요청 200 을 확인하고, 마지막에 **psycopg2 가 없음**까지 확인한다 — 누가 배포 셋에
드라이버를 넣으면 ②의 검사가 조용히 무의미해지기 때문이다.

⚠ 남는 교훈: **프로덕션이 살아 있는지 아무도 안 보고 있었다.** 18시간이 걸린 이유는
고치기 어려워서가 아니라(원인 셋 다 반나절 안에 해소됐다) 아무도 몰라서다. 헬스체크
모니터링은 아직 없다.

⚠ **다만 Postgres 로는 아직 못 재 봤다.** 이 기계에 Docker 도 Postgres 도 없다
(`docker` · `psql` 둘 다 미설치, 2026-08-27 확인). 위 검증은 전부 SQLite 기준이라
**마이그레이션↔모델 드리프트와 실행 가능성**을 재는 것이지 Postgres 고유 동작을
재는 것이 아니다. 모델이 애초에 SQLite 를 전제로 설계돼 있어(`models/auth.py` 머리말)
차이가 클 자리는 없지만, 그 구분을 흐리지 않으려고 적어 둔다.
