# AGENTS.md — docs/apply (공모전 신청서)

루트 [AGENTS.md](../../AGENTS.md) 를 먼저 읽는다. 이 문서는 이 디렉터리에만 더 얹는 규칙이다.
자매 디렉터리 [docs/papers](../papers/AGENTS.md) 와 같은 구조다 — 거기는 논문, 여기는 신청서다.

여기는 **코드가 아니라 글**이다. 저장소의 다른 통과 조건(테스트·빌드)이 통하지 않으므로
통과 조건을 스크립트 하나로 다시 정의한다:

```bash
python scripts/check_application.py --doc docs/apply/<대회>/draft.md
```

이 명령이 있기 때문에 이 디렉터리의 작업을 Codex 로 내보낼 수 있다
(`.claude/skills/codex-handoff` 의 4항목 중 3번 '통과 조건'). 없으면 못 내보낸다.

## 이 디렉터리에서 절대 하지 않는 것

1. **[claims.json](claims.json) 에 없는 수치를 본문에 쓰지 않는다.**
   근사치·"약 X%"·반올림한 기억도 안 된다. 대장에 있는 값을 그대로 옮긴다.
   새 수치가 필요하면 **먼저 대장에 출처와 함께 등재**한 뒤 본문에 쓴다.
2. **`condition` 을 떼고 수치만 옮기지 않는다.** `66거점` 을 쓰면서 `건축물대장` 을
   빼면 문장의 뜻이 바뀐다 — 산출값이 실측 정확도 주장이 된다.
   **이 디렉터리에서 가능한 최악의 산출물이 그것이다.**
3. **미평가를 성과로 고쳐 쓰지 않는다.** "현실 공실 정확도는 미평가"를 "높은 정확도"로
   바꾸는 것은 물론이고, 그냥 빼는 것도 고쳐 쓰는 것이다.
4. **`docs/papers/` · `docs/feature-*.md` · `reports/*.json` 을 수정하지 않는다.**
   여기서는 읽기만 한다. 원본 수치가 틀렸다고 판단되면 고치지 말고
   원고에 `<!-- 확인필요: ... -->` 를 남긴다.
5. **모집단이 다른 수치를 한 문서에 섞지 않는다.** 54거점 실험값과 66거점 서빙값은
   비교 가능하지 않다. `claims.json` 의 forbid 가 대표적인 것들을 막고 있다.
6. **주최처가 요구하지 않은 것을 지어내지 않는다.** 서식 항목명·분량·배점을 추측으로
   채우지 않는다. 확인 못 한 자리는 `<!-- 확인필요(서식): ... -->` 로 비워 둔다.

## 통과 조건

원고 변경은 아래를 만족해야 머지된다.

- [ ] `python scripts/check_application.py --doc <원고>` 가 exit 0
- [ ] 제출 직전에는 `--require-complete` 까지 붙여 exit 0 (FILL 잔여 0)
- [ ] `<!-- FILL -->` 를 지웠다면 그 자리가 실제로 채워졌다 (검사기 '빈절' 항목이 본다)
- [ ] 한계·미평가가 본문에 남아 있다 (요약하면서 증발시키지 않았다)

## 검사기의 사각 — 사람이 봐야 하는 자리

수치 대조는 **퍼센트 · 천단위 콤마 · 4자리 이상 정수**만 스캔한다. 배점(`20점`)과 절 번호까지
잡으면 오탐이 실제 위반을 덮기 때문이다. 그래서 **1~3자리 수치는 검사기가 못 잡는다** —
`832KB` · `211개` · `66거점` 같은 값은 통과해도 대장 대조가 된 것이 아니다.
규칙은 검사기가 아니라 [claims.json](claims.json) 이다: 자릿수와 무관하게, 대장에 없는
수치는 쓰지 않는다.

## 한 번에 하나의 절만 채운다

신청서 전체를 한 번에 생성하지 않는다. **절 하나 = 커밋 하나**가 이 디렉터리의 단위다.
이유: 근거 대조가 절 단위로만 가능하고, 통째로 생성한 글은 어디서 수치가 새는지 알 수 없다.

작업 요청은 이 형태로 받는다 — [codex-handoff](../../.claude/skills/codex-handoff/SKILL.md) 4항목이다:

```
1. 대상 파일   docs/apply/01-spatial-info/draft.md 의 §3 하나만
2. 입력 소스   docs/apply/claims.json 의 HUB66 · POLY. 수치 옆에 (출처: …) 를 괄호로 표기
3. 통과 조건   python scripts/check_application.py --doc docs/apply/01-spatial-info/draft.md
4. 금지        claims.json 밖의 수치 · §3 밖의 절 수정 · docs/papers 와 reports 수정
```

## FILL 마커 — 판단은 마커 안에 이미 들어 있다

마커에 **무엇을 · 어느 근거로 · 몇 자로 · 무엇을 피해서** 쓸지가 적혀 있다. 그 판단은
Claude Code 가 미리 해 둔 것이고, 이 디렉터리의 작업은 그 자리를 채우는 실행이다.
마커의 지시와 본문이 어긋나면 **마커가 맞다** — 마커를 고치려면 판단이 필요하므로
그때는 작업을 멈추고 보고한다.

```markdown
<!-- FILL(claims: HUB66, POLY)
     분량: 400~600자
     핵심 문장: …
     금지: … -->
```

## 언어와 형식

- **한국어**, 기술 용어는 영문 병기 (저장소 규칙과 동일)
- 최종 산출물이 `.docx` 로 나갈 경우 **한글 폰트 임베딩이 필요하다**
  → `memory/context/docx-korean-fonts.md` (폰트명만 지정하면 프리뷰에서 박스로 깨진다)
- 표 테두리는 top+bottom 만 — 4면을 다 주면 OOXML 스키마 위반이다

## 이 검사기가 못 하는 것

`check_application.py` 는 **거짓이 아님**만 본다. 설득력·구성·부문 선택·리프레이밍 각도는
판정하지 못한다. 그건 판단이고 판단은 위임 대상이 아니다. 검사기가 통과했다는 것은
"낼 수 있다"가 아니라 **"틀린 말은 없다"**는 뜻이다.
