# 출품 캘린더 → 서류별 작성 내용 (2026-09-21 기준)

출품 캘린더(아티팩트)의 각 자리에 **무슨 서류를 · 어떤 절 구성으로 · 어떤 근거 ID 로 · 무엇을
피해서** 쓸지를 한 장에 모은다. 작성 규칙 자체는 [AGENTS.md](AGENTS.md), 쓸 수 있는 수치의
전부는 [claims.json](claims.json) 이다. **이 문서는 무엇을 쓸지를 정하고, 수치는 대장에서 가져온다.**

> 원칙 하나만 다시 적는다 — `claims.json` 에 없는 수치는 어느 서류에도 쓰지 않는다.
> 조건(`condition`)을 떼고 값만 옮기는 것이 이 디렉터리에서 가능한 최악의 산출물이다.

### C. 핀테크 아이디어 공모전 (10-08 16:00)

**상금이 한 자릿수 위인 대신, 재사용률이 가장 낮다.** 지금 문서를 그대로 내면 "부동산
서비스"로 분류돼 떨어진다. **리프레이밍이 원고 작성보다 먼저다.**

**금융 언어로 바꾸는 세 각도** — 하나를 고른다.

1. **소상공인 여신 심사 보조 지표.** 심사에서 지금 보는 것은 사업자의 재무다. 그 사업자가
   들어가려는 **자리**의 리스크는 보지 않는다. 건물·층 단위 공실 이력과 업종 적합도가
   그 빈칸을 메운다.
2. **상가 담보 가치 평가 보조.** 담보 상가의 동일 건물·인접 층 공실 이력을 평가 시점에 붙인다.
3. **여신 포트폴리오 조기경보.** 상권 단위 공실 추세 변화를 기존 여신의 모니터링 신호로.

권고는 **1번**이다 — 화면 넷이 그대로 심사 화면이 되고, 층 스택이 "이 자리"를 보여 준다.

| 절 | 쓸 내용 | 주의 |
|---|---|---|
| 아이디어 개요 | 자리(place)의 리스크를 여신 판단에 넣는다 | C1 을 금융 언어로 재작성 |
| 문제·시장 | 사업자는 보고 자리는 안 본다 | 외부 통계를 인용하려면 출처 확인 후. 못 하면 `<!-- 확인필요(출처) -->` |
| 적용 시나리오 | 누가(은행·보증기관·상호금융) 어느 의사결정에서 어떤 화면으로 쓰는가 | 구체적으로 |

| 한계 | C6 | 빼지 않는다 |

**추가 금지.** 신용평가·부도예측 정확도를 주장하지 않는다 — 금융 라벨로 검증한 적이 없다.
개인 신용정보를 다룬다고 쓰지 않는다(사실이 아니고, 규제 카드를 스스로 버리는 것이다).

### F. 데이터+AI 혁신 챌린지 (10-22) — 참가 보류 권고

공개데이터 공모전이 아니다. **데이터안심구역 시설 안에서** 지정기관 미개방 데이터를 분석하는
형식이라 PlaceOS 산출물을 내는 자리가 아니고, 예선·본선이 시설 방문을 전제한다.
**할 일은 하나** — 지정기관 8곳에 LX 가 들어 있으니 **어떤 공간정보 데이터셋이 열리는지만
kdata.or.kr 원문으로 확인**한다. 총상금이 집계 매체와 보도자료에서 어긋나는 것도 같이 본다.

### G. DATA·AI 분석 경진대회 (KISTI · 11-25)

**부문이 둘이라 이중 출품이 가능하다** — 규정 확인 후.

- **문제발굴 부문**: 상권 공실을 풀 만한 문제로 제안한다. 서류는 문제 정의 + 왜 공공적으로
  중요한가 + 어떤 데이터로 풀 수 있는가. C2 + C7 이면 거의 끝난다.
- **문제해결 부문**: 자체 모델로 답한다. 분석 보고서 형식이라 C5 를 방법·결과·한계로 펼친다.

## 6. 통과 조건

원고를 낼 때마다 다음이 exit 0 이어야 한다.

```bash
python scripts/check_application.py --doc docs/apply/<대회>/draft.md --require-complete
```

검사기는 **거짓이 아님**만 본다. 통과했다는 것은 "낼 수 있다"가 아니라 **"틀린 말은 없다"**다.
설득력·부문 선택·리프레이밍 각도는 사람이 판정한다. 그리고 검사기는 1~3자리 수치를 잡지
못하므로, `66거점` 같은 값은 통과해도 대장 대조가 된 것이 아니다.
