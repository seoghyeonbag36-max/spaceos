# 앵커 모집단 불일치 규명 결과 (2026-08-01)

`docs/prompt-anchor-population-mismatch.md` 의 작업 결과다. 재현: `python -m data.analyze_anchor_population`
(캐시 재생성은 `--rebuild`, 수 분). **API 콜 0 · gold 산출물 무수정.**

## 0. 한 줄 결론

**후보 A(앵커 모집단 불일치)와 후보 B(분자 커버리지 결손)가 둘 다 참이고, 겹쳐 있다.**
어느 한쪽이 원인이 아니다. 모집단·단위를 R-ONE 에 맞추면 13거점 합 **51.8% → 30.5%** 로
21.3%p 가 닫히고, 남는 ~20%p 는 분자(상가정보)가 층을 못 채우는 데서 온다.
그리고 그 과정에서 **세 번째 문제**가 드러났다 — 우리 지표는 분자와 분모의 **단위가
서로 다르다**(점포 수 vs 층 수). 지금까지 `min(active, capacity)` 클램프가 그걸 덮고 있었다.

세 축이 전부 다르다. 특히 표본 규모가 **상권당 16동 vs 우리 거점당 수백 동**이라,
같은 상권명을 붙였을 뿐 같은 대상을 재고 있지 않다.

## 2. 모집단을 R-ONE 에 맞춰 재집계 (표 1)

호실 기준, 지번(pnu) dedupe, 건물별 `min(active, capacity)` 클램프.

| 변형 | 정의 | 13거점 합 |
|------|------|-----------|
| A 현행 | primary(expos_units+floor_ouln) 전체 | **51.8%** (11,218동) |
| B 규모정렬 | 일반건축물 & (3층↑ or 330㎡ 초과) | 44.3% (7,958동) |
| C 용도정렬 | B + 표제부 주용도가 상가류(근생·판매·위락·문화) | 39.5% (7,117동) |
| D 면적가중 | C 를 건물 상업면적으로 가중 (R-ONE 면적 기준 근사) | **30.5%** (7,107동) |
| E 소규모 | 일반건축물 & 2층↓ & ≤330㎡ & 상가류 (vac_small 대조) | 29.7% (2,481동) |
| 집합(참고) | 집합건축물 — R-ONE 중대형 앵커 대상 아님 | 72.7% (755동) |

- **집합건물을 앵커 비교에서 빼야 한다.** 755동뿐인데 공실률 72.7% 로 전체를 끌어올린다.
  이 세그먼트는 이미 "신뢰 구간 밖"으로 표시돼 있었는데(`calibrate_vacancy` note),
  그럼에도 primary 에 섞여 앵커와 비교되고 있었다.
- **주용도 필터(B→C)가 걷어내는 건 업무·숙박이다.** B 모집단 7,958동의 구성은
  제2종근생 57.3% · 제1종근생 30.4% · **업무시설 6.4%(509동)** · **숙박 4.2%(332동)** ·
  문화및집회 0.6% · 판매 0.6%. 주택류는 이미 `non_commercial` 로 빠져 있어 없다
  (반경 내 전체로 보면 단독주택 1,303동 · 공동주택 276동이 중대형 규모조건을 통과하지만
  분모에 들어오지 않는다). R-ONE 중대형 표본은 업무시설·숙박시설도 안 뽑는다.
- 정렬 효과가 가장 큰 거점: myeongdong 59.8 → 16.6% · ikseon 58.3 → 25.3% ·
  seoulsup 39.7 → 22.6%. 거의 안 변하는 거점: euljiro 71.0 → 56.9% · hongdae 55.1 → 52.6%.
- **그래도 앵커(3.4~17.6%)보다 여전히 높다.** D 기준 잔여 격차는 songridan +1.6%p ·
  garosugil +10.7%p 부터 euljiro +50.1%p 까지. → 후보 A 만으로는 설명되지 않는다.

## 3. 층 단위로 맞춰 본 분자 (표 2) — 후보 B

상가정보 원본에 **`flrNo`(층)** 가 있다. 층별개요의 지상 상업층 번호와 직접 맞췄다
(대상 = C 모집단).

| 지표 | 값 |
|------|-----|
| 층 기준 공실률 **하한**(층이 확인된 점포만 인정) | 52.7% |
| 층 기준 공실률 **상한**(층 미상 점포를 빈 층에 낮은 층부터 배정) | 30.0% |
| 층별 점유율 하한 | 1층 66.6% · 2층 44.3% · 3층 37.4% · 4층 32.4% · 5층+ 32.5% |
| 층별 점유율 상한 | 1층 **92.1%** · 2층 71.7% · 3층 57.2% · 4층 49.9% · 5층+ 47.7% |
| 분모 밖 층에 있는 점포 | **22.6%** (2,953/13,057) |

- **`flrNo` 공란이 약 30%.** 하한/상한 폭이 22.7%p 나 되는 이유이고, 이 불확실성이
  현행 지표에는 아예 표현돼 있지 않다.
- **점포의 22.6% 가 우리 분모에 없는 층에 있다.** 층별개요 상업층 필터가 실제 영업
  중인 층을 놓치고 있다는 직접 증거다. `active > capacity` 인 건물이 거점당 34~45%
  나오던 현상의 실체가 이것이다 — 클램프는 이 초과분을 조용히 버려 왔다.
- 1층조차 하한 66.6% 점유(= 공실 33.4%)다. 명동 1층 점유 52.1% 는 현실과 맞지 않는다.
  상한 시나리오(92.1% 점유)가 실제에 훨씬 가깝고, 그렇다면 **분자 결손이 크다**.

## 4. 1층 한정 대조 — 41.6% 는 여전히 폐기가 맞다

garosugil 1층 공실률: **하한 32.8% · 상한 9.1%**.
R-ONE 신사역 중대형 **17.6%** 는 이 밴드 **안**에 들어온다. 가두 1층 실태조사(2024)
**41.6%** 는 밴드 **밖(위)** 이다. 2026-07-28 에 41.6% 를 앵커에서 뺀 판단이 옳았음이
독립적으로 재확인됐다. (거점별 1층 밴드: songridan 18.0~2.8% ~ myeongdong 47.9~8.5%)

## 5. 판정과 다음 수순

**판정: A ∧ B.** 순서는 정해졌다 — 앵커를 바꾸는 게 아니라 **지표를 앵커의 정의에
맞추고, 그 다음 분자를 층 단위로 채운다.**

1. **`calibrate_vacancy` 의 primary 모집단을 C/D 로 교체.** 집합건물을 빼고(별도 계열로
   보고), 표제부 주용도가 상가류인 중대형만 앵커와 비교한다. 면적 가중(D)을 대표값으로,
   호실 기준(C)을 병기. **α 보정은 여전히 쓰지 말 것** — 정의를 맞추는 것이 먼저다.
2. **층 단위 매칭 도입(API 콜 0).** 분자를 "건물 내 점포 수" 대신 "점포가 확인된 상업층
   수"로 바꾸면 분자·분모 단위가 같아지고 클램프가 필요 없어진다. `flrNo` 공란 30% 는
   상·하한 밴드로 노출한다(단일 값으로 감추지 말 것).
3. **분모 밖 층 22.6% 재검토.** 층별개요 `NON_CAPACITY_PURPS` 네거티브 필터가 실제
   영업 층을 떨어뜨리고 있다. 점포가 있는 층은 정의상 상업층이므로, 분모를
   "층별개요 상업층 ∪ 점포 확인 층"으로 넓히는 것이 일관적이다.
4. 그 뒤에도 남는 격차만이 진짜 미측정분이다. 그때 로드뷰 재표본으로 검증하되
   **층화 기준은 분모 규모**(1~2호 / 3~10 / 11~20 / 21~50 / 51+)로 잡는다.

## 5-1. 2026-08-01 후속 — 지표 정의를 앵커에 맞춰 전환 완료

§5의 1~3번을 구현했다. 파이프라인·산출물이 모두 바뀌었다(API 콜 0).

- **신규 사이드카** `data/pipelines/build_building_attrs.py` → `silver/{거점}/building_attrs.json`
  (지번별 등록구분·지상층수·연면적·주용도·상업층 번호·상가정보 점포 층). bronze 대장이
  85MB인데 이 환경은 페이지파일 여유가 ~0.1GB라 **행 단위 스트리밍**으로 읽는다.
- **분모 확장 + 층 단위 분자** (`recalc_floor_ouln`): 분모 = 층별개요 상업층 ∪ 점포가
  확인된 지상층(13거점에서 2,000여 동이 넓어짐), 분자 = 점포가 확인된 층 수(상한은
  층 미상 점포·PIP·인허가를 빈 층에 낮은 층부터 배정). 행에 `capacity_floors` ·
  `active_floors_lo/hi` · `vacancy_lo/hi` 를 남긴다.
- **`build_page_master`** 도 층 기준으로 전환 — 같은 지번 여러 동의 capacity 를
  **합산하지 않고 합집합**으로 바꿨다(지번당 산출물을 동 수만큼 부풀리던 버그).
  feature 에 `vacancy_rate_lo/hi`(밴드)와 `stores`(점포 수)를 추가.
- **`calibrate_vacancy.rone_aligned`** 신설 — R-ONE 과 같은 모집단·단위의 대표값.
  `mid`(중대형 앵커 대조) · `small`(소규모 앵커) · `mall`(집합, 대조 금지)로 분리.
  기존 `primary`/`segments`/`methods` 는 하위호환으로 유지하되 note 로 강등 표시.
  백엔드·ML 서빙(`ground_anchor`)도 `rone_aligned.mid` 를 우선하도록 바꿨다.

## 6. 주의 (재현 시)

- 집계는 **건물별 `min(active, capacity)` 클램프 후 합산**. 단순 합산은 공실률을 0% 로 누른다.
- 분모는 **지번(pnu) 단위 dedupe**. capacity 는 지번당 1회 산출물이라 동(bdMgtSn) 단위로
  세면 중복된다.
- `building_vacancy.json` 의 모집단은 상가정보 bdMgtSn 그룹핑 산출물이라 **사실상 점포가
  1건 이상 있는 건물**이다(15,534행 중 active=0 은 91행, 0.6%). 반면 프론트의 red dot
  (`status=empty`)은 `page_building_master.geojson` 쪽 모집단이다 — garosugil 기준
  836 feature 중 empty 123동. 두 모집단이 다르니 "집계 공실률"과 "공실 건물 수"를
  같은 문장에서 섞어 인용하지 말 것.
- bronze `bldg_ledger_raw.json` 은 최대 85MB, 이 환경 가용 RAM 은 ~2GB 라
  `json.load` 가 MemoryError 를 낸다. 진단기는 최상위 블록 스트리밍으로 읽는다.
- `PYTHONIOENCODING=utf-8` 필수(cp949 로 죽는다).
