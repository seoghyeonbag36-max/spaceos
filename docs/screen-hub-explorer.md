## 1. 화면 목적

서빙 거점을 지도 위에서 하나씩 열어 **출점 후보로 남길지 버릴지**를 그 자리에서 판정한다.

이 화면이 막아야 하는 오해가 하나 있다 — **경계선은 상권 경계가 아니라 "우리가 잰 범위"다.**
선 안쪽이 상권이고 바깥이 아니라는 뜻이 아니라, 선 안쪽이 공실률 분모에 들어간 곳이라는 뜻이다.
이 구분이 무너지면 사용자는 커버리지 5.2%짜리 거점(banpo)의 경계를 상권 경계로 읽는다.

## 2. 레이아웃 맵

### 2-1. 데스크톱 (≥1024px)

```
0   64                                                              100vw
├────┼──────────────────────────────────────────────────────────────┤
│    │  A  overlay-top   top:12 left:12 right:12   z:5              │  12
│레일│ ┌──────────┐ ┌───────────┐ ┌──────────────────────────┐      │
│ 64 │ │거점 선택 ▾│ │ 건물 검색 │ │유동|공실|임대|밀도       │ 40h  │  52
│fix │ └──────────┘ └───────────┘ └──────────────────────────┘      │
│    │                                                              │
│ S  │ ┌─ B 거점 목록 ─┐              ┌─ C 거점 요약 ────────┐      │  64
│ 서울│ │ top:64        │              │ top:64  right:12     │      │
│ 거점│ │ left:12       │   [지도]     │ width:340            │      │
│Plat│ │ width:320     │   z:0        │ bottom:68 (범례 위)  │      │
│Page│ │ bottom:12     │              │ overflow-y:auto      │      │
│Post│ │ overflow-y    │              └──────────────────────┘      │
│Prog│ │               │                                            │
│    │ │               │      ┌── E 시간바 ──┐                      │
│    │ └───────────────┘      │ bottom:12 중앙│   ┌─ D 범례 ─┐      │
│    │                        └───────────────┘   │right:12  │      │
│    │                        (유동 레이어일 때만)  │bottom:12 │  44h │
└────┴────────────────────────────────────────────┴──────────┴──────┘
```

| 슬롯 | 위치 | 크기 | z | 비고 |
|------|------|------|---|------|
| 레일 | `fixed; left:0; width:var(--rail-w)` | 64px | 별도 | 지도 셸과 겹치지 않는다 |
| 지도 | `fixed; inset:0 0 0 var(--rail-w)` + 캔버스 `width/height:100%` | 잔여 전부 | 0 | `inset:0`만 주면 높이 0으로 접힌다 |
| A 상단바 | `top:12 left:12 right:12` | h40 | 5 | `pointer-events:none`, 자식만 `auto` |
| B 거점 목록 | `top:64 left:12 bottom:12` | w320 | 5 | 기존 `.side-panel` 재사용 |
| C 거점 요약 | `top:64 right:12 bottom:68` | w340 | 5 | **신설.** bottom 68 = 범례 44 + 여백 24 |
| D 범례 | `right:12 bottom:12` | h44 | 5 | 경계 근거 배지가 여기 붙는다(§6) |
| E 시간바 | `bottom:12` 중앙 | — | 5 | 유동 레이어 전용 |
| F 모달 | `inset:0` | — | 20 | 건물 상세(이 설계서 범위 밖) |

- 지도 폭 = `100vw − 64px`. C 패널은 지도 **위에** 뜬다 — 지도를 좁히지 않는다.
- C 를 우측에 둔 이유: 좌측 B(목록)와 마주 보게 해서 **고른 것(좌) → 고른 결과(우)** 로 시선이 흐른다.
  둘을 같은 쪽에 쌓으면 세로 320+340 이라 1080 높이에서 잘린다.

### 2-2. 모바일 (<768px)

```
┌──┬────────────────────────────┐
│레│  A  거점선택 + 레이어(가로스크롤)│  검색은 숨긴다(탭하면 펼침)
│일│                            │
│52│         [지도]             │
│  │                            │
│  │        ┌─ D 범례 ─┐        │  bottom: calc(38vh + 12px)
│  │ ┌──────────────────────┐   │
│  │ │ ═══ 핸들 ═══         │   │  G 바텀시트 (B+C 통합)
│  │ │ [요약 카드]          │   │  peek 38vh / full 82vh 2단 스냅
│  │ │ ─────────────────    │   │  요약이 시트 헤더, 목록이 본문
│  │ │ [건물 목록 …]        │   │
└──┴─┴──────────────────────┴───┘
```

- B·C 를 **한 시트로 합친다.** 좁은 화면에서 패널 둘을 띄우면 지도가 사라진다(C1 위반).
- 시트 peek(38vh) 상태에서 요약 카드 상단 2줄(거점명 + 공실률·근거 배지)이 보여야 한다.
- 범례·시간바는 시트 높이를 따라 올라간다 — 기존 `calc(44vh + 12px)` 규칙을 38vh 로 맞춘다.

## 3. 상태표

| 상태 | 지도 | 경계 | C 요약 | 문구 |
|------|------|------|--------|------|
| 초기(탭 진입) | 마지막 카메라 유지. 재생성 없음 | 직전 선택 유지 | 직전 선택 유지 | — |
| 거점 미선택 | 서울 전역(zoom 11) | 없음 | 접힘 | "거점을 고르면 실측 범위와 요약이 여기 뜬다" |
| 로딩 | 지도 그대로 조작 가능 | 이전 경계 유지(깜빡임 방지) | 스켈레톤 3줄 | 경계 배지 자리에 "범위 계산 중" |
| 거점 선택됨 | fitBounds 400ms | 실선 + 배지 | 전체 | §5 표대로 |
| 셀 파편 다수 | 동일 | 조각 전부 실선, 1칸 섬은 얇게 | 동일 | 배지 "실측 범위 · 10조각(최대 30%)" |
| 대표값 미제공 (`vacancy_withheld`) | 동일 | 동일 | 공실률 자리에 **"대표값 미제공"** | `caveat-withheld` 전문 + 커버리지 5.2% 명시 |
| 예외 거점 (`caveat`) | 동일 | 동일 | 값은 싣되 비교 금지 표식 | `caveat-note` 전문 |
| API 실패 | 지도 유지 | 이전 유지 | 오류 카드 | "거점 요약을 못 불러왔다 — 다시 시도" + 재시도 버튼 |
| 지도 인증 실패 | 회색 대신 안내면 | — | — | `describeNaverMapError()` 문구 그대로(원인+조치 한 줄) |

"빈 화면"은 이 표에 없다. 값이 없는 자리에는 **왜 없는지**가 들어간다.

## 4. 상호작용

| 트리거 | 반응 | 목표 시간 |
|--------|------|-----------|
| A 거점 선택 변경 | ① 경계 계산 → ② `fitBounds(경계 bbox, padding)` → ③ C 패널 채움. 셋이 같은 프레임에서 시작 | 카메라 정지 ≤400ms |
| B 목록 항목 클릭 | 해당 건물로 `panTo` + C 패널은 거점 요약 유지(건물 상세는 B 하단) | ≤250ms |
| 경계 클릭 | 아무 일도 없다 — 경계는 `clickable:false`. 밑의 건물 폴리곤이 클릭을 받아야 한다 | — |
| 지도 드래그/줌 | 경계·요약 그대로. 재계산 없음 | — |
| `Esc` | C 패널 접기(거점 선택은 유지) | 즉시 |
| `Tab` | A → B목록 → C요약 → D범례 순. 지도 캔버스는 탭 순서에서 뺀다 | — |
| `↑/↓` (B 포커스 시) | 목록 이동, `Enter` 로 선택 | — |
| URL | `#hub=<slug>` 로 반영. 새로고침·공유 시 그 거점으로 복원 | — |

**fitBounds 패딩** — 오버레이 밑에 경계가 깔리면 안 된다.

```
desktop: { top: 76,  right: 364, bottom: 68, left: 344 }   // 패널 폭 + 여백
mobile : { top: 64,  right: 16,  bottom: <시트높이>+16, left: 16 }
```

**카메라는 거점 center 가 아니라 경계 bbox 에 맞춘다.** `center` 는 수집 원점이라 실측 범위와
어긋날 수 있다(banpo: 셀 18개가 원점에서 7조각으로 흩어져 있다).

전부 `GET /api/v1/commercial-districts` 한 번으로 온다(66행). 거점 전환 시 재요청 없음.

## 6. 근거 표기 규칙

화면에 뜨는 선과 숫자는 **무엇으로 만든 것인지** 옆에서 말한다.

| 배지 | 붙는 곳 | 문구 | 근거 |
|------|---------|------|------|
| 실측/합성 | C 공실률 옆 | `실측(Gold)` / `합성` | `vacancy_source`. 현재 66/66 이 gold |
| 경계 근거 | D 범례 좌측 | `실측 범위 · N조각` | 부록 A. 조각이 1개면 "· 1조각" 생략 |
| 최대조각 경고 | 같은 배지 뒤 | `(최대 30%)` | 최대 조각이 전체의 70% 미만일 때만 |
| R-ONE | C 앵커 줄 | `R-ONE` | 모집단이 달라 격차 0이 정상은 아니다 |
| LSTM | C 예측 줄 | `LSTM` | 미배포면 줄 자체를 숨긴다 |
| 예외 | C 상단 | ▣ 단일시설 / ▤ 계획상가 밀집 / ▨ 대표값 미제공 | `CaveatNote` 재사용 |

**경계선 스타일** — 양식 §6 규칙을 그대로 따른다.

| 요소 | 스타일 |
|------|--------|
| 실측 범위 외곽(조각 ≥2칸) | 실선 2px `--brand` #0EA5B7, `fillOpacity: 0.06`, `clickable:false` |
| 1칸짜리 섬 | 실선 1px, `fillOpacity: 0` — 경계가 아니라 점으로 읽히게 |
| 컨벡스 헐(선택 옵션, 기본 끔) | 파선 1px `--muted` — 근사라 파선 |

공실 색계열(`colors.vacancy`)을 경계에 쓰지 않는다. 값과 경계가 같은 색이면 섞여 읽힌다.

## 7. 토큰

하드코딩 hex 금지. 이 화면이 쓰는 것 전부:

| 용도 | 토큰 |
|------|------|
| 경계선·활성 | `--brand` / `--brand-pressed` / `--brand-soft` |
| 본문·보조 | `--ink` / `--muted` / `--line` |
| 패널 | `--surface`, `--radius-lg`(14~16px), `--shadow-card` |
| 공실 색계열 | `colors.vacancy[0..4]` (건물 폴리곤·범례 전용) |
| 예외 | `.caveat-note` / `.caveat-mall` / `.caveat-withheld` / `.value-absent` |
| 레일 오프셋 | `--rail-w` (64 / 모바일 52) — **단일 출처** |
| 폰트 | `--font-sans` (Pretendard) |

네이버 그린(`--naver-green`)은 이 화면에 없다. 길찾기·예약 같은 네이버 연동이 붙을 때만.

## 8. 접근성

- C 패널의 지도 위 텍스트는 불투명 배경(`rgba(255,255,255,.94)` 이상) 위에 올린다. 지도 타일 위
  반투명 텍스트는 대비가 타일마다 달라져 AA 를 보장할 수 없다.
- 거점이 바뀌면 `aria-live="polite"` 로 한 줄 알린다:
  `"신사동 가로수길 선택됨. 공실률 15.8퍼센트, 실측 범위 1조각."`
  대표값 미제공 거점은 `"고속터미널·반포 선택됨. 대표 공실률 미제공."`
- 경계는 순수 시각 요소다 — 스크린리더에는 배지 텍스트로만 전달한다(폴리곤에 `aria` 없음).
- 지도 캔버스는 `tabindex="-1"`. 키보드 사용자가 탭으로 지도에 갇히지 않게 한다.
- 조각 수·비중을 **색으로만** 말하지 않는다. 숫자를 같이 적는다.

## 9. 통과 조건

```
- [ ] 「거점」 → 「Platform」 → 「거점」 으로 돌아와도 지도 중심·줌이 그대로다(지도 재생성 없음).
- [ ] 거점을 바꾸면 400ms 안에 카메라가 멈추고, 그 시점에 경계와 C 요약이 같이 떠 있다.
- [ ] 경계가 좌측 목록(320px)·우측 요약(340px) 패널 밑에 깔리지 않는다.
- [ ] D 범례의 경계 배지가 "실측 범위"라고 말한다(상권 경계라고 말하지 않는다).
- [ ] yeouido 를 열면 배지가 "10조각(최대 30%)"을 낸다 — 조각을 숨기지 않는다.
- [ ] banpo 를 열면 공실률 자리가 "0%"가 아니라 "대표값 미제공"이고, ▨ 전문이 보인다.
- [ ] garak·yeouido·banpo 에서 비교 금지 표식이 뜨고, 나머지 63거점에서는 뜨지 않는다.
- [ ] 거점 목록 개수가 API 응답 길이와 같다(화면 문구·코드에 66 이라는 상수가 없다).
- [ ] 1024px → 768px 로 줄이면 좌·우 패널이 시트 하나로 합쳐지고 지도 폭이 줄지 않는다.
```

## 부록 A. 경계 산출 알고리즘 (B안 — 실측 커버리지 외곽)

`GET /api/v1/heatmap/vacancy?district={id}` 의 `cells[]` 만으로 만든다. 추가 수집 없음.

**입력의 성질**(실측 확인 — 부록 B): 셀은 정수 인덱스 `i,j` 를 가진 균일 격자다.
`dlat=0.0009`, `dlng=0.00113`(100m)이 66거점 4,501셀 전부에서 동일하다.
`lat/lng` 는 **남서 모서리**, `c_lat/c_lng` 는 중심이다(`c_lat − lat === dlat/2` 확인).

```
1) 채택 집합 S = cells 전부.
   ⚠ v > 0 으로 거르지 말 것. 응답의 모든 셀이 capacity > 0 이라 배열에 있다는 것이 곧
     "재어진 곳"이다. v > 0 으로 거르면 4,501 중 1,598셀(35.5%)이 빠지는데, 그건 공실이
     0인 = 가장 꽉 찬 블록들이다. 경계에 구멍이 나고, 하필 제일 건강한 자리에 난다.

2) 경계 간선 수집 (marching edges)
   S 의 각 셀 (i,j) 에 대해 네 변을 낸다:
     남 (i,j)-(i+1,j) · 북 (i,j+1)-(i+1,j+1) · 서 (i,j)-(i,j+1) · 동 (i+1,j)-(i+1,j+1)
   이웃이 S 에 있는 변은 상쇄한다(내부 변). 남은 변만 외곽이다.
     (i,j) 의 북쪽 이웃 (i,j+1) ∈ S  → 북 변 제거
     이하 4방향 동일.

3) 간선을 링으로 잇기
   남은 변을 끝점으로 이어 붙여 닫힌 링을 만든다. 격자 위 변이라 각 끝점의 차수는
   2 또는 4다. 차수 4(대각으로만 맞닿은 지점)에서는 **시계방향 우선**으로 갈라
   두 링으로 나눈다 — 8-이웃으로 묶으면 대각 접점이 한 덩어리로 보여 조각 수가 준다.
   연결요소 판정은 4-이웃 기준으로 통일한다(§9 통과조건의 조각 수와 같아야 한다).

4) 격자 좌표 → 위경도
   점 (i,j) → { lat: lat0 + j*dlat, lng: lng0 + i*dlng }
   lat0/lng0 는 i=0,j=0 셀의 lat/lng. 응답에 그 셀이 없을 수 있으므로
   아무 셀 c 에서 역산한다: lat0 = c.lat − c.j*dlat, lng0 = c.lng − c.i*dlng.

5) 렌더
   링마다 naver.maps.Polygon 하나. 조각 크기(셀 수)로 스타일을 가른다(§6).
   구멍(내부 링)은 Polygon 의 두 번째 path 로 넣는다 — 채우기가 구멍을 덮으면
   "저기도 쟀다"로 읽힌다.

6) 배지 문구
   조각 수 n, 최대 조각 비중 p 를 같이 낸다.
   n === 1        → "실측 범위"
   n > 1, p ≥ 70% → "실측 범위 · n조각"
   n > 1, p < 70% → "실측 범위 · n조각(최대 p%)"
```

**비용**: 셀 최대 169개 × 변 4 = 676변. 거점 전환당 1회. 메모이즈 불필요.

**폴백 순서**: `cells` 가 비면 → `/heatmap/buildings` 폴리곤의 컨벡스 헐을 **파선**으로
(라벨 "건물 외곽 근사") → 그것도 없으면 경계를 그리지 않고 배지에 "실측 범위 없음".
현재 66거점 전부 셀이 있어 폴백은 방어 코드다.

**파편과 커버리지의 관계** — 경향은 있으나 원인은 하나가 아니다.

혼자 해석하게 두지 않는다.
