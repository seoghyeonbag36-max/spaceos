# SGIS 집계구 자료신청 — 제출용 준비 (2026-08-25)

> **이 문서는 코드가 아니라 사람이 할 일의 준비물이다.** `foot`(유닛 단위 유동인구)은
> 막힘 5번이고, 막는 것은 코드가 아니라 **신청·승인**이다
> ([finding-foot-traffic-resolution.md §3-1](finding-foot-traffic-resolution.md)).
> 승인까지 시간이 걸리므로 **먼저 넣고 다른 트랙을 병행한다**가 08-20 판단이었고,
> 그 판단이 아직 실행되지 않은 채 5일이 지났다. 아래를 그대로 채워 오늘 넣는다.

## 왜 이게 필요한가 (신청서에 쓸 한 문장)

54개 상권 거점의 **공실 유닛 단위** 입지 분석에 필요한 최소 공간 단위가 집계구다.
현재 보유한 유동인구는 상권 단위(거점당 1~9곳, 중앙 3곳)라, 한 거점의 공실 유닛
12개가 2~3등급으로만 갈린다 — 유닛 사이 서열을 만들어낼 수 없다.

## 받아야 할 것 둘 — 하나만 받으면 못 쓴다

| # | 자료 | 어디서 | 경로 | 상태 |
|---|---|---|---|---|
| 1 | **집계구 경계(폴리곤)** | SGIS 자료제공 | 회원가입 → 자료신청 → **승인** → 다운로드 | ⛔ 신청 필요 |
| 2 | **집계구 단위 생활인구** | 서울 열린데이터광장 | 파일(ZIP) 직접 다운로드 — 신청 불필요 | ✅ 지금 가능 |

- 1번 URL: https://sgis.mods.go.kr/view/pss/openDataIntrcn
- 2번은 OpenAPI 가 **없다.** 데이터셋 페이지의 "Sheet·OpenAPI 는 4일전 당일자료만"은
  집계구 파일에 적용되지 않는다. 실제 제공은 **일별 ZIP 143개**(38~40MB/일,
  월 아카이브 ~1,200MB, 2017.1~2026.7). 서비스명 후보 4종
  (`_TOT`·`_JIPGYE`·`_ADSTRD`·`_RESD`)은 전부 `ERROR-500` 이다 — 다시 시도하지 말 것.
- 대안 경로: 서울 빅데이터캠퍼스에도 집계구 경계가 있으나 **역시 신청 절차**다.
  SGIS 가 반려되면 그때 간다.

## 신청서 초안 (그대로 복사해 쓴다)

**신청 자료명**: 통계지리정보 집계구 경계 (서울특별시)

**신청 목적**:
> 서울시 상권 거점의 건물 단위 공실 분석 및 입지 추천 서비스 연구개발.
> 건축물대장 기반으로 산출한 공실 유닛(54개 거점 528호)에 유동인구 지표를
> 결합하려 하는데, 현재 공개된 상권 단위 유동인구는 한 거점 안에서 값이 상수라
> 유닛 간 비교가 불가능합니다. 집계구 경계를 받아 집계구 단위 생활인구(서울 열린
> 데이터광장 공개분)를 유닛 좌표에 공간조인하려 합니다.

**이용 범위**: 자체 연구개발 및 서비스 내 분석 지표 산출
**공간 범위**: 서울특별시 전역 (25개 자치구)
**시간 범위**: 최신 기준 연도 1개 (갱신 시 재신청)

⚠ 라이선스는 확인해 두었다 — **공공누리 1유형**(상업 이용·변경 가능)이라 상용
서비스 결합에 제약이 없다. 신청서에 이용 범위를 축소해 적을 이유가 없다.

## 승인이 나면 — 그때 할 코드 작업

승인 전에는 착수하지 않는다(경계 없이 만든 조인은 검증할 수 없다).

1. `data/collectors/` 에 집계구 경계 적재기 — GeoJSON/SHP → `silver/jipgyegu.geojson`
2. 집계구 생활인구 ZIP 파서 — `TMZON_PD_SE` 가 **00~23 시간별**이라 Page 24시간 축과
   같은 입도다. 행정동(현행)보다 세밀하다.
3. 유닛 좌표 → 집계구 PIP 조인 → `posting_inputs` 의 `foot` 을
   `flpop+trdar`(현행 최근접 상권) 에서 `jipgyegu` 로 승격.
4. 승격 후에도 **출처를 밝힌다** — `inputs_source["foot"]` 에 새 값을 추가하고,
   상권 단위로 물러난 거점은 계속 그렇게 표시한다.

## 신청과 무관하게 지금 되는 것 (혼동 방지)

[finding-foot-traffic-resolution.md §3-2](finding-foot-traffic-resolution.md) 가 이미
밝힌 대로, **레이어(4-2)·시간 슬라이더(4-4)는 집계구를 기다리지 않는다.** 둘 다
08-23~24 에 배선됐다. 집계구를 기다리는 것은 **`foot` 유닛 서열 하나**다.

⚠ 상권 단위로 `foot` 을 대신하면 안 된다 — 거점당 상권 수 중앙이 2~3곳이라
"실측처럼 보이는 추정치"가 된다. 이 판단은 유지된다.
