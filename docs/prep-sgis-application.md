# SGIS 집계구 자료신청 — 제출용 준비 (2026-08-25)

> **이 문서는 코드가 아니라 사람이 할 일의 준비물이다.** `foot`(유닛 단위 유동인구)은
> 막힘 5번이고, 막는 것은 코드가 아니라 **신청·승인**이다
> ([finding-foot-traffic-resolution.md §3-1](finding-foot-traffic-resolution.md)).
> 승인까지 시간이 걸리므로 **먼저 넣고 다른 트랙을 병행한다**가 08-20 판단이었고,
> 그 판단이 아직 실행되지 않은 채 5일이 지났다. 아래를 그대로 채워 오늘 넣는다.

## 왜 이게 필요한가 (신청서에 쓸 한 문장)

54개 상권 거점의 **공실 유닛 단위** 입지 분석에 필요한 최소 공간 단위가 집계구다.
현재 보유한 유동인구는 상권 단위(거점당 1~9곳, 중앙 3곳)라, 한 거점의 공실 유닛
12개가 2~3등급으로만 갈린다 — 유닛 사이 서열을 만들어낼 수 없다.

  서비스명 후보 4종(`_TOT`·`_JIPGYE`·`_ADSTRD`·`_RESD`)은 전부 `ERROR-500` 이다 —
  다시 시도하지 말 것.

- 대안 경로: 서울 빅데이터캠퍼스에도 집계구 경계가 있으나 **역시 신청 절차**다.
  SGIS 가 반려되면 그때 간다.

## ⚠ "승인 대기" 전제를 다시 볼 것 (2026-08-25)

이 문서와 막힘 5번은 **"승인까지 시간이 걸리니 먼저 넣고 병행한다"** 를 전제로 서 있다.
그 전제가 이 문서를 5일 묵히기도 했다. 그런데 SGIS **자료제공 안내**(위 1번 URL ·
[dataProvdIntrcn](https://sgis.mods.go.kr/view/pss/dataProvdIntrcn))가 적어 둔 절차는 **4단계**이고
**담당자 승인 단계가 없다**:

> 1. 회원가입 및 로그인 → 2. 자료신청 1단계 입력 및 이용약관 동의 →
> 3. 원하시는 자료 선택 후 **자료신청 완료처리** → 4. 신청한 자료를 **자료다운로드 화면에서 다운로드**

집계구경계는 같은 페이지에서 **"공개 · 무료"** 로 표시된다. 처리 기간은 어디에도 명시돼
있지 않다(문의 042-481-2246).


## ✅ 결론 — 승인 대기는 없었다 (2026-08-25 실행·검증 완료)

위 4단계를 실제로 밟았다. **신청 완료처리 직후 `downloadList` 에서 바로 받아졌다 —
담당자 승인 단계는 존재하지 않는다.** 막힘 5번의 "승인 대기" 전제는 **근거 없는
추정이었고**, 그 추정이 이 작업을 5일 묵혔다. 확인에 든 시간은 10분이다.

### 남은 검증 둘 — 여기서 끝난 게 아니다

1. **조인키가 실제로 붙는지 아직 모른다.** 경계의 `TOT_OA_CD`(14자리)와 OA-14979
   생활인구의 집계구코드가 **같은 체계·같은 자릿수인지 대조하지 않았다.** 생활인구
   파일을 아직 안 받았기 때문이다. 붙지 않으면 경계만으로는 아무것도 못 한다 —
   이 문서 위쪽 "하나만 받으면 못 쓴다"가 여전히 성립한다.
2. **기준일이 어긋난다.** 경계는 **2025-06-30** 고정인데 생활인구는 2017.7~2026.8 이다.

   어느 구간까지 이 경계로 덮이는지는 실제 조인으로 재야 한다.

→ 다음 작업은 신청이 아니라 **코드**다: OA-14979 최근 1개월 ZIP 확보 → 코드 체계 대조 →
공간조인. `foot` 유닛 배선은 이제 **막힘이 아니라 미착수**다.

→ **즉 "신청 후 대기"가 아니라 자기신청 즉시 다운로드일 가능성이 있다.** (아래 결론으로 확정됨) 확인 방법은

받아지지 않으면 그때 대기가 실재하는 것이므로 이 문서의 종전 판단이 맞다 — 어느 쪽이든
**오늘 밟아서 확정한다.** 결과를 여기 적을 것.

## 2026-08-25 밤 — 신청 전 사전조사 (로그인 없이 확인 가능한 것을 전부 확인했다)

`남은 것` 이 지목한 **과거집계구(2016년판) 자료신청**을 밟으러 갔다. 신청 화면 자체는
로그인이 선행이라 여기서 끝까지 못 갔지만, **그 전에 확인해야 할 것 넷을 먼저 쟀다.**
셋이 새로 드러났고 그중 하나는 계획을 바꿀 뻔했다.

### ① 신청 진입점 — 찾았다 (목록 화면에 링크가 안 걸려 있다)

`openDataIntrcn` 목록 맨 아래 `※ 과거집계구 자료신청` 은 **`<a href>` 가 아니라
`fnPast()` 자바스크립트**다. 원문에서 추출한 실제 이동 경로:

    https://sgis.mods.go.kr/contents/shortcut/shortcut_05_03_past_year.jsp

`fnPast()` 는 이동 전에 확인창을 띄운다 — *"집계구 경계는 시계열 데이터가 아닙니다.
최신 집계구 경계 기준의 데이터를 받으세요. 이 자료는 과거 시점 경계 기준이 꼭
필요한 분들을 위한 자료입니다."* **확인을 눌러야 한다.** 우리가 바로 그 "꼭 필요한"
경우다(아래 ②).

비로그인으로 열면 **631바이트 · 제목만** 돌아온다 — `requestData` 와 같은 증상이고,
페이지가 없는 것이 아니라 로그인이 선행이라는 뜻이다.

### ② 신청 대상 연도 — 2016년판이 맞다 (마지막 달까지 재확인)

*"생활인구가 2016 기준"* 은 08-25 낮의 판정이었다. 그 뒤로 바뀌었을 가능성을
배제하려고 **계열의 마지막 달(2026-07)** 을 직접 받아 다시 쟀다:

| 확인 | 실측 |
|---|---|
| 파일 | `LOCAL_PEOPLE_202607.zip` (1.28GB 중 **1.9MB 만** 증분 해제) |
| 첫 멤버 | `LOCAL_PEOPLE_20260701.csv` · 33열 |
| 헤더 | `기준일ID · 시간대구분 · **행정동코드** · **집계구코드** · 총생활인구수 …` |
| 시간대 00 집계구 | **19,038개** · 전부 **13자리** (예 `1101053010001`) |

즉 **계열의 끝까지 2016년판 코드다.** 보유한 2025년 2분기 경계(14자리 · 19,097개)와는
끝내 붙지 않는다. 신청 대상은 **과거집계구 2016년 기준**으로 확정.

### ③ ⛔ 새로 드러난 것 — 이 계열은 **2026-07-31 로 생산이 끝났다**

OA-14979 데이터셋 공지:

> ※ 국가표준격자(250m 격자) 단위로의 데이터 전환으로 기존 데이터 생산이
> **2026년 7월 31일 이후 종료됨**

후속으로 무엇이 나왔는지 확인했다 — **OA-23019~23022** (`[내국인] 자치구별 서울
생활인구(250m)` 외 3종, 공개 2026-07-29, 갱신 매일).

**그런데 이름만 250m 이다.** `250_LOCAL_RESD_GU_2025.zip`(28MB)을 실제로 받아
열어 보니 행 단위가 격자가 아니다:

    "일자","시간","**자치구코드**","생활인구합계","남자 0~9세",…
    "20250101","0","**11110**",196824.08,…

**자치구 × 시간**이다. 우리가 이미 쓰는 행정동 24시간 축(§Page)보다 **거칠다.**
250m 격자 원자료는 열린데이터광장에 아직 격자 단위로 공개돼 있지 않다.

**결론: 집계구가 여전히 가장 세밀한 공개 자료이고, 계열 종료가 이 계획을 무효로
만들지 않는다.** `foot` 은 유닛의 **대표 수준**을 매기는 정적 피처이지 실시간 피드가
아니다. 2017-01~2026-07 **115개월**이 남아 있고 파일은 계속 내려받힌다. 다만 앞으로
갱신은 없으므로, 이 피처는 **그 기간의 대표값**이라고 산출물에 밝혀야 한다.

### ④ OpenAPI 로는 우회가 안 된다 — 확인했다

`SGIS_CONSUMER_KEY/SECRET` 로 인증해(`sgisapi.kostat.go.kr` · Success) 경계
엔드포인트를 전수 프로브했다:

| 엔드포인트 | 결과 |
|---|---|
| `/OpenAPI3/boundary/hadmarea.geojson` | **errCd=0 Success** (행정동만) |
| `/OpenAPI3/boundary/oa.geojson` | 404 |
| `/OpenAPI3/boundary/jipgyegu.geojson` | 404 |
| `/OpenAPI3/boundary/tot.geojson` | 404 |
| `/OpenAPI3/boundary/basicarea.geojson` | 404 |

집계구 경계는 API 로 안 나온다. **자료신청이 유일한 경로**이고, 그래서 로그인이 필요하다.

### 그래서 사람이 할 일 — 3단계, 확인창 하나

1. `https://sgis.mods.go.kr` 로그인 (이미 계정이 있다 — 08-25 낮에 2025년판을 받았다)
2. `https://sgis.mods.go.kr/contents/shortcut/shortcut_05_03_past_year.jsp` 로 이동
   → *"과거집계구 자료신청으로 이동하시겠습니까?"* **확인**
3. **집계구경계 · 서울특별시 · 2016년 기준** 신청 → `downloadList` 에서 다운로드
   (08-25 낮 실측상 **담당자 승인 단계는 없다** — 완료처리 직후 받아진다)

받은 ZIP 은 `data/bronze/seoul/{날짜}/jipgyegu_2016/` 에 풀고:

    python -m data.probe_sgis_boundary data/bronze/seoul/{날짜}/jipgyegu_2016

이 점검기는 **자릿수 13** 을 이미 기대하도록 적혀 있다(모듈 docstring 2번 항목).
13자리 · 19,038개 근처가 나오면 조인이 성립한다.

## ⛔ 조인 검증 결과 — **받은 경계로는 못 붙는다** (2026-08-25)

경계 파일 자체는 정상이다. 그런데 **생활인구와 기준연도가 달라 조인이 성립하지 않는다.**
이 문서 위쪽이 "남은 검증 둘"로 남겨 둔 항목 1·2 가 **둘 다 실패로 판정됐다.**

### 어떻게 쟀나 — 1.28GB 중 2.1MB 만 받았다

월별 ZIP 은 1.28GB 지만 전량 받을 필요가 없었다. `nio_download.do` 응답을 **스트리밍**
하면서 첫 멤버(`LOCAL_PEOPLE_20260701.csv`)를 `zlib.decompressobj(-15)` 로 증분 해제해
`시간대구분 == "00"` 구간만 읽고 끊었다 — **2.1MB 로 집계구 19,038개 전량** 확보.
같은 방법으로 스키마만 볼 때는 300KB 면 된다. 전량 다운로드 전에 이걸 먼저 할 것.

- 다운로드: `POST https://datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do?&useCache=false`
  form `infId=OA-14979` · `seq=YYMM`(예 `2607`) · `infSeq=1` · `seqNo=`(빈값)
- CSV 인코딩 **cp949** · 헤더 33열 · 키 컬럼 **`집계구코드`**(13자리) · `행정동코드`(8자리)
  · `기준일ID` · `시간대구분`(00~23) · `총생활인구수` + 성·연령 30열

### 불일치 실측

| | 경계 `TOT_OA_CD` | 생활인구 `집계구코드` |
|---|---|---|
| 자릿수 | **14** (`11010530010001`) | **13** (`1101053010001`) |
| 집계구 수(서울) | 19,097 | 19,038 |
| 기준 | `BASE_DATE` **20250630** (2025년 2분기) | **통계청 2016년 기준 집계구** |

자릿수 차이는 잉여 자리 하나였다(경계 `[8]` 번 자리는 **고유값이 `'0'` 하나뿐**). 그걸
제거해 13자리로 맞춰 대조했더니:

```
일치 7,156 / 19,097  =  37.5%      경계에만 11,941 · 생활인구에만 11,882
```

**37.5% 는 우연 일치다.** 같은 행정동(`1101053`) 안에서 경계는 집계구 일련번호가
`010001·020001~020004`, 생활인구는 `010001~010005` 로 **분할 자체가 다르다.** 7자리
행정동 prefix 는 425 대 424 로 거의 겹치는데(418) 그 아래 집계구가 갈린다 — 즉 코드
포맷 문제가 아니라 **집계구 경계가 재획정된 것**이다.

SGIS 도 같은 말을 팝업으로 띄운다:

> "집계구 경계는 **시계열 데이터가 아닙니다.** 최신 집계구 경계 기준의 데이터를 받으세요.
>  이 자료는 과거 시점 경계 기준이 꼭 필요한 분들을 위한 자료입니다."

### 그래서 받아야 할 것 — **2016년 기준** 집계구경계

`openDataIntrcn` 의 통계지역경계 표는 집계구경계를 **2025년 기준 하나만** 제공한다.
과거 시점은 별도 진입점이다:

- **과거집계구 자료신청**: https://sgis.mods.go.kr/contents/shortcut/shortcut_05_03_past_year.jsp
  (목록 페이지의 `※ 과거집계구 자료신청` = `javascript:fnPast()` 가 여기로 보낸다)
- 이 페이지도 **비로그인으로는 본문이 안 나온다**(제목만 응답) — 로그인 후 확인.
- ⚠ 여기서도 승인 대기가 없는지는 **아직 모른다.** 2025년판이 즉시 받아졌다고 과거분도
  그러리라 단정하지 말 것 — 밟아서 확인한다(그게 오늘 이미 한 번 통했던 방법이다).

받은 뒤 재검증은 **이 문서의 대조 절차를 그대로 다시 돌리면 된다** —
일치율이 95% 를 넘으면 조인 성립, 그 아래면 또 다른 기준연도다.
