# Page 구조 감사·영향·재현성 분석

이 보고서는 동결된 인벤토리를 대상으로 수행한 연구 실행 기록이다. 논문 본문에 사용할 새 수치는 아직 근거 인덱스에 등재하지 않았다. **자동 구조 일관성과 독립적인 현실 공실 정확성을 구분한다.**

## 실행 범위와 재개 이력

[분석 계획](analysis-plan.json)을 저장한 후 현재 마스터 전체, 현재 선택되는 점포·폴리곤 원천, 층 범위, 릴리스 차이를 검사했다. 모든 대장 원본 행의 감사, 모든 결합 간선 복원, 도형 위상 검증을 완료한 것은 아니다.

첫 번째 격리 재실행은 완료됐지만 두 번째 실행 도중 세션이 중단되고 중간 결과가 먼저 커밋됐다. [재개 계획](resume-plan.json)에 실행기 변경과 첫 실행 파일의 해시를 기록하고, 중단된 두 번째 실행은 보존한 채 새 프로세스에서 처음부터 다시 수행했다. 실행기 변경은 재개 제어 흐름이며 제품 변환·집계 코드는 수정하지 않았다.

입력은 [인벤토리 manifest](../page-inventory-20260906/manifest.json)로 특정한다. Bronze 원본, Silver 층 속성, Gold 수용량 자료를 읽고 연구 폴더에서만 마스터·커버리지·서빙 결과를 생성한다. 과거 Gold가 어떤 입력으로 만들어졌는지, 원천 API 응답을 처음부터 다시 수집했을 때 같은 결과인지까지 입증하는 실험은 아니다.

## 구조 감사 결과

[structural-audit.json](structural-audit.json), [findings.json](findings.json), [hub-summary.csv](hub-summary.csv)에 거점별 집계와 검사 분모를 기록했다.

- 현재 서빙 레지스트리의 **66개 거점, 52,642개 마스터 폴리곤**을 검사했다.
- 마스터 ID 중복, 현재 폴리곤 원천의 지번 존재, 도형의 기본 형식, 분자·분모 범위, 공실 계산식, 상태 계산식 검사에서 실패가 없었다. 이것은 현장 정확도 검증이 아니다.
- 층 정보가 있는 **30,912개 폴리곤**에서 층 집합·활성 범위·공실 상하한 계산이 일치했다.
- 모든 거점의 원천 관측 시점 정렬은 **평가 불가**로 남겼다. 수집 폴더 날짜를 실제 관측일로 바꾸지 않았다.
- 점포 좌표와 같은 지번의 건물 외곽이 일치하지 않는 수는 진단값으로만 남겼다. 경계점·좌표 오차·지번 내 다동 구조 때문에 그 수를 오귀속 오류 수로 쓰지 않는다.

넓게 적용한 ‘같은 지번이면 수용량도 같다’ 검사에서 **613개 비교 행, 428개 거점·지번 그룹**이 표시됐다. [후속 분류](same-lot-flag-qualification.json) 결과 모두 `floor_approx`와 `pip_only` 또는 `polygon_only` 경로였고, 현행 대표 집계에 포함되는 행은 없었다. 폴리곤별 근사값은 건물이 다르면 달라질 수 있으므로 이 진단을 **확정 오류로 집계하지 않는다**. 원래 검사 결과와 사후 해석을 모두 보존했다.

## 독립 표본 감사 상태

[sample-design.json](sample-design.json)의 마스터 전역 지번 프레임에서 **40,125개 객체를 기준으로 211개 표본**을 층화 무작위 추출했다. 난수 시드·층별 포함확률·가중치는 [검토용 CSV](independent-review-sample.csv)에 있다. 목표 검토 예산에 따른 예비 배분이며 특정 정밀도 달성을 주장하지 않는다. 미매칭 원천 객체까지 포함한 표본은 아니다.

독립 검토자 판정은 **미실행**이며 모든 표본은 `unresolved`다. 따라서 독립 오류율·공실 정확도·검토자 일치율을 계산하지 않았다.

[기존 검증 자료 조사](legacy-review-evidence.json)에서 채워진 가로수길 라벨 파일과 미기입된 수용량 확인표들을 찾았다. 기존 메모에는 AI 판독 표시가 있어 이번 표본의 독립적인 사람 정답으로 재사용하지 않았다. 새로운 사람이 확인한 동시점 자료는 아직 확보되지 않았다.

## 영향 분석

### 기존 층 정보의 공실 범위

[impact-intervals.json](impact-intervals.json)에 현행 집계 대상 중 층 단위가 확인된 지번만 포함해 기존 점유 상·하한을 합산했다. 동일 지번은 현행 서빙 순서대로 한 번만 포함하고, 호실·점포 단위와 혼합하지 않았다.

거점별 공실 범위 폭은 모두 양수였으며 중앙값 **16.235267101643892%p**, 최댓값 **34.38818565400844%p**였다. 이는 층을 특정하지 못한 활성 정보의 배정에 따른 범위다. 통계적 신뢰구간, 실제 공실률 오차, 새로 확인된 빈 층의 수로 해석하지 않는다. 독립적으로 확인한 수정값이 없어 ‘오류 정정 후 정확도 개선’ 분석은 수행하지 않았다.

### 폴리곤 순서의 민감도 — 사후 탐색

지번 내 차이 진단을 확인한 뒤 [추가 계획](exploratory-order-plan.json)을 기록하고, 같은 폴리곤 내용의 역순·ID 정렬·고정 난수 순서를 각각 기존 서빙 함수에 입력했다. 입력값과 집계 제외 규칙은 바꾸지 않았다.

[order-sensitivity.json](order-sensitivity.json)의 **198개 시행**에서 거점 전체 집계는 모두 같았다. 하지만 **65개 거점**에서 격자 소속이나 격자별 분자·분모가 달라졌다. 지번 중복 제거 시 먼저 만난 폴리곤의 위치를 셀 배정에 사용하므로, **동일 입력 바이트에 대한 반복 재현과 행 순서 불변성은 다르다.**

이 실험은 사후 탐색이며 최대 가능한 변동이나 현실 위치 오차를 측정한 것은 아니다. 현행 지번·집계 규칙을 수정하지 않았으며 제품 변경 판단은 별도 작업이다.

## 재현성 최종 판정

[reproduction-comparison.json](reproduction-comparison.json), [비교표](reproduction-summary.csv), [서빙 교차 검사](serving-crosscheck.json)를 기준으로 다음을 확인했다.

| 검증 | 결과 | 확인한 범위 |
|---|---|---|
| 두 번의 마스터 바이트 비교 | 66/66 일치 | 별도 프로세스에서 같은 선택 입력을 사용 |
| 두 번의 마스터 의미 비교 | 66/66 일치 | 고유 폴리곤 ID로 연결한 전체 피처 |
| 두 번의 커버리지 비교 | 66/66 일치 | 사전 지정한 생성시각 `built_at`만 제외 |
| 두 번의 서빙 결과 비교 | 66/66 일치 | 격자·집계·앵커 응답 전체 |
| 저장된 마스터와 현재 입력 재생성본 | 66/66 의미 일치 | 이번 입력 묶음으로 현재 저장본이 재현됨 |
| 독립 감사 합산과 실제 서빙 집계 | 66/66 일치 | 수용량·활성값·지번 수·거점 공실 지표 |

저장본 대비 거점 공실 지표 차이는 전부 **0.0%p**였고 변경된 폴리곤은 없었다. 이는 현재 입력 묶음과 현재 코드의 재현 결과이며 과거 실행 이력이나 현실 공실 정확성을 보증하지 않는다. 원본 보존 검증 결과는 [사후 검증](input-verification-after.json)에 기록한다.

[릴리스 비교](release-comparison.json)는 보존된 점포 원천이 여러 벌인 가로수길에서만 가능했다. 비교한 파일은 `2026-07-08`과 `2026-07-19` 보관 폴더의 자료다. 공통 고유 ID는 **2,926개**, 후속 파일의 신규 ID는 **2,338개**, 사라진 ID는 없었다. 공통 ID의 검사 대상 키·층·좌표·대분류 필드는 바뀌지 않았다. 이 날짜들은 보관 라벨이며 원천 관측일로 확정하지 않았다. 과거 수집 범위의 동일성이 검증되지 않았으므로 신규 ID를 신규 개업으로 해석하지 않는다. 다른 거점의 릴리스 비교는 수행할 보존본이 부족했다.

**완료 범위:** 현재 자료의 구조 감사, 검토 표본 생성, 층 범위·행 순서 영향 분석, 현재 마스터·서빙의 반복 재현 비교. **미완료 범위:** 독립 사람 판정, 동시점 현실 공실 정확도, 원장 전수 계보 감사, 오류 정정 효과의 독립 평가. 원천 부재·미판정 값을 채워서 이 공백을 숨기지 않는다.

## 자료 보존과 재실행

원본·재생성 Gold 사본과 실행 로그는 로컬 연구용으로 보존하고 Git 추적에서 제외한다. 비교 결과·해시·서빙 결과·실행기는 추적한다. 해시만으로 원천 보존이나 클라우드 접근이 보장되지는 않는다.

실행기는 [run_page_quality_audit.py](../../run_page_quality_audit.py), 순서 민감도 실행기는 [page_order_sensitivity.py](../../page_order_sensitivity.py)다. 본 실행은 원본을 덮어쓰는 재빌드·외부 API 호출·제품 코드 수정 없이 수행한다. 입력 해시가 바뀌면 기존 실행에 섞지 말고 새 실행 계획과 폴더를 사용해야 한다.
