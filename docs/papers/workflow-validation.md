# SpaceOS 원문 기반 논문 제작 방식 — 여섯 차례 검증 보고

검토일: 2026-09-06. 대상 제안: 후보 논문 원본을 GitHub에 보관하고 AI가 빠짐없이 읽은 뒤, SpaceOS 데이터와 선행연구 방법을 조합하여 가설을 검증하고 논문을 작성한다.

**판정: 원문에 근거한 연구 설계는 권장한다. 다만 GitHub 업로드와 반복 정독만으로 가설 검증이 완성되지는 않는다. 문헌별 권리 확인, 읽기 범위 기록, 측정 개념 대조, 독립 평가와 재현 가능한 분석을 추가해야 한다. 현재는 Page의 데이터 품질·계산 재현성 연구를 우선 진행하는 것이 타당하다.**

여기서 ‘여섯 차례’는 서로 다른 판정 기준과 증거를 사용한 검토다. 같은 질문에 AI가 반복해서 동의한 것을 검증 횟수로 세지 않았다. 독립 연구자들의 심사, 독립 실험의 반복, 논문 제작 생산성의 비교 실험을 수행했다는 뜻도 아니다. 후보 전체 PDF의 문자 단위 정독은 이번 작업의 완료 항목이 아니다.

## 작업 범위와 근거

- 작성 대상: 이 보고서. 논문 본문, 제품 코드, 원천 데이터는 변경하지 않는다.
- 내부 입력: [후보표](literature-candidates.md), [후속 뼈대 선정](backbone-selection.md), [데이터 명세](data-specification.md), [Page 프로토콜](page-data-quality-protocol.md), [분석 실행 기록](audits/page-analysis-20260906/README.md), [인벤토리](audits/page-inventory-20260906/manifest.json).
- 외부 입력: 후보별 Crossref 레코드 실조회, 아래 출판사·저자 공개 자료, 이용허락과 연구 투명성 안내.
- 문서 확인 항목: `six_reviews_have_evidence_and_verdict`, `nine_candidates_accounted_for`, `reading_scope_disclosed`, `local_links_resolve`, `empirical_limitations_retained`.
- 금지: 원문 미확인을 정독 완료로 표기, 실측·정답 생성, 기각 결과 변경, 기존 실행을 사전등록 가설 검증으로 소급 포장, 논문 원문 일괄 재배포.

## 1차 — 후보의 실재성·선정 상태 검증

**질문:** 현재 후보 파일에 있는 논문들이 그대로 최종 뼈대가 되는가?

**실제 확인:** 저널 후보의 DOI를 각각 Crossref API로 조회하여 제목과 대조했다. 조회 경로는 `https://api.crossref.org/works/{DOI}`이며 제목, 온라인·인쇄 출판일, `license`, `content-version`, 관계·업데이트 필드를 확인했다. 예를 들어 [개별 주택 탐지 레코드](https://api.crossref.org/works/10.1080/24694452.2019.1665492)와 [자선 광고 레코드](https://api.crossref.org/works/10.1080/00913367.2023.2183285)에서 아래 버전·권리 차이를 확인할 수 있다. 아래 후보표의 저널 논문 외에 ICDE의 O²-SiteRec이 학회 보조문헌으로 들어 있다. 후속 `backbone-selection.md`는 Page에 Alsudais의 Inside Airbnb 감사 연구, Posting에 fuzzy MCDM 연구, Program에 HaluCheck를 우선 배치했다. 따라서 초기 후보 묶음과 후속 선정 묶음은 같지 않다.

**판정:** 서지 식별은 확인했다. ‘모두 AI/MIS 분야 Q1이며 현재 최종 뼈대다’라는 전제는 충족되지 않는다. 기존 문서에도 분야·연도별 Q1 검증의 공백이 남아 있다. Q1은 논문 개별 품질의 보증이 아니며, 평가체계·연도·저널 분야를 특정해야 한다. 이 보고서에서 Q1 판정을 새로 확정하지 않았다.

추가로 *Individual Vacant House Detection*은 Crossref상 온라인 출판과 인쇄본 출판 연도가 다르다. 기존 후보표의 온라인 연도 표기가 곧 가짜 서지는 아니지만, 최종 참고문헌에서는 사용하는 출판본과 연도 규칙을 통일해야 한다. DOI만 확인하면 이러한 버전 차이를 놓칠 수 있다.

**진행 조건:** 초기 후보는 관련연구로 유지하되, 현재 연구 질문을 실제로 지탱하는 핵심 문헌을 다시 표시한다. 출판본·저자 공개본·부록·정정 공지를 구분하고, Q1 근거는 별도의 공식 레코드로 확인한다. Crossref 응답에 정정 관계가 없었다는 것만으로 정정·철회가 없다고 보증하지 않는다.

## 2차 — 원문 확보·GitHub 보관 조건 검증

**질문:** 논문을 읽으려면 모든 출판사 PDF를 GitHub에 올리는 것이 필요한가?

**실제 확인:** Crossref의 `license`와 `content-version`, 출판사 원문에 표시된 이용허락을 대조했다. 표에서 ‘메타데이터’라고 적힌 사항은 PDF 자체의 권리 문구까지 대조한 최종 허가 판정이 아니다.

| 후보 | 이번 권리·접근 확인 범위 | 보관 판단 |
|---|---|---|
| CityTransfer | Crossref에는 ACM 일반 저작권 정책 링크. 자동 원문 접근 실패 | 개별 파일 권리 확인 전 일괄 업로드 대상에 넣지 않는다 |
| Weighted Adversarial Network | Crossref에는 ACM 일반 저작권 정책 링크. 자동 원문 접근 실패 | 출판사·저자 제공본을 확보하고 버전별 조건 확인 |
| Census Tract Housing Vacancy | Crossref의 출판본 메타데이터에 CC BY 4.0. 출판사 검색 결과로 연구 내용 확인 | PDF와 제3자 자료 표기를 대조한 후 출처·라이선스와 함께 보관 가능 여부 확정 |
| Individual Vacant House Detection | Crossref 이용허락 목록 비어 있음. 이번 출판사 직접 접근 실패 | 허가가 없다는 확정도, 자유 재배포가 된다는 확정도 하지 않는다 |
| Monte Carlo simulations | 출판사 페이지에 구매 대상 표시. Crossref의 정책 링크는 `tdm` 항목 | 텍스트 마이닝 정책 링크를 PDF 재배포 허가로 해석하지 않는다 |
| Sensitivity Analysis | Crossref의 정책 링크가 `tdm` 항목. 원문 미확보 | 이용 가능한 저자본·기관 접근 및 사용 조건 확인 필요 |
| Personalized persuasion | 출판사 Rights and permissions에 CC BY 4.0 확인 | 저자·출처·라이선스·변경 여부 표시와 제3자 자료 조건 준수 |
| Human favoritism | Cambridge PDF 첫 페이지에서 CC BY 4.0 확인 | 해당 조건을 지켜 원본을 보관·공유할 수 있음 |
| Charitable Giving Ads | Crossref의 출판본 메타데이터에 CC BY-NC-ND 4.0. 이번 출판사 접근 실패 | 비영리·변경금지 조건과 실제 파일을 대조해야 함. 사업용 저장소라고 자동 적합 판정하지 않는다 |

ACM은 현재 전면 공개 전환을 안내하고 있다. 따라서 이전 접근 실패나 이번 HTTP 오류를 유료 장벽의 증거로 사용하면 안 된다. 반대로 일반 공개 정책만으로 특정 과거 파일에 임의의 CC 라이선스를 붙이지도 않는다. [ACM 공개 전환 안내](https://prod-www.acm.bloomreach.cloud/about-acm/acm-pres-on-oa-transition-and-dl-changes).

**판정:** GitHub는 버전 관리 수단으로 유용하지만 필수 원문 저장소는 아니다. 비공개 저장소라는 사실만으로 제3자 저작물의 이용 권한이 새로 생기지 않는다. 저자가 자신의 원고를 공유할 권한과 우리가 그 원고를 다시 배포할 권한도 구분한다. 출판 전 원고·게재 승인본·최종 출판본의 공유 조건이 다르다. [Taylor & Francis의 버전별 안내](https://authorservices.taylorandfrancis.com/research-impact/sharing-versions-of-journal-articles/).

**진행 조건:** 파일별로 DOI, 버전, 취득 URL·날짜, SHA-256, 페이지 수, 라이선스 근거, 저장 위치를 기록한다. GitHub에는 서지·방법 분석·코드·자체 산출물을 우선 관리하고, 원문은 해당 조건이 허용하는 경로로 연구 환경에 제공한다. 전체 텍스트 추출본이나 번역본도 원문 재배포 문제를 자동으로 피하는 수단이 아니다. [CC BY 조건](https://creativecommons.org/licenses/by/4.0/), [CC BY-NC-ND 조건](https://creativecommons.org/licenses/by-nc-nd/4.0/).

## 3차 — ‘한 글자도 빠짐없이 읽기’의 검증 가능성

**질문:** 업로드 후 정독을 지시하면 원문 이해의 완전성이 보장되는가?

**실제 확인:** Cambridge 원문에서 표지·라이선스와 Methods의 연구 설계·절차를 확인했다. 원문은 참가자를 baseline, partially informed, informed 조건에 무작위 배정한다. 기존 후보표의 ‘blind 평가한 뒤 제작 주체를 공개하는 2단계 평가를 그대로 적용’이라는 설명은 원문 설계를 정확히 재현한 설명이 아니다. 같은 참가자를 전후 측정한다면 SpaceOS가 새로 도입한 설계이며 순서·기억 효과를 따로 다뤄야 한다. [원문 Methods §3.1–3.3](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/S1930297523000372).

또한 이 원문은 부록의 데이터·코드·참가자 안내와 사전등록 자료를 참조한다. Matz 논문도 출판사 페이지에서 별도 Supplementary Information 문서를 제공한다. 본문 PDF만으로 연구에 필요한 모든 자료가 갖춰지는 것은 아니다. [Matz 출판사 페이지의 부록](https://www.nature.com/articles/s41598-024-53755-0).

OpenAI의 API 파일 입력은 PDF의 추출 텍스트와 페이지 이미지를 처리하는 방식을 설명한다. 이는 GitHub에 저장된 PDF가 Codex 작업에서 자동으로 전부 열리고 검토됐다는 보증이 아니다. 실제 사용하는 작업에서 파일 열기·추출·이미지 확인을 수행하고 그 범위를 남겨야 한다. [OpenAI 파일 입력 문서](https://developers.openai.com/api/docs/guides/file-inputs).

**판정:** ‘완벽히 읽었다’라는 자기보고는 통과 조건으로 부적절하다. 이번에도 PDF 화면 캡처 시도는 시간 초과로 실패했다. 따라서 텍스트의 해당 절을 확인한 것과 페이지 시각 대조를 완료한 것을 구분했다. 전체 후보의 수식·표·각주·부록을 전수 검토했다고 주장하지 않는다.

**진행 조건:** 논문별 읽기 장부를 만든다. 각 PDF 페이지와 부록 항목에 `텍스트 확인 / 도표·수식 시각 확인 / 방법 추출 / 미해결`을 기록한다. 모든 페이지가 장부에 포함돼야 하며, 빈 추출·깨진 수식·각주 누락은 미해결로 남긴다. 핵심 주장에는 인쇄 페이지와 PDF 페이지, 절·표·식 위치를 연결하고 사람이 원문을 대조할 수 있게 한다. 분할 정독 뒤 논문 전체의 정의·가정·분모가 일관되는지도 다시 확인한다.

페이지 확인율은 작업 범위의 지표다. 모든 글자의 정확한 인식이나 과학적 이해까지 수학적으로 보증하는 지표로 사용하지 않는다.

## 4차 — 후보별 데이터·측정 개념·방법 적합성

**질문:** SpaceOS의 공공데이터를 후보 논문 입력으로 바꾸면 같은 연구 질문을 검증할 수 있는가?

**실제 확인:** 후보표의 데이터·타깃 설명을 데이터 명세, Page 프로토콜 및 실제 감사 기록과 대조했다. 아래에서 초록 수준 문헌의 세부 모델·평가 절차는 여전히 원문 검증 대상이다.

| Human favoritism — [10.1017/jdm.2023.37](https://doi.org/10.1017/jdm.2023.37) | 생성 주체와 출처 공개 조건의 평가 | 참가자 판단이 필요. 문장 사실성은 별도 측정해야 함 | Program 평가 설계 참고 |
| Charitable Giving Ads — [10.1080/00913367.2023.2183285](https://doi.org/10.1080/00913367.2023.2183285) | AI 광고와 공개 정보에 대한 반응 연구 | 자선과 지역 상점의 목적 차이. 소비자 반응 데이터·원문 절차 미확보 | Program 후속 관련연구 |

**판정:** 동일한 공공 API를 사용해야 하는 것은 아니다. 중요한 것은 관측 단위, 측정 개념, 시점, 타깃, 결과를 해석할 조건이 대응하는가다. 반대로 같은 ‘공실’ 또는 ‘매출’이라는 이름과 공공 출처만으로 대응한다고 판정할 수 없다.

**진행 조건:** `원문의 개념 → 원문 측정법 → SpaceOS 변수·단위·시점 → 타당성 근거 → 추가 수집 → 허용되는 주장`의 연결표를 먼저 완성한다. 결정적인 타깃이 없으면 연구 질문을 현재 검증 가능한 범위로 좁히거나 데이터를 추가로 수집한다. 결측 타깃을 AI 판정이나 제품 예측값으로 만들어 성공을 평가하지 않는다.

## 5차 — 가설 검증과 결과 도출의 타당성

**질문:** 기존 SpaceOS 결과에 맞는 논문 구조를 고르면 확인적 연구가 되는가?

**실제 확인:** 기존 Page 실행 기록은 자동 구조 감사, 입력 순서 민감도, 반복 재생성을 보고한다. 독립 사람 판정은 미실행이고, 원천 관측 시점 정렬도 평가 불가로 남아 있다. 입력 순서 분석은 사후 탐색으로 명시돼 있다. 따라서 이를 뒤늦게 작성한 가설의 사전등록 검증이라고 바꾸어 쓸 수 없다.

COS의 사전등록 안내도 이미 본 데이터에서 도출한 가설과 보지 않은 자료를 통한 확인을 구분한다. 이 구분에 비추어 현재 결과를 탐색적 발견으로 유지하고, 후속 확인 계획에 기존 데이터 접근 범위를 밝혀야 한다. [COS 사전등록 안내](https://www.cos.io/initiatives/prereg).

**판정:** 원문은 설계 근거를 제공하지만 SpaceOS 가설을 대신 검증하지 않는다. 연구에는 검증할 관계·측정법·비교 기준·분석 단위가 필요하다. 모든 연구를 유의확률 중심 가설검정으로 만들 필요도 없다. 고정 데이터의 계산적 불변성 검사는 명시한 조건에 대한 속성 검증으로 보고할 수 있다.

| 가능한 Page 연구 주장 | 현재 증거와 추가 조건 |
|---|---|
| 같은 입력·코드에서 계산 결과가 반복되는가 | 기존 재실행 결과로 그 실행 범위에서 보고 가능. 독립 팀·클라우드 재현까지 확장한 주장은 추가 실행 필요 |
| 동일 내용의 입력 순서가 공간 출력에 영향을 주는가 | 기존 탐색 결과로 해당 스냅샷의 민감도 보고 가능. 새로 확인한 오류·실제 위치 오차라고 부르지 않음 |
| 공실 정보가 현실과 얼마나 정확히 일치하는가 | 동시점의 독립 참조자료와 판정 필요. 내부 일관성 검사로 대체 불가 |
| 오류 수정이 의사결정 또는 정확도를 개선하는가 | 확정 오류·수정 근거·평가 기준·독립 평가자료 필요. 현재 결과만으로 효과 주장 불가 |

**진행 조건:** 후속 분석 전에 주 질문, 평가 단위, 주 지표, 비교 기준, 표집·미판정 처리, 필요한 효과크기·정밀도와 분석법을 고정한다. 공간 중복·같은 지번·같은 원천값을 독립 표본으로 부풀리지 않는다. 학습 연구는 공간·시간 누출을 차단하고, 확인 연구는 결과를 보지 않은 자료 또는 신규 독립 판정을 사용한다. 비유의·기각·미평가도 그대로 보고한다.

## 6차 — 재현성·학술 기여·작업 효율 검증

**질문:** 제안한 방식이 현재 병목을 해결하고, 심사 가능한 자체 연구로 이어지는가?

**실제 확인:** [재현 비교](audits/page-analysis-20260906/reproduction-comparison.json)와 [순서 민감도](audits/page-analysis-20260906/order-sensitivity.json)는 같은 입력 반복에서의 일치와 입력 순서 변화에 따른 공간 출력 차이를 함께 남긴다. [인벤토리](audits/page-inventory-20260906/manifest.json) 및 실행 기록은 원본 일부가 Git 추적 대상이 아님을 밝힌다. 따라서 코드·문헌을 푸시했다고 클라우드에서 분석 입력까지 확보됐다고 볼 수 없다. 해시는 파일 식별에 유용하지만 원본 파일 자체를 대신하지 않는다.

현재 Page 뼈대인 Alsudais의 [저자 공개본 안내](https://arxiv.org/abs/2007.03019)는 데이터 수집 오류와 릴리스 재현 문제를 다루는 짧은 연구 노트라고 명시한다. SpaceOS가 같은 순서의 목차에 지역명만 바꾸면 충분한 기여가 생기는 것은 아니다. 이 프로젝트의 독자적 질문은 공간 결합·측정 단위·집계 절차가 표시 결과와 해석에 어떤 영향을 주는지에 있다. 이 기여가 어디까지 검증됐고 어디부터 추가 자료가 필요한지 분명히 해야 한다.

**판정:** 핵심 문헌의 정독과 구조화된 방법 기록은 설계 오류를 발견하는 데 유용했다. 다만 이번 검토는 전체 논문 제작 시간 단축률, 누락률 감소, 학위논문·저널 게재 성공률을 측정하지 않았다. ‘효과가 입증된 자동 논문 제작 방식’이라는 주장은 하지 않는다. 네 편의 독립 논문이 되는지도 서로 구별되는 질문·기여·증거와 목표 심사 기준에 따라 결정된다.

**진행 조건:** 참고문헌의 문장·표현을 복제하는 대신 이론·방법의 출처를 인용하고 적용 변경을 설명한다. 사용한 모델·프롬프트·도구·환경·실행 코드와 결과 근거를 남기며 저자가 인용·계산·해석을 검토한다. 동일 데이터를 재사용하는 논문 간에는 중복과 차별성을 밝힌다. 석사 수준 충족은 결과를 긍정적으로 만드는 것이 아니라 연구 질문·타당한 절차·검증 범위·독립 기여를 갖추는 방향으로 준비한다.

작업 효율을 추후 실제 비교하려면, 짧은 요약 중심 검토와 원문·부록·읽기 장부 검토에 동일한 방법론 추출 과제를 부여한다. 원문을 확인한 사람이 정답 기준을 만들고 검토 경로를 가린 채 핵심 항목 누락·오해·근거 추적 가능성·소요시간을 평가한다. 이 비교 실험은 제안이며 이번에 수행한 결과가 아니다.

## 권장 실행 순서

1. **Page 핵심 문헌 묶음 확정:** Alsudais 공개본과 최종 출판본의 차이를 확인하고, 측정·표집·공간 결합 평가에 필요한 보조문헌을 선정한다. 초기 후보 전체를 동일 깊이로 읽는 작업은 후속 연구의 필요에 맞춰 배분한다.
2. **원문과 부록 확보:** 파일별 권리·버전·해시·페이지 목록을 작성한다. 허용되는 원문만 연구 환경에 제공하고, 권리 불명확 파일은 링크와 접근 필요 상태로 관리한다.
3. **방법 근거표 작성:** 연구 질문, 이론, 가설 또는 검증할 속성, 관측 단위, 타깃, 표집·분할, 기준선, 수식·통계, 한계를 원문 위치와 연결한다. 기존 후보표의 Zhang·Gosline 실험 설명부터 정정 대상에 넣는다.
4. **SpaceOS 설계 동결:** 지금까지 본 데이터·분석과 새 확인 분석을 분리한다. 계산 재현성에 한정한 연구인지, 독립 현실 정확도까지 주장할 연구인지에 따라 추가 자료를 확정한다.
5. **독립 평가와 재현 패키지 완성:** 기존 검토 표본의 사람 판정, 필요 시 새 동시점 자료 확보, 분석 환경의 입력 접근 검증을 수행한다. 원천 없는 항목은 미평가로 유지한다.
6. **검증된 결과부터 집필:** 새 실측 수치는 근거 인덱스에 등재한 뒤 사용한다. 문제·방법·결과·한계를 절 단위로 작성하고, 원문 인용 위치와 실행 결과를 대조한다.

바로 다음 산출물은 **Page 핵심 문헌의 원문·부록 목록과 페이지별 방법 근거표**가 적절하다. 이 보고서는 제안된 작업 방식의 검토를 마친 기록이며, 원문 전체 확보·전체 정독·신규 가설 검증을 완료한 기록은 아니다.
