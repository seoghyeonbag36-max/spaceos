# Page 데이터 품질 감사 — 연구 질문·변수·평가 절차

상태: **연구 설계 작성 완료 / 감사·표본 추출·독립 판정·실험은 미실행**.

가제: **공공데이터 결합 기반 상업용 공실 정보의 데이터 품질과 재현성 평가: SpaceOS 사례**

## 작업 계약

- 대상 파일: `docs/papers/page-data-quality-protocol.md`만 작성한다. 논문 본문 전체를 채우는 작업이 아니다.
- 입력: [데이터 명세표](data-specification.md), [근거 인덱스](evidence-index.md), [뼈대 선정 검토](backbone-selection.md), 아래 구현·산출물과 저자 공개 논문. 공공 원천·가공값·추정 경로·독립 판정을 구분한다.
- 문서 통과 조건: `protocol_sources_exist`, `protocol_rq_variable_metric_traceability`, `protocol_denominators_defined`, `protocol_unknowns_preserved`, `protocol_scope_unchanged`. 구체 판정은 마지막 절에 둔다.
- 금지: 결측 보완, 새로운 실측 수치 선언, 현장 정답의 대리 생성, 제품의 출처 계약·앵커 해석·집계 제외 규칙 변경, 과거 실험군과 현재 서빙본 혼합.

## 선행연구와 확장 범위

Abdulkareem Alsudais, *Incorrect data in the widely used Inside Airbnb dataset*, Decision Support Systems, 2021, DOI [10.1016/j.dss.2020.113453](https://doi.org/10.1016/j.dss.2020.113453). 이번 작업에서 [저자 공개본의 본문](https://arxiv.org/pdf/2007.03019)을 확인했다. 공개본과 최종 출판본의 일치 대조는 미완료다. 앞선 선정 문서의 ‘전체 본문 미확인’보다 확인 범위가 진전된 기록이며, 다른 P의 검증 상태를 바꾸지는 않는다.

저자 공개본의 데이터 구조·오류 탐지 절은 서로 다른 객체 유형이 같은 식별자를 사용할 때 리뷰가 잘못 귀속되는 사례와 원천 대조 절차를 다룬다. 릴리스 비교 절은 자료 버전의 차이가 재현에 미치는 영향을 다루며, 변화 자체가 수집 오류라는 결론은 내리지 않는다. 이 연구가 사용한 민간 플랫폼 공개 자료와 SpaceOS의 공공 행정자료는 동일한 자료가 아니다. 이식하는 것은 **객체 의미 확인 → 원천 대조 → 버전 고정**의 검증 구조다.

SpaceOS의 확장 기여는 식별자뿐 아니라 측정 단위·공간 결합·집계 제외가 공실 정보에 미치는 영향을 추적하는 데 둔다. 아래 연구 질문·변수·표집·평가는 이 프로젝트를 위한 새 설계이며 선행논문의 실험 결과가 아니다. 저널 등급의 근거와 한계는 선정 검토 문서를 따른다.

## 코드와 산출물에서 확인한 설계 전제

| 구현·자료 | 확인한 내용 | 감사 설계에 반영할 점 |
|---|---|---|
| [거점 레지스트리](../../data/config/page_hubs.py) | `ACTIVE_HUBS`가 서빙 목록의 출처 | 감사 시작 시 목록·설정·해시를 동결한다. 파일 디렉터리 수로 모집단을 정하지 않는다 |
| [Page 마스터 빌더](../../data/pipelines/build_page_master.py) `_aggregate`, `run` | 지번별 결합, 층 정보 유무에 따른 분기, 원천별 최신 파일 로딩 | 같은 필드명이라도 층·점포·호 단위와 실제 사용한 입력 버전을 별도로 기록한다 |
| [서빙 집계](../../apps/backend/app/services/gold_vacancy.py) `build_cells` | 지번 중복 제거; `floor_ouln` 사용; `expos_units`, `floor_approx`, `polygon_only` 제외 | 표시 폴리곤과 대표 집계 모집단을 구분하고 현행 규칙을 그대로 검증한다 |
| [가로수길 마스터 표본](../../data/gold/garosugil/page_building_master.geojson) | `pnu`, `id`, `capacity`, `active`, `stores`, `source`, `capacity_method`, 공실 범위 및 층 필드 존재 | 스키마 표본 확인이다. 모든 거점·행의 필드 충족을 보증하지 않는다 |
| [가로수길 커버리지](../../data/gold/garosugil/coverage.json) | 표시·제외·방법별 집계와 `built_at` 존재 | 파일의 커버리지 명칭만 보고 서빙 집계 커버리지와 동일하다고 판단하지 않는다 |
| [가로수길 앵커 파일](../../data/gold/garosugil/calibration.json) | 앵커·추정값·방법·주석 존재 | 외부 집계 대조의 참고자료다. 개별 공실 정답으로 사용하지 않는다 |
| [원천 로더](../../data/collectors/common.py), [층 속성 빌더](../../data/pipelines/build_building_attrs.py) | 마스터 빌더가 원천 로더와 속성 자료에 의존 | 날짜별 Bronze 하위 경로까지 탐색한다. 거점 폴더 직하에 파일이 없다는 이유로 원본 누락을 선언하지 않는다 |

`scripts/pppp_status.py`를 읽기 전용으로 실행해 정상 종료를 확인했다. 진행률은 연구 정확도가 아니다. 이 문서에는 그 출력에서 새 경험적 수치를 옮기지 않는다.

**주의:** `vacancy_source="gold"`라는 기존 제품 출처 계약은 유지한다. 연구에서는 그 가공값의 타당성을 별도로 평가한다. `gold` 라벨만으로 현장 공실의 독립 정답이 확보된 것은 아니다. 과거 지상검증 기록도 원본·판정 시점·표집 절차를 확인하기 전에는 현재 평가셋으로 재사용하지 않는다.

## 연구 질문과 검증할 주장

| ID | 연구 질문 | 관측·설명 변수 → 결과 변수 | 평가 및 주장 가능한 범위 |
|---|---|---|---|
| RQ1 | 객체 귀속·측정 단위·시점의 불일치는 어디서 발생하고 어떤 집계 경로에 집중되는가? | 결합 경로, 단위, 원천 시점, 제외 사유 → 규칙 위반, 확인 오류, 판단 불가 | 전수 구조 검사와 층화 확률표본 독립 감사. 구조적 의심과 실제 확인 오류를 분리한다 |
| RQ2 | 확인된 자료 오류 또는 판정 불가능한 입력에 의존하는 정도는 Page 집계값과 표시 대상에 얼마나 영향을 주는가? | 확인 오류 유형, 분석용 격리 여부, 알려진 층 귀속 범위 → 집계 차이, 잔존 커버리지, 상태 전이 | 동일 스냅샷의 짝지은 분석. 정확도 향상·실제 공실 감소·사업 성과를 의미하지 않는다 |
| RQ3 | 동일 입력을 다시 처리할 때 결과가 재현되는가? 서로 다른 입력 릴리스에서 변화는 어디서 발생하는가? | 원천 해시, 코드·환경·설정, 릴리스 → 재실행 불일치, 진입·이탈·공통 객체의 변화 | 고정 입력 재실행과 릴리스 비교를 별도 실험으로 보고한다. 릴리스 변화만으로 오류라 하지 않는다 |

주가설의 방향을 ‘개선’으로 고정하지 않는다. 오류가 드물거나, 영향이 작거나, 입력 보존이 부족하여 검증하지 못하는 결과도 유효한 결과로 기록한다. RQ1을 주 분석, RQ2·RQ3을 후속 분석으로 둔다. 대규모 예측모형 학습은 이 설계의 요건이 아니다.

## 모집단·관측 단위·분모

감사 시점에 `ACTIVE_HUBS`를 동결하고 그 범위 안에서 다음 프레임을 별도로 만든다. 현재 서빙본 밖의 과거 자료는 별도 코호트로 표시한다.

| 프레임 | 관측 단위와 식별 방법 | 포함·분모 정의 |
|---|---|---|
| 원천 객체 프레임 | 원천 종류·객체 종류·원천 ID·스냅샷의 복합 키 | 수집 범위 내 원천 행 전체. ID가 없는 행도 미식별 행으로 남긴다 |
| 결합 프레임 | 원천 객체에서 지번·폴리곤·층으로 연결한 간선 | 매칭 성공뿐 아니라 미매칭·복수 후보·실패를 포함한다. 결합 오류의 분모다 |
| 마스터 표시 프레임 | 거점·폴리곤 `id`; 별도 지번 `pnu` | Gold 표시 행 전체. 동일 지번의 여러 폴리곤은 그 자체로 중복 오류가 아니다 |
| 대표 집계 프레임 | 거점·지번, 현행 코드의 식별자 폴백도 기록 | 현행 `build_cells` 필터·도형 검사를 통과하고 중복 제거된 지번. 층·호 단위는 별도 층화한다 |
| 미표시·제외 프레임 | 원천 또는 마스터의 제외 객체와 사유 | 비상업, 분모 미확인, 비정밀 방법, 집합건물, 도형 실패 등을 사유별 기록. 포함 프레임과 합쳐 임의 평균하지 않는다 |

같은 지번이 여러 거점 경계에 포함되면 전역 객체 키와 거점 소속을 둘 다 보존한다. 전체 오류율·독립 감사에서는 같은 물리 객체를 중복 표집하지 않는다. 거점별 서빙 재현에서는 기존 소속을 유지한다. 전역 연결이 불확실한 ID 폴백은 확정 지번과 합치지 않고 `identity_unresolved`로 보고한다.

`capacity`와 `active`의 합산은 측정 단위가 같은 영역에서만 한다. 코드의 `capacity_method`만으로 단위를 단정하지 않고 실행 분기·층 속성·원천을 대조한다. `coverage.json`의 대표 집계와 실제 서빙 집계는 별도의 명칭·분모로 기록하며, 차이는 우선 정의 차이로 분류한 뒤 검증한다.

## 변수 사전

다음의 ‘신규 감사’ 필드는 제안 스키마다. 현재 API나 파일에 이미 존재한다고 주장하지 않는다. 신규 감사 레코드의 공통 키는 `audit_run_id`, `hub_slug`, `snapshot_id`, `entity_key`다.

| 변수 | 구분·형식 | 정의·원천·결측 처리 |
|---|---|---|
| `pnu`, `id` | 기존 / 문자열 | 마스터 지번·폴리곤 식별자. 원천 객체 키와 같은 의미로 취급하지 않는다. 없으면 미식별 |
| `source`, `capacity_method` | 기존 / 범주 | 마스터의 결합·분모 경로. 문자열을 보존하며 연구자가 출처를 승격하지 않는다 |
| `capacity`, `active`, `stores` | 기존 / 수치 | 마스터의 수용·활성·참고 점포 값. `active`를 항상 점포 수로 읽지 않는다. 원천 분기 확인 후 단위를 부여한다 |
| `com_floors`, `occ_floors`, `unknown_n` | 기존 / 목록·수치 | 상업층·확인 점유층·배정 상한과 하한의 차이. `unknown_n`을 원천의 층 미상 점포 수로 치환하지 않는다 |
| `vacancy_rate`, `vacancy_rate_lo`, `vacancy_rate_hi` | 기존 / 퍼센트 | 가공 공실 지표 및 층 정보에 따른 범위. 통계적 신뢰구간이나 현장 정답이 아니다 |
| `measurement_unit`, `unit_evidence` | 신규 감사 / 범주·참조 | `floor`, `unit`, `store_proxy`, `unknown`과 판정 근거. 미확인은 합산 분석에서 별도 보고 |
| `source_entity_key`, `target_entity_key`, `join_route` | 신규 감사 / 문자열·범주 | 원천→목표 연결, 직접 키·공간 귀속 등의 경로. 재구성이 불가하면 `not_observable` |
| `eligible_for_serving`, `exclusion_reasons` | 신규 감사 / 불리언·목록 | 동결 코드에 의한 집계 여부·전체 사유. 필터로 제외됐다는 이유만으로 오류 라벨을 부여하지 않는다 |
| `observed_at`, `retrieved_at`, `built_at` | 혼합 / 시각 또는 기간 | 원천 관측·수집·가공 시점을 구분. `built_at` 존재는 표본 파일에서 확인했으나 모든 자료에 보장되지 않는다. 파일 수정 시각으로 대체 금지 |
| `observation_lag`, `join_time_gap` | 신규 감사 / 시간 구간 | 기준 시점과 원천 관측 시점 차이, 결합 원천 간 차이. 분기 자료는 분기 범위로 표현하고 정확한 일자를 생성하지 않는다 |
| `rule_id`, `rule_result` | 신규 감사 / 범주 | 사전 고정한 검사별 `pass`, `fail`, `not_evaluable`, `not_applicable` |
| `review_label`, `review_reason`, `evidence_ref` | 신규 감사 / 범주·텍스트·참조 | `confirmed_error`, `confirmed_consistent`, `unresolved` 및 독립 근거. 원천 내부 일치와 현실 확인을 별도 과제로 판정 |
| `reviewer_id`, `reviewed_at`, `reference_observed_at` | 신규 감사 / 식별·시각 | 검토자, 판정 시각, 참조자료 관측 시각. 시점 불일치 시 그 과제는 미판정 |
| `stratum`, `inclusion_probability`, `sampling_weight` | 신규 감사 / 범주·수치 | 확률표집 설계와 포함확률 역수. 편의표본에는 가중치를 지어내지 않는다 |
| `input_hash`, `code_commit`, `code_diff_hash`, `config_hash`, `environment_ref` | 신규 감사 / 문자열·참조 | 스냅샷과 실행 버전. 작업 트리가 수정됐다면 커밋 ID만으로 코드 버전을 설명하지 않는다 |

## 평가 지표와 계산 규칙

아래 수식은 계획된 계산 정의이며 실측 수치가 아니다. 모든 비율에 분자·분모·제외 수·미판정 수를 함께 출력한다. 분모가 비면 `NA`와 이유를 기록한다.

| ID | 지표·정의 | 해석 제한 |
|---|---|---|
| M1 | 규칙 위반율 = 실패 수 / (통과 수 + 실패 수). 미평가율 = 평가 불가 수 / 적용 대상 수 | 검사별·단위별 산출. 여러 검사 실패를 단순 합해 객체 오류율로 쓰지 않는다 |
| M2 | 확정 오류 비율의 하한 = 가중 확인 오류 / 가중 전체 감사표본; 상한 = 가중(확인 오류 + 미판정) / 가중 전체 감사표본 | 미판정으로 인한 식별 범위이며 통계적 신뢰구간이 아니다. 확정 판정된 표본만의 오류율도 별도 제시 |
| M3 | 식별·결합 커버리지 = 해소된 객체 또는 연결 수 / 해당 원천 프레임 전체 수 | 매칭 성공은 정확한 귀속의 증거가 아니다. 미표시 자료를 분모에서 지우지 않는다 |
| M4 | 지번별 공실 지표 차이 = 분석 사본 값 − 고정 기준값; 상태 전이 = 동일 객체의 전후 상태 교차표 | 동일 단위·시점·객체에서만 계산. 원천 근거 없는 수정값은 생성하지 않는다 |
| M5 | 격리 후 잔존 커버리지 = 잔존 지번 수 / 고정 기준 지번 수; 동일 단위 영역에서만 수용량 잔존 비율도 병기 | 잔존값 평균의 변화는 대상 구성 변화가 섞인 기술통계다. 정확도 개선으로 해석하지 않는다 |
| M6 | 재실행 불일치율 = 의미 비교에서 값이 달라진 객체 수 / 동일 입력 재실행의 객체 합집합 수 | 생성시각 등 사전 지정 메타데이터만 비교에서 분리한다. ID·행 누락도 불일치로 센다 |
| M7 | 릴리스별 진입·이탈 수; 공통 식별 객체의 값 차이·출처 전이·단위 전이 | 단위가 바뀐 객체는 수치 차이를 계산하지 않고 전이로 보고한다. 변화를 오류라고 단정하지 않는다 |

전수 검사 결과는 동결된 프레임에 대한 기술통계로 보고한다. 표본 감사에서는 층별 추출률을 반영한 가중 집계와 층화 설계 기반 표준오차를 사용한다. 단순 무작위·독립 가정을 전체 데이터에 자동 적용하지 않는다. 통계 구현·신뢰수준은 본 감사 전 분석계획에 고정하고 미판정 범위와 표집 오차를 별도로 출력한다. 서울 전체 상업용 부동산으로 일반화하지 않는다.

## 평가 절차

### A. 입력과 분석계획 동결

거점 목록, 경계·반경, 기준 시점, 원천별 관측 기간, 코드·설정·환경 및 사용한 파일 경로·해시를 manifest로 고정한다. `load_latest`가 실제 선택한 날짜별 파일을 기록하며 실행 도중 최신 파일이 바뀌지 않게 한다. 로컬 존재, Git 추적 여부, 클라우드 접근 여부는 각각 확인한다. API 키는 manifest에 기록하지 않는다.

원천→중간 산출물→마스터→서빙 집계의 연결을 기록한다. 필요한 Bronze가 없으면 해당 연결의 출처 재현은 `not_evaluable`다. Gold만 있으면 Gold→서빙 재현 범위로 축소했다고 명시한다. 과거 원천이 없는데 새 API 응답을 과거 정답으로 사용하지 않는다. 전수 오류 결과를 보기 전에 검사 목록·표집·주 지표를 고정한다.

### B. 전수 구조 감사 — RQ1

아래 검사는 향후 구현할 평가 명세다. 기존에 구현·통과한 테스트 목록이 아니다.

| 검사 ID | 확인 사항 | 실패·미평가 처리 |
|---|---|---|
| `audit_identity_namespace` | 원천 종류·객체 종류별 키의 유일성, 원천→목표 관계, 미식별·다중 연결 | 지번의 정상 다동 폴리곤은 실패가 아니다. 해소 못한 연결은 의심 또는 미평가 |
| `audit_unit_consistency` | 분자·분모의 단위와 실행 분기, 층 목록·가공 공실 범위의 논리 일치 | 현재 가공식과 일치해도 현실 정확성은 미판정. 클램프 때문에 가려진 원천 모순은 원천에서 별도 검사 |
| `audit_spatial_assignment` | 좌표계·유효 도형·경계·다중 후보·직접 키와 공간 귀속의 불일치 | 단순히 폴리곤 밖이라는 이유로 확정 오귀속하지 않는다. 거리 허용치의 근거가 없으면 거리 분포만 보고 |
| `audit_temporal_lineage` | 관측·수집·가공 시점, 실제 입력 파일 버전, 결합 시점 격차 | 허용 시차는 원천 갱신 주기 근거를 본 감사 전에 고정. 없으면 임의 최신성 합격선 사용 금지 |
| `audit_serving_population` | 현행 필터, 도형 검사, 지번 중복 제거, 출력 분모와 provenance | 제외 규칙은 변경하지 않는다. 커버리지 파일과 서빙의 다른 정의는 별도 표기 |

규칙 결과는 `confirmed_error`와 다른 층위다. 확인 오류는 독립 판정과 결합해야 한다. 전수 결과를 본 후 추가한 탐색 규칙은 사후 분석으로 표시한다.

### C. 독립 표본 감사 — RQ1

표집 단위는 전역 고유 지번 또는 해소되지 않은 객체 그룹이다. 선택된 그룹 안의 관련 결합을 함께 검토하되 간선별 지표에는 해당 포함확률을 적용한다. 오류 의심 여부·집계 포함 여부·측정 단위·원천 경로·거점 소속을 이용해 서로 겹치지 않는 층을 만들고, 층 정의와 작은 층의 병합 기준을 동결한다.

각 층에서 무작위로 추출하며 난수 시드·추출 코드·프레임 해시·포함확률을 남긴다. 의심 사례뿐 아니라 검사 통과 사례도 포함한다. 의심 사례를 과대표집할 수 있으나 전체 비율은 설계 가중치로 복원한다. 별도 편의 사례는 사례 설명용으로만 사용한다.

표본 크기는 전수 프레임과 검토 가능 시간을 확인한 뒤 목표 오차폭에 맞춰 확정한다. 단순 무작위 계획의 출발식은 `n0 = z² × p × (1−p) / e²`, 유한 모집단 보정은 `n = n0 / (1 + (n0−1)/N)`이다. 사전 오류율 정보가 없으면 `p × (1−p)`의 최대값을 사용하는 보수적 계획으로 시작한다. 실제 층 배분과 미판정 예상은 별도로 반영한다. 이 식은 표본 크기가 이미 확정됐다는 뜻이 아니다. 확보량이 부족하면 달성 정밀도를 보고하며 목표를 달성했다고 쓰지 않는다.

독립 검토자 두 명이 같은 증거 묶음을 보고 먼저 따로 판정한다. 가능하면 자동 의심 라벨·제품 공실값을 숨긴다. 원천 보존본 대조는 **전사·결합 정확성**을 검증한다. **실제 점유·공실 정확성**에는 대상·층·관측 시점이 일치하는 현장 기록 또는 독립 확인 자료가 필요하다. 동시점 근거가 없으면 이 과제는 `unresolved`다. R-ONE 평균, 같은 입력에서 만든 다른 Gold 파일, 최신 거리뷰를 과거 공실 정답으로 대체하지 않는다.

초기 판정의 일치율과 라벨 교차표를 먼저 보존하고, 불일치는 근거를 재검토해 합의 사유를 기록한다. 끝내 해소되지 않으면 미판정으로 남긴다. 검토자가 확보되지 않으면 자동 검사만 보고하고 독립 감사 완료를 선언하지 않는다.

### D. 영향 분석 — RQ2

원본과 서비스 출력은 고정하고 연구용 사본에서만 분석한다.

- **기준 분석:** 현재 코드·현재 필터로 동결 입력을 재현한다.
- **확인 오류 격리:** 독립적으로 확인된 오류의 영향 객체를 분석 사본에서 제외한다. 잔존 집계값과 함께 M5를 보고한다. 오류의 수정값을 알 수 없으면 격리만 하며 값을 보완하지 않는다.
- **근거 있는 정정 비교:** 같은 시점의 독립 원천으로 수정값이 확인되는 객체만 짝지어 M4를 계산한다. 표본 밖 객체를 임의 정정하지 않는다. 감사표본만 검토했다면 ‘표본 확인 오류의 영향’으로 범위를 제한한다.
- **층 정보의 범위 분석:** 기존 `vacancy_rate_lo/hi`가 유효한 동일 단위 객체에서 그 폭과 파급 범위를 기술한다. 미상 층을 임의 배정한 정답이나 신뢰구간으로 해석하지 않는다.

자료가 없는 제외 객체는 관측 대상처럼 다시 편입하지 않는다. 기존 제외 규칙을 해제하는 실험은 이 설계에 포함하지 않는다. R-ONE과의 격차는 기존 해석을 유지한 참고 항목으로만 남기고, 격차 축소를 정확도 목적함수로 삼지 않는다. 결과가 변하지 않거나 판정 자료가 부족한 경우도 그대로 보고한다.

### E. 재현성과 릴리스 비교 — RQ3

동결 입력·코드·환경으로 분리된 연구 출력 위치에 재실행한다. 원본 Gold를 덮어쓰는 빌더는 출력 격리를 먼저 구현하기 전 실행하지 않는다. 원천 수집·유료 API 재호출은 고정 입력 재현의 일부가 아니다.

원본 바이트 해시와 의미 비교를 둘 다 수행한다. 의미 비교는 사전 지정한 정렬·숫자 직렬화·비분석 메타데이터 분리 규칙을 사용하며, 값이 다른 필드를 사후에 제외하지 않는다. 원시 입력과 중간 산출물까지 확보되면 구간별 재현하고, 일부만 확보되면 가능한 시작 계층을 명시한다.

서로 다른 릴리스가 보존된 경우에만 동일 코드·동일 거점 설정으로 비교한다. 진입·이탈·공통 객체를 분리하고, 공통 객체에서는 측정 단위·출처가 유지되는 부분만 값을 비교한다. 코드도 바뀌었다면 동일 입력에 대한 코드 차이와 동일 코드에 대한 입력 차이를 구분할 수 있는 경우에만 원인 분석을 한다. 실패한 재실행과 버전 미보존 자체도 결과다.

아래는 후속 감사에서 생성할 산출물 명세다. 이번 작업에서 생성된 파일이 아니다.

| 산출물 | 필수 내용 | 진행 조건 |
|---|---|---|
| `audit-manifest` | 코호트·원천 파일·관측기간·해시·실행 버전·이용 가능 계층 | G0: 입력 동결 가능. 불완전하면 분석 범위를 명시적으로 축소 |
| `audit-findings` | 검사 ID, 객체 키, 결과, 실패·미평가 사유, 근거 참조 | G1: 객체·단위·분모가 정의됨. 미해소 단위는 별도 영역으로 보고 |
| `audit-sample` 및 `audit-labels` | 프레임·층·포함확률·원판정·합의·독립 근거 | G2: 독립 감사 자료 확보. 미확보면 M2 및 현실 정확도 판정 유보 |

| `audit-reproduction` | 입력·코드·환경·출력 해시 및 객체별 차이 | G4: 입력 재현과 릴리스 변화가 분리됨 |
| 논문용 근거 등재안 | 각 새 수치의 분자·분모·코호트·재현 명령·산출물 해시 | G5: [근거 인덱스](evidence-index.md)에 등재된 뒤 본문 작성 |

자료의 존재와 평가 성공을 혼동하지 않는다. 자동 구조 감사만 완료된 경우 연구 주장은 출처 추적·구조 일관성·재현성으로 한정한다. 독립 현실 정답이 없는 경우 공실 정확도, 임대 가능성, 실제 입점 의사결정 개선은 주장하지 않는다.
