## 붙여 넣을 프롬프트

```
SpaceOS 건물 공실률 지표를 R-ONE 앵커와 같은 것을 재도록 정의를 고쳐줘.
원인 규명은 docs/finding-anchor-population.md 에 끝나 있다. API 콜은 0으로 가능하다.

## 확정된 사실 (다시 규명하지 말 것)
1. R-ONE 중대형 공실률 = **면적** 기준(공실면적/임대가능면적), 모집단은 **일반건축물**
   중 3층 이상 또는 연면적 330㎡ 초과, **집합상가는 별도 계열**, 전국 **표본** 5,761동
   (상권 368개 → 상권당 약 16동). 우리 지표는 호실 기준·전수·집합 포함이었다.
2. 모집단/단위를 맞추면 13거점 합 51.8% → 39.5%(호실) → 30.5%(면적가중).
   그래도 앵커(3.4~17.6%)보다 높다 → 분자 결손이 남는다.
3. 상가정보 원본에 층(flrNo)이 있다. 층별개요 층번호와 맞춰 보면
   1층 점유율이 하한 66.6% / 상한 92.1%(층 미상 30%를 빈 층에 배정), 그리고
   **점포의 22.6%가 우리 분모에 없는 층에 있다.**
4. 가로수길 1층 공실 밴드 9.1~32.8% 안에 R-ONE 신사역 17.6%가 들어온다.
   가두 실태조사 41.6%는 밴드 밖 → 앵커에서 뺀 07-28 판단이 옳았다.

## 해야 할 일
1. data/pipelines/calibrate_vacancy.py 의 primary 를 앵커 모집단에 맞춘다.
   - 집합건물(expos_units)을 대표값에서 분리한다(별도 세그먼트로 보고).
   - 일반건축물 중 표제부 주용도가 상가류(근생·판매·위락·문화)이고
     3층 이상 또는 연면적 330㎡ 초과인 건물만 중대형 앵커와 비교한다.
     (업무시설 509동·숙박 332동이 지금 섞여 있다.)
   - 소규모(2층 이하 & 330㎡ 이하)는 vac_small 과 별도로 대조한다.
   - 면적 가중값을 대표로, 호실 기준을 병기. **α 보정은 도입하지 말 것.**
   - 필요한 건물 속성(grndFlrCnt·totArea·주용도)은 bronze 대장에 이미 있다.
     data/analyze_anchor_population.py 가 스트리밍으로 뽑아 silver/anchor_pop 에
     캐시해 둔 것을 재사용하거나, gold 에 속성을 실어 파이프라인을 단순화할 것.
2. 분자를 층 단위로 바꾼다.
   - 지금은 분자 = 건물 내 점포 수(층 무관), 분모 = 지상 상업층 수라 단위가 다르고
     min(active, capacity) 클램프가 그 불일치를 덮고 있다.
   - 점포의 flrNo 로 "점포가 확인된 상업층 수"를 분자로 삼으면 단위가 맞고 클램프가
     불필요해진다. flrNo 공란 약 30%는 **상·하한 밴드**로 노출할 것(단일 값 금지).
3. 분모를 "층별개요 상업층 ∪ 점포가 확인된 지상층"으로 넓힌다.
   점포가 있는 층은 정의상 상업층인데 지금 22.6%가 분모 밖이다.
4. 재산출 후 build_page_master → calibrate_vacancy → score_labels 체인을 돌리고,
   앵커 격차·status 정확도(현재 75.0%, 표본 28동)의 변화를 보고할 것.

## 완료 기준
- calibration.json 의 대표값이 R-ONE 과 같은 모집단·단위로 산출된다.
- 층 기준 공실률이 상·하한 밴드로 나온다.
- 13거점 앵커 격차가 표로 정리되고, 남은 격차의 크기가 명시된다.

## 주의
- 집계는 건물별 min(active, capacity) 클램프 후 합산(층 단위로 바꾸면 클램프 불필요).
- 분모는 지번(pnu) 단위 dedupe.
- bronze 대장은 최대 85MB, 가용 RAM 약 2GB → json.load 금지, 스트리밍으로 읽을 것.
- PYTHONIOENCODING=utf-8. Windows + PowerShell 5.1(.ps1 은 UTF-8 BOM).
- 긴 작업은 백그라운드. 배터리 구동 시 약 7배 느려지고 덮개를 닫으면 멈춘다.
```

## 왜 이 순서인가

분자를 먼저 파면 모집단이 틀린 상태에서 커버리지를 재게 된다. 모집단·단위를 맞추는
작업은 API 콜 0에 반나절이면 끝나고, 그 뒤 남는 격차만이 진짜 미측정분이다.
로드뷰 재표본(라벨 수집)은 그 다음이며, **층화 기준은 `capacity_method` 가 아니라
분모 규모**(1~2호 / 3~10 / 11~20 / 21~50 / 51+)로 잡는다.
