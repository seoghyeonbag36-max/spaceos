# 정확도 현황과 95% 도달 가능성 — 지표마다 답이 다르다 (2026-09-15)

물음: **PlaceOS 의 현재 KPI(정확도)는 몇 %인가, 95% 로 올릴 수 있는가.**

- 방법: 저장소 산출물 실측 · 네트워크 0콜
- 기계가 읽을 값: `reports/accuracy_95_2026-09-15.json`
- 선행: `finding-sequence-and-accuracy-2026-08-17.md`(계층별 사전분포) ·
  `finding-anchor-gap-2026-09.md`(격차 원인) · `finding-expansion-direction-2026-09-15.md`

## 0. 한 줄 결론

**"정확도 몇 %"라고 답할 수 있는 값이 넷이고, 서로 다른 것을 잰다.**
그중 **95% 가 의미도 있고 달성도 가능한 것은 하나뿐**이다 — **공실 판정 정확도(현재 75%)**.
예측(LSTM)과 추천(GNN)의 95% 는 **수학적으로 상충**하거나 **표본이 허락하지 않는다**.

---

## 1. 현재 값 — 넷을 구분해 적는다

| # | 지표 | 현재 | KPI | 표본 | 성격 |
|---|---|---|---|---|---|
| ① | **LSTM 공실예측 방향 정확도** | **70.8%** (46/65) | 70% | 65 | 예측 |
| ② | GNN 업종추천 **Top-3** | **91.67%** | 70% | test 분할 | 추천 |
| ③ | GNN 업종추천 Top-1 | 64.94% | (게이트 폐기) | test 분할 | 추천 |
| ④ | **지상검증 공실 판정 정확도** | **75%** | 70% | **로드뷰 라벨 20~30건 · 1거점** | 측정 |

대외적으로 인용해 온 **"AI 정확도 70%+"는 ①의 70.8%** 다.

### 1-1. 넷 다 그대로 인용하면 안 되는 이유

**① 은 KPI 를 통계적으로 넘지 못했다.**

```
46/65 = 70.8%  ·  SE 5.6%p  ·  95% CI  59.7 ~ 81.8%
KPI 70% 와의 차 0.8%p = SE 의 0.14배
```

0.14σ 는 **70% 와 구분되지 않는다.** "목표 달성"이라 부를 수 있는 값이 아니다.

**② 는 사전분포가 이미 89.35% 인 문제다.** 리프트는 **5.3%**, macro-F1 은 **0.235** 로
사실상 다수 클래스를 맞히고 있다. 더 중요한 것 — **서빙 아티팩트는 아직 카카오 유래본**이다
(`platform_industry_recommend.json`). 09-15 에 노드 소스를 상가정보로 옮기기로 했으나
재학습은 **막혀 있다**(`DATA_GO_KR_SERVICE_KEY` 미설정 → Bronze 없음,
`reports/gnn_label_arms_2026-09-15.json`). 즉 **지금 서빙되는 91.67% 는
약관상 영구 저장이 불가한 소스에서 나온 값**이다.

**④ 가 제품이 실제로 파는 것인데, 표본이 가장 얇다.**

```
n≈25, p=75% → SE 8.7%p · 95% CI  58 ~ 92%
```

**지금 표본으로는 75% 와 95% 를 구분할 수 없다.** 게다가 66거점 중 **1거점**(garosugil)이다.

### 1-2. 그리고 지표 전체가 공식 통계와 어긋나 있다

| | 값 |
|---|---|
| 우리 대표 공실률(mid) 중앙 | **19.2%** |
| R-ONE 앵커 중앙 | **8.8%** |
| **배율** | **2.18배** |

정확도를 논하기 전에, **우리는 서울 상권 공실을 공식 통계의 2.2배로 보고하고 있다.**

## 2. 95% 도달 가능성 — 지표별 판정

### ① LSTM 방향 정확도 → **불가**

분기 공실률 변화의 **부호**를 맞히는 문제다. 현재 CI 상한이 **81.8%** 라 95% 는 구간 밖이다.
표본을 늘려도 성능이 오르는 것이 아니다 — 표본은 **주장의 정밀도**만 바꾼다.

```
95% 를 ±3%p 로 주장하려면 홀드아웃 n = 203
현재 n = 65 (거점 66 × 마지막 분기 1)
분기당 +66 → 약 0.5년치 분기 축적이 있어야 '주장'이 가능
```

→ **표본을 다 모아도 성능이 95% 가 된다는 근거는 없다.** 이 지표에 95% 를 거는 것은
   목표 설정 오류다.

### ② GNN Top-3 → **대분류 7종에서만 사정권, 그러나 입도와 상충**

08-17 실측표(`finding-sequence-and-accuracy-2026-08-17.md` §6)가 이미 정량화했다:

| 분류 체계 | 클래스 | 사전 Top-3 | 95%까지 |
|---|---|---|---|
| **대분류 7종 (현행)** | 7 | 89.7% | **+5.3%p** ← 유일한 사정권 |
| 상가정보 대분류 | 10 | 69.9% | +25.1%p |
| 상가정보 중분류 | 75 | 28.5% | +66.5%p |
| 상가정보 소분류 | 247 | 20.1% | +74.9%p |

현행 실측 91.67% → 95% 까지 **+3.33%p** 다. **닿을 수는 있다.**

**그러나 이것은 제품이 원하는 방향과 반대다.** 고객은 "음식점"이 아니라 "국수 전문점"을
묻는다. 입도를 내리는 순간 사전분포가 무너져 95% 는 **수학적으로 불가능**해진다.
→ **95% 와 실용적 입도는 동시에 못 넘는다.**

### ④ 공실 판정 정확도 → **가능. 여기가 유일한 자리다**

측정 문제이지 예측 문제가 아니다. 오차의 **출처가 귀속 가능**하고, 따라서 줄일 수 있다.

## 3. ④를 95% 로 올리는 방법 — 기전이 특정됐다

### 3-1. 실측: 점포 귀속률이 건물 규모에 따라 단조 감소한다

| 층수 | 건물 수 | 공실률 중앙 | **점포/호실** |
|---|---|---|---|
| 1층 | 13,603 | 0.0% | **1.12** |
| 2층 | 8,799 | 50.0% | 0.61 |
| 3–4층 | 15,832 | 0.0% | 0.63 |
| 5–7층 | 10,750 | 16.7% | 0.56 |
| **8층+** | 3,658 | 10.0% | **0.41** |

**귀속이 옳다면 이 열은 평평해야 한다.** 1층 1.12 ↔ 8층+ 0.41 은 **2.7배** 차이다.
1층이 1을 넘는 것은 과귀속이고, 고층이 0.41 인 것은 **분자 결손**이다.

이것이 `finding-anchor-gap-2026-09.md` §3-3 의 *"큰 건물의 분자 결손"* 의 실물이다.
그리고 R-ONE 정렬 대상의 **66.1%(25,619동)가 `mid` 세그먼트**(≥3층 또는 >330㎡),
즉 **결손이 가장 큰 구간이 정확히 앵커 비교 대상**이다.

### 3-2. ⚠ 내가 세운 가설 하나는 기각됐다 — 거점 단위로는 설명되지 않는다

"층 근거(`occ_floors`)가 부족한 거점일수록 격차가 크다"를 검사했다:

```
층근거 하위 절반(중앙 45.9%) → 격차 중앙 +9.90%p
층근거 상위 절반(중앙 62.9%) → 격차 중앙 +8.10%p
피어슨 r = −0.122
```

**상관이 거의 없다.** 격차는 **거점의 성질이 아니라 건물 규모의 성질**이다.
→ 교정 작업은 거점별이 아니라 **건물 규모별**로 설계해야 한다. (이 반증이 없었다면
   거점 단위 보정을 짜서 헛일을 했을 것이다.)

### 3-3. 단계

| 단계 | 할 일 | 통과 조건 |
|---|---|---|
| **1** | **층·호 식별 보강** — 상가정보 `flrNo` 공란 **35.8%**(그 행의 `hoNo` 는 100% 동시 공란). 내부 복원 불가라 **외부 소스**가 필요하다 | 점포/호실 열이 **규모에 걸쳐 평평**해진다(8층+ 0.41 → 1.0 대역) |
| **2** | **앵커 정합 확인** | 격차 중앙 **+8.95 → ±3%p** · \|격차\|>10%p 거점 **31 → 10 이하** |
| **3** | **지상 실측 표본 확대** | **20~30건 → 457건** (95% 를 ±2%p 로 말하기 위한 최소) · 거점 **1 → 5~8**, 격차 상·중·하위 층화 추출 |

필요 표본(p=0.95, 양측 95% CI):

| 정밀도 | 필요 n |
|---|---|
| ±10%p | 19 |
| ±5%p | 73 |
| ±3%p | 203 |
| **±2%p** | **457** |
| ±1%p | 1,825 |

→ **95% 는 모델을 고쳐서 도달하는 값이 아니라, 귀속을 고치고 표본을 갖춰 "측정"하는 값이다.**

## 4. 판정

1. **현재 인용 가능한 값은 70.8%(①)** 이고, 그조차 KPI 70% 와 **통계적으로 구분되지 않는다**.
2. **95% 를 전사 목표로 두는 것은 틀렸다** — ①은 불가, ②는 실용적 입도와 상충.
3. **95% 를 걸 자리는 ④ 공실 판정 정확도(현 75%)** 다. 기전이 특정됐고(규모별 분자 결손),
   오차가 귀속 가능하며, 이것이 **제품이 실제로 파는 값**이다.
4. 선결 조건은 정확도가 아니라 **타당성**이다 — 공식 통계의 **2.18배**를 먼저 닫아야 한다.

## 5. 하지 않을 것

1. **네 지표를 "정확도"라는 한 단어로 합쳐 말하는 것** — 대외 자료에서 91.67%(②)를
   "PlaceOS 정확도"로 인용하면 공실 판정 정확도(75%, n≈25)로 오해된다
2. **①에 하이퍼파라미터를 더 태우는 것** — `train_lstm.py` 가 이미 *"무한 튜닝 금지"* 로
   막아 둔 자리다. 병목은 모델이 아니라 표본과 문제 성질이다
3. **②의 91.67% 를 재학습 전까지 갱신된 값처럼 쓰는 것** — 서빙본은 카카오 유래본이고
   재학습은 키 미설정으로 막혀 있다
4. **표본을 안 늘린 채 95% 를 선언하는 것** — n≈25 에서는 75% 와 95% 가 구분되지 않는다
