# [실측] KPI 가 새고 있었다 — 임계값이 무정보 베이스라인 아래였다 (2026-09-16)

## 한 줄

**KPI① "AI 정확도 70%+" 는 입력을 하나도 안 보는 규칙이 이미 넘는 선이었다.** 그래서
"목표 달성" 이라는 표기에 정보가 없었고, 그 표기가 진행률·기능 문서·공모전 원고까지
그대로 흘러 있었다.

## 어떻게 드러났나

재학습 없이 **이미 커밋된 서빙 산출물만으로** 다시 셀 수 있었다. 표준 라이브러리만
쓴다 — `python scripts/kpi_baseline.py`.

`data/gold/platform_vacancy_forecast.json` 에 거점별 홀드아웃 65건의
`pred·actual·prev` 가 그대로 남아 있다. 그걸 세면:

| | 값 | |
|---|---|---|
| 모델 방향 정확도 | **70.8%** (46/65) | 문서가 "목표 70% 달성"으로 적어 온 값 |
| 실제 방향 분포 | 하락 51 · 상승 14 | 한쪽으로 크게 쏠려 있다 |
| **무정보 상수 '항상 하락'** | **78.5%** (51/65) | **모델보다 7.7%p 높다** |

즉 **모델을 통째로 들어내고 "매 분기 하락"이라고만 답해도 KPI 를 넘긴다.** 임계값을
올려도 같은 문제다 — 78.5% 위로 올리면 그건 "상수보다 낫다"를 에둘러 쓴 것이므로,
처음부터 베이스라인과의 차이를 재는 게 맞다.

같은 구멍이 GNN 에도 있다. Top-3 ≥70% 게이트인데 **거점 사전분포**(모델 없이 '이
거점에 흔한 업종 3개')만으로 **89.4%** 가 나온다. 게이트가 19.4%p 만큼 헐겁다.

## 셋 이상으로 교차 확인했다

1. **재계산** — 저장된 `direction_hit` 46/65 와 `sign(pred−prev) == sign(actual−prev)`
   재계산이 일치. 값 자체는 맞다.
2. **베이스라인 대조** — `{항상 상승, 항상 하락}` 중 좋은 쪽이 78.5%. 모델 −7.7%p.
3. **불확실성** — Wilson 95% 신뢰구간 [58.8%, 80.4%]. **목표선 70% 가 구간 안에 있다.**
   n=65 에서 0.8%p 차이로 달성/미달을 가르는 것은 표본이 허락하지 않는다.
4. **쌍대 검정** — McNemar 정확검정 b=8 · c=13 · p=0.383. "모델이 더 나쁘다"까지
   증명되지는 않는다. 증명된 것은 **"더 낫다고 말할 근거가 없다"** 쪽이다.
5. **오차 축** — 지속성(예측=직전 분기값) MAE 1.333 vs 모델 1.061 → **기술점수 +20.5%**
   (RMSE +15.4%). **여기엔 실력이 있다.** 방향 축과 답이 갈린다.
6. **GNN** — Top-3 91.7% vs 사전분포 89.4% → +2.32%p. Top-1 64.9% vs 61.7% → +3.26%p.
   양수지만 작다. off-prior(사전분포가 원리적으로 못 맞히는 자리) Top-3 은 33.8%.
7. **계측 부재** — "지도·건물 상세 로딩 3초 이내" · "API p95 <200ms" 는 저장소 전체에
   측정 코드가 **0줄**이다(`security.py` 주석 한 줄이 목표를 언급할 뿐). "유료 전환
   의향 30%+" · "NPS 30+" 도 계측기가 없다. `usage.record_access` 가 세는 것은
   `active_orgs` 하나다.
8. **절차 감사** — 아래 '학습 절차도 새고 있었다'.

## 학습 절차도 새고 있었다 (두 겹)

### ① 전처리 누수 — 표준화 통계가 홀드아웃을 포함했다

`ml/training/datasets.py` 가 `mu`·`sd`·`y_mu`·`y_sd` 를 **전체 행**에서 냈다. 분기
시계열에서 이건 미래를 보고 스케일을 맞추는 것이다. 방향 판정이 `pred − prev` 의
부호라 `y_mu` 이동이 판정을 그대로 흔든다 — 아핀 불변이 아니다.

→ **차단**: 각 거점의 마지막 2분기(val·test 타깃)를 뺀 행에서만 적합한다.

### ② 선택 누수 — 보고할 홀드아웃으로 하이퍼파라미터를 골랐다

`ml/training/train_lstm.main` 이 8개 조합을 돌려 **test 방향정확도**가 가장 좋은 것을
고르고, 게다가:

```python
if res["dir_acc"] >= 0.70:
    best = res
    break            # ← KPI 임계값이 곧 멈춤 규칙이었다
```

즉 **절차가 목표 달성을 보장하도록 짜여 있었다.** 8회 중 최댓값이라 위로 편향되고,
보고된 70.8% 는 test 가 아니라 사실상 val 값이다.

→ **차단**: 끝에서 두 번째 분기를 **val**(선택), 마지막을 **test**(보고)로 가른다.
임계값 조기중단을 없앴다. test 는 한 번만 쓴다.

⚠ **재학습은 아직 안 했다.** Gold(`data/gold/platform13/`)가 `.gitignore` 라 이
환경에 없다. 코드는 고쳤고, 산출물에 `protocol` 블록을 남기게 했다 — 블록이 없으면
옛 규약이다. `pppp_status` 의 `LSTM 학습 규약` 게이트가 이걸 0% 로 찍어 재학습이
남았음을 계속 드러낸다. Gold 가 있는 머신에서 `python -m ml.training.train_lstm`.

## 배운 규칙 (KPI 를 쓸 때)

1. **임계값 단독 금지.** 같은 표본에서 무정보 규칙이 몇 점인지 먼저 재고, 그 위에서만
   성과로 센다. 임계값은 발명하는 것이 아니라 베이스라인에서 유도한다.
2. **불확실성을 함께 쓴다.** n 과 신뢰구간 없이 "달성"이라 적지 않는다. 구간이 목표를
   품으면 그건 "구분 불가"이지 달성이 아니다.
3. **선택 지표와 보고 지표를 분리한다.** 고르는 데 쓴 표본으로 성능을 보고하지 않는다.
4. **계측기 없는 목표는 KPI 가 아니다.** 계측 배선이 0번 조건이다.
5. **두 축의 답이 갈리면 둘 다 적는다.** 방향은 실패, 오차는 성공 — 하나만 인용하면
   어느 쪽이든 거짓이 된다.
