2026-07-27 13거점 Tier1 대장 수집 완료 후 build_page_master를 재빌드했더니,

## 왜 문제인가
- 부동산원(R-ONE) 실제 상권 공실률은 통상 10~20%대다. 65%는 자릿수가 다르다.
- 특히 garosugil은 PoC 정확도 검증의 기준 거점이다. 기록상 Tier1 집계 공실률
  39.1% vs 부동산원 41.6%(오차 -2.5%p), 지상검증 정확도 75%로 PoC exit을 통과했다.
  그 garosugil이 지금 56.0%(파이프라인 출력) / 61.9%(직접 계산)로 올라갔다.
  PoC exit 기준(거시 -2.5%p)을 크게 벗어난다.
- 즉 Tier2(층수 근사) → Tier1(실제 대장) 승격으로 데이터는 정밀해졌는데
  지표는 더 틀렸다. 정밀화가 오차를 키운 구조라는 뜻이다.

## 가설 (검증할 것)
분모만 정확해지고 분자는 그대로다.
- capacity(분모) = 전유부 실제 호수 or 층별개요 기반. Tier1으로 커지고 정확해졌다.
- active(분자) = 상가정보 API로 매칭된 영업 점포 수. 특정 업종만 수록되므로
  실제 입점 업체를 구조적으로 과소집계한다.
- 결과: (1 - active/capacity)가 부풀어 오른다. Tier2 시절엔 분모도 과소(층수×2)라
  오차가 상쇄돼 우연히 맞아 보였을 가능성이 있다.

## 해야 할 일
1. 위 가설을 데이터로 검증. garosugil에서 capacity와 active의 분포를 뜯어보고,
   Tier2 시절(39.1%)과 지금(56.0%)의 차이가 분모/분자 중 어디서 왔는지 분해할 것.
   git 이력이나 bronze 스냅샷으로 Tier2 시점 값을 복원할 수 있으면 직접 비교.
2. capacity 정의가 타당한지 점검. 전유부 호수에 주거·업무 용도가 섞여 있으면
   상업 용도만 걸러야 한다(NON_CAPACITY_PURPS 필터가 충분한지).
3. active 커버리지를 정량화. 상가정보 API가 실제 입점 업체의 몇 %를 잡는지
   garosugil 지상검증 데이터와 대조해 보정계수를 구할 수 있는지 검토.
   (licensing 인허가 데이터가 이미 active 하한을 올리는 데 쓰이고 있다 —
    그걸 더 활용할 여지가 있는지)
4. 결론이 나오면 지표 정의를 고치고 13거점 재계산 → garosugil이 부동산원 41.6%에
   다시 근접하는지 확인.
