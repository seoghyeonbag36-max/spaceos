> 형제 문서: [plan-mvp-3hubs-2026-09.md](plan-mvp-3hubs-2026-09.md) (9월 미션 개발 과정)

## 0. 먼저 정한 것 — 웹페이지는 **둘**이다

디자이너 조언은 "웹사이트 하나를 만든다"를 전제로 한다. 그 전제가 우리에겐 안 맞는다.
PlaceOS 가 지금 가진 웹페이지는 **하나뿐이고, 그건 랜딩이 아니라 앱**이다.

| | **A. 랜딩** | **B. 앱** |
|---|---|---|
| 주소 | **없다 — 신규** | https://spaceos-twin.web.app |
| 보는 사람 | 투자자 · B2B 리드 · 지자체 · 디자이너 | 소상공인 · 프랜차이즈 출점팀 |
| 답하는 질문 | "PlaceOS 가 뭔데?" | "연남동 어디가 비었고, 얼마고, 어떻게 알리나" |
| 재료 | 기획안 · PRD · 일러스트 | 실측 66거점 · 네이버 지도 SDK · 4트랙 API |
| **Lovable** | **쓴다 — 여기가 적지다** | **쓰지 않는다 — 시안만 받아 이식** |

지금 `firebase.json` 은 **모든 경로(`**`)를 Cloud Run 컨테이너로 리라이트**한다.
`firebase-public/` 은 비어 있다. 즉 방문자가 도메인을 치면 곧바로 지도 대시보드가 뜬다 —
"이게 뭐 하는 서비스인지" 말하는 화면이 **구조적으로 없다.** 그게 랜딩이 필요한 이유다.

### 0-1. 왜 앱을 Lovable 로 다시 만들지 않는가

디자이너 조언("러버블에 싹 다 넣고 만들어달라고 해")은 **코드베이스가 없는 사람**에게 맞는 말이다.
우리는 반대 상황이라 그대로 따르면 손해가 크다.

| Lovable 이 다시 만들 수 없는 것 | 지금 코드의 근거 |
|---|---|
| 네이버 지도 SDK 단일 인스턴스 생명주기 | `MapHost.tsx` — 탭 전환을 언마운트가 아니라 `visibility` 로 처리해 중심·줌을 보존(217d469) |
| 지도 위 4레이어 오버레이 수거 | `MapShell.tsx` `clearOverlays()` + `overlaysRef` |
| 실측 데이터 바인딩 | 66거점 × (건물마스터 · 공실유닛 · 히트맵 4종 · 앵커 대조) |
| 백엔드 계약 | `/api/v1/{heatmap,districts,ai,marketing}` · 게이트 24개 |

⚠ 그리고 **되돌리기 어렵다**: Lovable 이 뱉은 지도 화면은 우리 좌표계·거점 목록·경계 규칙을 모른다.
"경계선은 상권 경계가 아니라 우리가 잰 범위"([screen-hub-explorer.md](screen-hub-explorer.md) §1) 같은
불변 조건은 프롬프트로 전달되지 않고, 어긴 화면은 데모에서 신뢰를 통째로 깎는다.

### 0-2. 그러면 Lovable 을 **어디에** 쓰는가 — 두 자리뿐

1. **랜딩 페이지 초안 생성** (A) — 지도가 없는 화면이라 Lovable 의 강점이 그대로 산다.
2. **앱의 디자인 소스 추출기** (B) — 화면을 **쓰지 않고**, 뽑아낸 레이아웃·타입스케일·여백 규칙·
   컴포넌트 시안만 우리 토큰으로 옮긴다. Lovable 결과물은 `design/references/lovable/` 에 캡처로 남긴다.

### 0-3. 경쟁사 소스 참조(피드백 2번)에 대해 한 줄

레이아웃·인터랙션 패턴·정보 위계를 **보고 배우는 것**은 자유다 — 그게 §3 의 레퍼런스 수집이다.
다만 배포된 JS/CSS 번들 자체는 저작권이 붙어 있어 **복사해 넣으면 라이선스 문제**가 된다.
직접 진행하신다 했으니 판단은 맡기고, 이 문서는 "구조를 보고 우리 토큰으로 다시 짠다"만 다룬다.

## 1. 실측 — 디자이너 지적은 코드에 물리적 근거가 있다

디자이너가 눈으로 본 것이 코드에서 어떻게 생겼는지. 이 표가 §7 작업 목록의 근거다.

| 디자이너 지적 | 코드 실측 (2026-09-06) | 재측정 명령 |
|---|---|---|
| "정돈이 필요함" | `design/components/` 6개(Button·Card·BottomSheet·MapMarkerPin·VacancyLegend·NaverPayButton) 중 **페이지가 import 하는 것 0개**. 토큰 `colors` 만 3개 파일에서 쓴다 | `grep -rn "@/design" src/ \| grep -v "^src/design"` |
| "여백에 규칙이 없다" | 하드코딩 hex **558** vs 토큰 `var()` **202** → 채택률 **27%**. `tokens.css` 에 **spacing 토큰 자체가 없다**(radius·shadow만 있음) | `grep -oE "#[0-9a-fA-F]{3,8}" src/pages/*.css src/components/*.css src/pages/*.tsx \| wc -l` |
| "폰트 위계가 없다" | `--font-sans: "Pretendard"` 를 선언해 두고 **`public/fonts/` 디렉터리가 없다** → 전 화면이 조용히 `system-ui` 로 떨어진다. type scale 정의 없음 | `ls apps/frontend/public/fonts` |
| "글자가 너무 많음" | `PageDashboard.tsx` **919줄** · `PlatformConsole.tsx` **805줄** · `ProgramStudio.tsx` **611줄** — 한 화면이 결론·근거·원자료를 동시에 편다 | `wc -l src/pages/*.tsx` |
| "공실을 red-dot 혹은 핀으로" | 현행 지도(`MapShell.tsx:253`)는 **4상태(full·partial·high·empty)를 전부 폴리곤으로 칠한다** → 화면이 색으로 꽉 찬다. red dot 구현은 **이미 있는데**(`PageDashboard.tsx:370`, `empty` 만 Marker) `#board` 해시로 밀려난 화면에만 남았다 | `grep -n "Polygon\|Marker" src/pages/MapShell.tsx src/pages/PageDashboard.tsx` |
| "기능별로 색깔 구분" | 토큰 색 축이 **2개뿐**(`--naver-green` · `--brand` teal). PPPP 4트랙에 대응하는 색이 없어 레일·헤더·범례가 트랙을 색으로 말하지 못한다 | `head -30 src/styles/tokens.css` |
| "코드가 에러 나고 무거워진다" | 메인 번들 **247KB**(지도 SDK 제외, 코드 스플릿 후). 3D 제거로 832KB→4KB 는 이미 처리됨(2026-09-05) | `ls -la apps/frontend/dist/assets/*.js` |

**추가로 드러난 것 — `tailwind.config.ts` 는 죽은 설정이다.**
파일은 있고 토큰과 1:1 매핑까지 적혀 있는데, `tailwindcss` 가 **설치돼 있지 않고**
`@tailwind` 지시문도 **0개**다. 파일 첫 줄이 `// TODO: tailwindcss 설치 후 활성화` 다.
→ 처리 방침은 §7-0.

## 3. D0 — 재료 정리 (0.5일)

**AI 에게 기획안을 시키기 전에, 내 머릿속에 있는 걸 먼저 꺼낸다.** 이걸 건너뛰면
AI 가 일반론(“상권 분석 플랫폼”)을 쓰고, 그 일반론이 PRD·디자인까지 그대로 흘러간다.

### 이미 있는 재료 — 다시 만들지 않는다

| 재료 | 위치 |
|---|---|
| PPPP 4P 대응표 (정본) | `CLAUDE.md` §PPPP Framework |
| 화면설계서 양식 + 불변 조건 2개 | [prompt-ux-screen-spec.md](prompt-ux-screen-spec.md) |
| 완성된 화면설계서 실례 | [screen-hub-explorer.md](screen-hub-explorer.md) |
| 디자인 토큰·네이버 호환 규칙 | [feature-design-system.md](feature-design-system.md) |
| 트랙별 기능 근거 | `feature-{platform,page,posting,program}.md` |

### 새로 그릴 것 하나 — **여정 지도(Journey Map)**

디자이너가 말한 "고객의 창업 아이템에 맞게 결정되면 4P 플로우가 정해진다"가 여기 대응한다.
지금 앱은 4트랙이 **탭으로 병렬**이라 순서가 없다. 순서를 먼저 종이에 정한다.

```
김민수(34) · 카페 창업 희망 · 예산 1.5억 · 연남동 선호
  ↓ 묻는 것: "연남동에서 카페 해도 되나?"
① Platform  이 상권은 어떤 플랫폼인가        → 연남동 = 골목 트렌드 · 20~30대 · 주말 피크
② Page      어디가 비었나                    → 실측 공실 12.5% · 노출 1,133동 · 공실 유닛 N개
③ Posting   그 자리 얼마고 몇 개월에 회수되나 → 3-Tier(고급화/가성비/기능중심) 회수기간
④ Program   어떻게 알리나                    → 온라인(퍼포먼스) / 오프라인(상권활성화)
  ↓ 얻는 것: 후보 3자리 + 각각의 회수기간 + 홍보안 1장
```

산출: `design/planning/00-idea-map.md` — 위 여정을 페르소나 **3개**(소상공인 · 프랜차이즈
출점팀 · 지자체)로 각각 적는다. 마인드맵 도구를 쓸 거면 캡처를 같이 넣는다.

## 4. D1 — 기획안 (.docx, 1~2일)

### 4-1. 규칙

- **한글 폰트 임베딩 필수.** 폰트명만 지정하면 프리뷰에서 □ 로 깨진다 → `memory/context/docx-korean-fonts.md`
- **docx 로 받는 이유**는 편집 때문이다(디자이너 조언). PDF 로 받으면 고칠 때 처음부터 다시 시킨다.
- 숫자는 **실측만** 쓴다. 아래 표를 프롬프트에 그대로 박아 넣어 AI 가 지어내지 못하게 한다.

### 4-2. 프롬프트에 박아 넣을 실측 (2026-09-06)

```
거점 66곳 전부 Tier1(건축물대장 실측)
연남동  노출 1,133동 · 대표공실 12.5% · 앵커(R-ONE) 5.0%  · 격차 +7.5%p
신촌·이대 노출 1,443동 · 대표공실 17.2% · 앵커 11.68% · 격차 +5.52%p
홍대     노출 1,325동 · 대표공실 15.0% · 앵커 8.1%  · 격차 +6.9%p
공실 유닛 인벤토리 66/66거점 · 664유닛
히트맵 4레이어(공실·임대·유동·밀도)가 같은 100m 격자 위에 선다
업종추천 Top-3 91.7% (단, 거점 사전분포 89.3% → Top-1 lift 5.3%)
```
재측정: `python scripts/chain_status.py` · `python scripts/pppp_status.py`

⚠ **격차 +5.5~+7.5%p 를 숨기지 않는다.** 우리는 전수 실측이고 R-ONE 앵커는 중대형 표본이라
다른 수를 재는 게 정상이다. 기획안이 이 차이를 먼저 말해야 데모에서 무너지지 않는다
([plan-mvp-3hubs-2026-09.md](plan-mvp-3hubs-2026-09.md) §M2).

### 4-3. 붙여넣을 프롬프트 (부록 A 에 전문)

핵심만: 역할(PlaceOS 창업자) → 배경(§4-2 실측) → 독자(투자자/B2B/지자체 셋 중 하나 지정) →
목차 강제(문제·해법·PPPP·실측근거·비즈니스모델·로드맵) → **출력 형식 .docx, 한글 폰트 임베딩** →
금지(실측 표 밖의 숫자 생성 금지, "AI 기반" 같은 공허한 수식 금지).

## 5. D2 — PRD (2일)

기획안이 "왜"라면 PRD 는 **"어떤 화면이 어떤 데이터로 무엇을 답하는가"**다.

### 5-1. PRD 도 둘로 나눈다

| | `docs/prd-landing.md` | `docs/prd-app.md` |
|---|---|---|
| 대상 | Lovable 에 넣을 것 | 우리가 직접 구현할 것 |
| 담는 것 | 섹션 순서 · 카피 · 일러스트 슬롯 · CTA | 화면별 레이아웃 · 상태 · 데이터 바인딩 · 통과 조건 |
| 양식 | 자유 | **[prompt-ux-screen-spec.md](prompt-ux-screen-spec.md) §3 을 통째로 복사** |

⚠ **앱 PRD 는 양식을 재발명하지 않는다.** 이미 불변 조건 2개(중앙은 네이버 지도 전체화면 고정 ·
지도 인스턴스는 앱 수명 동안 하나)가 박힌 양식이 있고, [screen-hub-explorer.md](screen-hub-explorer.md)
가 그 양식으로 완성된 실례다. 새 양식을 만들면 그 불변 조건이 조용히 빠진다.

### 5-2. 앱 PRD 가 반드시 담아야 할 것 — 디자이너 피드백에서 나온 3개

1. **타입 스케일 5단** — 지금 없다. 예: 28/20/15/13/11px, 본문 15px·줄간격 1.5(한글 가독성 규칙)
2. **여백 그리드** — 4px 배수. `--sp-1`~`--sp-8` 토큰으로 정의
3. **4트랙 색 축** — Platform/Page/Posting/Program 각각의 색. 단 §5-3 제약을 지킨다

### 5-3. 색을 정할 때의 제약 (어기면 네이버 연동 규칙 위반)

- `#03C75A` 네이버 그린은 **네이버 연동 맥락에만**(길찾기·네이버페이). 트랙 색으로 쓰지 않는다
- `#0EA5B7` brand teal 은 PlaceOS 고유 기능. 이걸 4트랙 중 하나에 배정하면 나머지 셋이 종속돼 보인다
- → **권고: teal 을 앱 전체의 주색으로 두고, 4트랙은 채도 낮은 보조 색 4개**로 구분한다.
  대비는 WCAG AA 를 넘겨야 한다 → `feature-design-system.md` §2

## 6. D3 — 디자인 재료 (1~2일)

### 6-1. 핀터레스트 — 키워드와 "무엇을 가져올지"

이미지를 모으는 게 목적이 아니라 **레이아웃 규칙을 뽑는 게** 목적이다. 캡처마다 한 줄을 붙인다.

| 검색 키워드 | 가져올 것 |
|---|---|
| `real estate dashboard UI` `property analytics dashboard` | 지도 + 사이드패널 비율, 필터 배치 |
| `map dashboard dark UI` `geospatial dashboard` | 지도 위 오버레이 카드의 여백·그림자 |
| `vacant building` `empty storefront korea` | 랜딩 히어로 이미지 톤 |
| `data storytelling landing page` | 실측 수치를 랜딩에서 보여주는 방식 |
| `korean fintech app UI` `toss ui` `당근 UI` | 한글 타이포 위계·바텀시트 패턴 |
| `isometric city illustration` | 일러스트 스타일 통일 기준 |

저장: `design/references/<주제>/` + `design/references/INDEX.md` 에 "출처 URL · 가져올 것" 표.
⚠ 핀터레스트 이미지는 **참조용이다.** 최종 산출물에 직접 넣지 않는다(저작권). 구조만 가져온다.

### 6-2. 일러스트 생성 — 프롬프트에 토큰 색을 박는다

색을 지정하지 않으면 생성물마다 색이 달라 화면이 더 어지러워진다.

```
아이소메트릭 일러스트, 한국 도심 상가 건물, 3~5층, 1층은 영업 중 2~3층은 비어 있음.
색: 배경 #F4F7FB, 선 #1C2533, 강조 #0EA5B7(빈 층 표시).
평면적·미니멀, 그림자 없음, 배경 투명 PNG, 텍스트 없음.
```
저장: `design/assets/illustration/` · 형식 SVG 우선(확대해도 안 깨짐), 없으면 투명 PNG.

⚠ **생성 일러스트를 앱 안에 넣지 않는다.** 앱은 실측 데이터를 보여주는 화면이라
장식 일러스트가 들어가면 "이 그림도 데이터인가?" 하는 오해가 생긴다. 랜딩 전용이다.

## 7. D5 — 앱 디자인 고도화 ★ 본체 (5~8일)

디자이너 피드백 7개를 코드 작업으로 번역한 표다. **순서가 중요하다** — 토큰이 먼저 서야
컴포넌트가 그 위에 서고, 컴포넌트가 서야 화면 정리가 반복 작업이 되지 않는다.

### 7-0. 선행 결정 — Tailwind 를 지운다

`tailwind.config.ts` 는 설치되지 않은 라이브러리의 설정이다(§1). 두 체계를 다 들고 가면
"색을 어디서 고치지?"가 매번 생긴다. **CSS 변수 하나로 단일화**한다 — 근거:
① `var()` 가 이미 202곳에 서 있다 ② 지도 오버레이는 SDK 가 인라인 스타일로 그려서
유틸리티 클래스가 닿지 않는다(`MapShell.tsx` 의 `fillColor` 는 JS 값이다).

작업: `tailwind.config.ts` 삭제 → `feature-design-system.md` §1·§4 와
`.claude/skills/design/SKILL.md` 의 3중 동기화 규칙을 **`tokens.json ⇄ tokens.ts ⇄ tokens.css`** 로 고친다.

### 7-1. 작업 7개
