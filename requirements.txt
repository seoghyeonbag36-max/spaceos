# Vercel Python 서버리스 함수(api/index.py) 의존성 — 배포용 최소 셋.
# 로컬 개발 전체 의존성은 apps/backend/requirements.txt (DB/Redis/Celery 포함) 사용.
#
# ⚠ 2026-08-27 — "sqlalchemy 는 기동 시 import 되지 않는다"가 **더 이상 참이 아니다.**
#   계정층 배선(2026-08-26 23:04, 커밋 1979bb4)이 `api/v1/router.py` 에 `auth` 를 무조건
#   import 하게 만들었고, auth → core.security 가 sqlalchemy·bcrypt·jwt 를, 스키마의
#   EmailStr 이 email-validator 를 부른다. 그 넷이 여기 없어서 **프로덕션 함수가 import
#   단계에서 죽었다**(FUNCTION_INVOCATION_FAILED). 프론트 정적 파일은 그대로 떠서
#   화면은 멀쩡해 보였고, /api/* 만 전부 500 이었다 — 약 18시간 동안 아무도 몰랐다.
#   ⚠ 이 주석을 지우지 말고, 여기 목록을 줄일 때는 `app/` 의 import 를 실제로 따라갈 것.
#      재발 방지 가드: .github/workflows/ci.yml 의 `서버리스 임포트` 잡이 이 파일만으로
#      `api/index.py` 를 import 해 본다. 의존성이 빠지면 CI 에서 먼저 터진다.
#
#   버전은 **apps/backend/requirements.txt 와 똑같이 핀한다.** 배포가 테스트와 다른
#   버전을 쓰면 그 차이 자체가 다음 함정이 된다. 넷 다 Python 3.14 에서 설치된다
#   (2026-08-27 PyPI 확인: bcrypt 4.2.0 은 cp37-abi3 휠이라 3.14 포함 전 버전 호환,
#   나머지 셋은 py3-none-any 순수 파이썬 휠. SQLAlchemy 는 C 확장 없이 순수 파이썬으로
#   떨어지지만 배포에는 DB 트래픽이 없어 문제되지 않는다).
# redis/celery 는 여전히 import 되지 않으므로 제외한다.
# anthropic 은 LLM_API_KEY 설정 시에만 지연 import 되지만, 미설치면 그 import 가
# 실패하고 예외가 폴백에 삼켜져 **키를 넣어도 조용히 규칙 기반으로 떨어진다.**
# Program LLM 생성을 배포에서 쓰려면 설치돼 있어야 한다 → 2026-08-06 주석 해제.
# cp314 확인(2026-08-06): 의존 트리 전체가 Python 3.14 바이너리 휠로 해결된다.
#   컴파일 확장은 jiter(0.16.0)·pydantic-core(2.46.4) 둘뿐이고 둘 다 cp314
#   manylinux2014 휠이 있다. 전체 4.7MB — 서버리스 상한에 영향 없다.
#   ⚠ 버전을 올릴 때 이 확인을 다시 할 것 (휠이 없으면 소스 빌드 → 빌드 실패).
# 버전 하한: Vercel 빌드가 Python 3.14 를 쓰므로 cp314 휠이 있는 pydantic 2.12+ 필수
# (2.9.x 는 소스 빌드 시도 → PyO3 3.14 미지원으로 빌드 실패). fastapi 0.119+ 가 pydantic 2.12 호환.
fastapi>=0.119,<1
pydantic>=2.12,<3
pydantic-settings>=2.8,<3
anthropic==0.117.0
