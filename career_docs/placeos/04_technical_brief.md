# PlaceOS 기술 요약

채용 검토 및 연구 준비 참고자료 · 2026-09-25

## 목적과 시스템 구조

PlaceOS는 공간·상권 데이터를 입지 및 공간 활용 검토에 연결하는 프로젝트다. React·TypeScript·Vite 화면과 FastAPI API가 있으며 지도는 네이버 지도 SDK와 연결된다. 화면 API 호출은 공통 모듈을 거친다. 이번 검토에서 확인한 주요 서빙 경로는 가공한 JSON·GeoJSON 등 로컬 산출물을 읽는다. PostgreSQL·Redis 등의 설정이 존재한다는 사실을 실제 운영 검증으로 해석하지 않는다.

```text
공공·외부 자료
  → Bronze 원자료 → Silver 정제 → Gold 분석·서빙 산출물
  → FastAPI 조회·계산 서비스 → React 화면과 네이버 지도 연계

Gold 시계열·점포 그래프 → LSTM·GNN 학습 코드
  → 배치 예측·추천 JSON → API에서 읽어 제공

상권 근거와 사용자 입력 → 프로그램 생성
  → LLM 경로 또는 규칙 기반 폴백과 출처 표시
```

위 도식은 코드에서 확인한 흐름을 요약한 것이며, 모든 경로의 운영·배포·외부 호출이 이번에 실행되었다는 뜻은 아니다. 실시간 물리 상태 동기화와 도시 시뮬레이션을 검증하지 않았으므로, 채용 문서에서는 '디지털 트윈 완성'보다 '공간 데이터 기반 의사결정 지원 프로젝트'로 표현한다.

## 데이터와 공간 단위

| 자료 | 처리·활용 | 해석상 주의 |
|---|---|---|
| 상가정보·건축물대장·건물 도형 | 건물·지번 결합, 공급 규모와 영업 점포 집계 | 도형·지번·호실·점포는 다른 단위다. |
| 인허가 이력 | 영업·폐업 이력을 지번에 연결 | 지번에 여러 동이 있으면 개별 동의 이력으로 단정하지 않는다. |
| 상권 분기 통계·R-ONE | 시계열 특성과 참조 지표 | 집계 모집단·관측시점이 다르며 개별 점포 정답이 아니다. |
| 생활인구 등 유동 지표 | 수요 관련 입력과 상권 설명 | 지역 집계값을 점포 방문자나 실매출로 해석하지 않는다. |
| 블로그 등 텍스트 | 콘텐츠 문맥 입력 후보 | 구역별 감성 측정은 미확보 상태다. |

GeoJSON 좌표와 인허가 자료의 좌표 체계는 동일하다고 가정할 수 없다. 소스에 좌표 변환과 보정 경로가 있으며, 지도 집계는 위·경도 간격의 셀을 사용한다. '100m'라는 코드 설명만으로 모든 위치의 셀 면적이 정확히 동일하다고 주장하지 않는다.

대표 공실 관련 지표는 적격 지번별 capacity와 active를 집계해 `(capacity - active) / capacity × 100`으로 계산한다. 코드에는 active 상한 처리와 집계 제외 규칙이 있다. 이 계산이 현실의 빈 호실을 직접 관찰한 결과라는 뜻은 아니다. 현재 제품의 출처 필드와 집계 규칙은 그대로 보존했다.

## 분석과 AI의 구분

공간 분석은 객체 결합과 지번 중복 제거, 셀·행정동 집계에 해당한다. 가격대 시나리오는 비용·회수기간을 비교하는 규칙이다. GNN 추천과 LSTM 예측은 학습 코드가 있으며, 백엔드에서는 이미 생성된 결과 파일을 제공하는 경로를 확인했다. LLM은 근거와 사용자 입력을 문장·프로그램 형태로 구성하는 별도 경로다.

LSTM 데이터셋의 목표는 폐업률·개업률·점포수 변화 등으로 구성한 공실 대리변수다. 개별 공실 여부의 현장 정답이 아니다. GNN의 점포 업종 예측은 최적 입점 업종과 사업 성공률을 검증한 결과가 아니다. LLM 생성문도 추천의 정확성을 독립적으로 증명하지 않는다.

## 검증 상태

2026-09-25 로컬 조사에서 현재 설정의 대상 거점은 81개였고, 81개 모두 공실 집계 서비스의 `gold` 경로를 사용했다. 셀별 capacity·vac_n 합과 전체 합을 대조했으며 불일치는 없었다. 이는 소스 유형과 계산 일관성 확인이지 현장 공실 정확도의 검증이 아니다.

지번 중복, 근거가 약한 도형의 집계 제외, 이력 부재 시 빈 응답, 공유 지번의 이력 표시 등을 포함한 선택 테스트 6개가 통과했다. 상태 스크립트 두 개도 정상 종료했다. 전체 테스트·부하 테스트를 통과했다는 의미는 아니다. 실행 기준 코드는 `ef31a059f962eab5ae922f7d722b8ef9dc435bfc`다.

현재 시계열 파일을 직접 읽은 결과 81개 거점, 22개 분기, 1,782행이며 범위는 2021년 1분기부터 2026년 2분기다. 거점·분기 키 중복은 없고 `vac_small`, `vac_mid`, `rent_small`에는 각각 18개 결측이 있다. 행 수는 독립 표본 수나 실제 공실 정답 수가 아니다.

이번에는 ML 재학습, 원천 API 수집, 유료 LLM 실호출, 배포 확인, 브라우저 화면 확인을 수행하지 않았다. 기존 모델·감사 결과는 존재하지만 이번 실행 성과로 합산하지 않는다. 원자료·상세 주소·점포 식별자·인증정보는 패키지에 넣지 않았다.

## 유지보수와 검토 포인트

자료 갱신은 수집·가공 파이프라인과 정적 산출물 로더에 의존한다. 일부 로더는 메모리 캐시나 파일 변경 시각을 사용한다. 캐시 유효시간은 원천 관측의 갱신주기와 다르며 실시간성을 뜻하지 않는다. 수집일·가공일·현실 관측일을 분리해야 한다.

운영 검토에서는 데이터 누락 시 표시, 출처 보존, 집계 단위, 환경별 파일 포함 여부를 먼저 확인할 수 있다. 응답 속도나 정확도가 좋아졌다고 주장하려면 동일 입력·환경과 비교 기준을 갖춘 별도 측정이 필요하다. 구체적인 지원 직무와 연결할 때는 공고의 실제 업무 범위를 우선한다.

현재 제품명은 PlaceOS다. 저장소 테스트 설정에는 SPACEOS 접두사를 개명 전 호환 이름으로 남겼다는 기록이 있고 폴더명에도 spaceos가 남아 있다. 이를 별도 제품·사업체 관계로 설명할 근거는 없다.
