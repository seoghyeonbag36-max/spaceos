# M1 기준 시나리오 — 김민수 · 연남동 (검증 가능판, 2026-09-07)

D0 의 여정 지도([docs/ux-persona-journey-2026-09-07.md](../../docs/ux-persona-journey-2026-09-07.md))를
**손으로 따라가며 통과/실패를 판정할 수 있는 형태**로 바꾼 문서다. 여정 지도는 "이 사람이
무엇을 느끼나"를 적었고, 여기서는 **조작 → 화면 → 실패 판정 → 다음 칸으로 가는 길** 넷만 적는다.

- **기준 인물**: 소상공인 김민수(34) · 카페 창업 · 예산 1.5억 · 연남동
- **목표**: 앱을 처음 열어 **5분 안에** 넷을 얻는다. 도움말·설명·안내 없이.
  ① 연남동은 어떤 상권인가 ② 어디가 비었나(건물·층) ③ 그 자리 얼마고 몇 개월에 회수되나 ④ 어떻게 알리나
- **무대**: 좌측 레일 탭 **6개뿐** — 서울 · 거점 · Platform · Page · Posting · Program.
  이 문서는 **없는 기능을 전제하지 않는다.** 화면에 길이 없으면 "없다"고 적고 §4 에 만들 것으로 넘긴다.
- **검증 거점 3곳**: `yeonnam` · `sinchon` · `hongdae` (C6 는 셋에서 같은 조작이 같은 자리인지를 센다)

> 판정 규칙: 한 단계라도 **실패 판정 조건에 걸리면 그 단계에서 시나리오는 끝난다.**
> 뒤로가기·새로고침·URL 직접 입력으로 살려낸 완주는 완주가 아니다(C1).

---

## 1. 6단계 — 조작 · 화면 · 실패 · 다음 길

각 단계의 4줄은 순서가 고정이다.
**① 조작**(사용자가 하는 것) · **② 화면**(그 순간 떠야 하는 것) · **③ 실패 판정**(이러면 실패) ·
**④ 다음 길**(다음 단계로 가는 길이 화면에 있는가 — 없으면 무엇을 만들어야 하나).

### S0 · 앱 열기 — 첫 화면 (탭: 서울)

| | |
|---|---|
| **① 조작** | 주소를 열기만 한다 (`App.tsx` 초기 view 는 `seoul`, 아무것도 안 눌러도 여기가 뜬다) |
| **② 화면** | 「서울 25개 자치구 진입 로드맵」 + Phase KPI 4장 + 구 카드 25장. 김민수가 찾는 **연남동은 이 화면에 한 번도 나오지 않는다**(마포구 카드의 `hot` 문구에만 섞인다) |
| **③ 실패 판정** | 앱 로드 후 **10초 안에 김민수가 스스로 다음 탭을 누르지 못하면 실패.** 「연남동」이라는 글자도, 눌러서 상권으로 내려가는 카드도 이 화면에 없다 — 첫 화면이 답이 아니라 **회사 로드맵**이다 |
| **④ 다음 길** | **없다.** 구 카드는 클릭 불가(`SeoulDashboard.tsx` 는 `onClick` 이 없고 각주가 "거점별 심층은 …연결 예정"이라고 적는다). → **만들 것 ①**: 구 카드 클릭 → 그 구의 거점 목록(거점 탭 `#hub=`)으로. 최소안은 카드에 「거점 N곳 보기」 한 줄 |

### S1 · 연남동 찾기 — ② 의 앞단, "우리가 잰 범위" (탭: 거점)

| | |
|---|---|
| **① 조작** | 레일 「거점」 클릭 → 좌측 목록 검색창에 `연남` 입력 → 결과 카드 클릭 |
| **② 화면** | 지도가 연남동으로 날아가 **실측 셀 외곽선**이 그려지고, 우측 요약에 `거점 대표 공실률 + 실측(Gold) 배지 · 공실 호실/점포 · 집계 건물/정밀도 · 분모 커버리지 41.7% · R-ONE 앵커 대조(±%p) · 다음 분기 예측(LSTM)` 이 한 판에 뜬다 |
| **③ 실패 판정** | (a) 클릭 후 **3초 안에 경계선+요약이 안 뜨면 실패**(C4). (b) 요약에 `대표값 미제공` 또는 `실측 없음` 이 뜨면 이 거점은 시나리오 자격 미달 — 3거점(`yeonnam·sinchon·hongdae`)에서는 셋 다 값이 있어야 한다. (c) 배지·앵커 없이 공실률 숫자만 뜨면 C5 실패 |
| **④ 다음 길** | **없다.** 요약 어디에도 "이 거점을 Platform/Page/Posting 에서 이어 보기" 버튼이 없다. 게다가 여기서 고른 `#hub=yeonnam` 은 **다른 네 탭이 읽지 않는다**(네 탭 모두 `DEFAULT_DISTRICT = "garosugil"` 로 각자 시작한다). → **만들 것 ②(최우선)**: 거점 선택을 앱 하나의 상태로 올리고 `#hub=` 를 네 탭이 공유한다. 요약 하단에 「이 거점으로 Platform ▸」 한 줄 |

### S2 · ① 연남동은 어떤 상권인가 (탭: Platform)

| | |
|---|---|
| **① 조작** | 레일 「Platform」 클릭 → **상권 select 를 다시 열어 「연남동 · 마포구」를 고른다**(S1 선택이 따라오지 않으므로 이 재선택은 지금은 필수 조작이다) |
| **② 화면** | 스크롤 없이 `Verdict` 한 판 — 질문(“이 입지·상권은 어떤 플랫폼인가”) → 결론 한 문장(형태: `연남동 — 「<유형>」 플랫폼이다 (<최대 군> <점유%> 최대 군 · 점포 <N>곳)` — 값은 화면이 계산한 그대로) → 근거 3줄(무엇이 모여 있나 / 누가·언제 오나 / 밖에서 뭐라고 불리나) → **출처 줄**(TRDAR · 네이버 블로그·데이터랩 · LSTM · GNN · R-ONE) |
| **③ 실패 판정** | (a) 탭 진입 후 **3초 안에 결론 한 문장이 안 뜨면 실패**(그 자리에 `상권 정체성을 불러오는 중이다` 가 남아 있으면 실패). (b) 결론이 `유형을 판정하지 않는다` 로 뜨면 실패. (c) 결론+근거 3줄이 **한 화면을 넘어가면 C2 실패**. (d) 첫 화면에 `vac_proxy`·`MAE` 같은 모델 지표가 보이면 실패 — 모델 근거는 `Fold` 안에 있어야 한다 |
| **④ 다음 길** | **부분적으로 있다.** 접힌 「자리 제안(openings)」이 빈 자리마다 GNN 추천을 주지만, 그 자리를 **지도에서 보거나 Posting 으로 넘기는 링크가 없다.** → **만들 것 ③**: 자리 카드에 「지도에서 보기(Page)」·「이 자리 계산(Posting)」 두 버튼. 지금은 사용자가 레일을 눌러 스스로 건너뛰어야 한다 |

### S3 · ② 어디가 비었나 — 건물·층 (탭: Page)

| | |
|---|---|
| **① 조작** | 레일 「Page」 클릭 → 상단 상권 select 에서 **연남동을 또 고른다** → 레이어는 기본 `공실` → 지도를 당겨(줌 > 15) 폴리곤이 뜨면 붉은 건물 하나 클릭 → 좌측 상세의 **「층별 공실 · 거리뷰 보기」** 클릭 |
| **② 화면** | 지도 위 건물 폴리곤 4색(만실·부분공실·고공실·공실의심) + 좌측 `연남동 · 건물 공실 · N동 · 실측(추정) · 거점 x.x% · 앵커 ±%p`, 건물 상세에 `공실률(추정) · 상가 수용/영업 · 대표 업종 · GNN 이 자리 업종 추천`, 모달에 **2D 층 스택 + 네이버 거리뷰** |
| **③ 실패 판정** | (a) **지도 초기 렌더 3초 초과 시 실패**(C4 · KPI①). (b) 좌측 패널 배지가 `샘플(추정)` 로 뜨면 실패 — 백엔드가 안 붙어 `LOCAL_BUILDINGS` 8동(가로수길 더미)을 그리고 있다는 뜻이다. (c) 멀리서 화면이 색으로 꽉 차 "어디가 비었나"가 안 읽히면 실패(줌 ≤ 15 에서는 공실의심만 점으로 찍혀야 한다). (d) 콘솔 에러·pageerror 1건이라도 나면 실패(C3) |
| **④ 다음 길** | **없다 — 그리고 여기가 시나리오의 끊긴 자리다.** 층 스택에서 본 그 층을 Posting 으로 넘길 길이 없고, 애초에 **층별 공실 매물 목록(296건 · `floor-vacancies`)은 6개 탭 어디에도 없다**(`PageDashboard.tsx` = `#board` 해시에만 산다). → **만들 것 ④**: 층별 매물 목록을 Page 탭 안으로 들이고, 매물 카드에 「이 자리 계산(Posting)」을 단다 |

### S4 · ③ 그 자리 얼마고 몇 개월에 회수되나 (탭: Posting)

| | |
|---|---|
| **① 조작** | 레일 「Posting」 클릭 → 상권 select 에서 **연남동을 세 번째로 고른다** → 자리 select(실측 12곳)에서 한 자리 → 업종에 `카페` (또는 GNN 추천 칩 클릭) → 권리금 `3000` 입력 → 「시뮬레이션」 |
| **② 화면** | 3-Tier 카드 3장(고급화·가성비·기능중심)에 `초기 투자 · 월 비용 · 월 매출 · 월 순익 · 회수기간 N개월`, 그 위에 **입력 출처 배지 4개**(`면적 대장 실측 · 임대료 R-ONE 실측 · 권리금 기업 입력 · 유동 실측`)와 `내부 3-Tier 폴백 / 코파일럿` 배지 |
| **③ 실패 판정** | (a) 「시뮬레이션」 후 **3초 안에 세 카드가 안 뜨면 실패.** (b) 세 tier 가 전부 `회수 불가` 로 나오면 시나리오 실패(김민수는 여기서 앱을 닫는다) — 단 그때도 `unviable_note` 는 반드시 떠 있어야 한다. (c) 출처 배지가 하나라도 안 붙으면 C5 실패. (d) **S3 에서 본 그 건물·그 층이 자리 select 에 없으면 실패** — 지금은 `vacant_units` 12곳과 `vacant_floor_units` 296곳이 다른 인벤토리라 **거의 항상 실패한다** |
| **④ 다음 길** | **없다.** 계산 결과에서 Program 으로 가는 길이 없다. → **만들 것 ⑤**: 결과 카드 하단에 「이 자리로 홍보안 만들기(Program)」 — 누르면 거점·업종이 채워진 채 Program 이 열린다 |

### S5 · ④ 어떻게 알리나 (탭: Program)

| | |
|---|---|
| **① 조작** | 레일 「Program」 클릭 → 가게명·카테고리(`카페`)·거점(연남동)을 **손으로 넣고** → 리뷰 칸은 비운 채 생성 |
| **② 화면** | `Verdict` 결론 한 문장 + 근거 3줄, 그리고 온라인/오프라인 콘텐츠에 각각 **근거 한 줄**. 근거가 비면 화면이 "리뷰·사진·메뉴가 모두 비면 가게 특성이 빠진 일반론이 나온다"고 **먼저 말해야** 한다 |
| **③ 실패 판정** | (a) 근거 없이도 그럴듯한 문장이 나오고 **그것이 일반론이라는 표시가 없으면 실패**(C5 — 창업 前이라 리뷰·사진·메뉴가 전부 빈칸인 것이 이 페르소나의 정상 상태다). (b) 생성이 **20초를 넘기면 실패**(LLM 호출이라 3초 기준을 적용하지 않되, 경과 시간이 화면에 보여야 한다). (c) 거점 select 가 `— 결합 안 함 —` 인 채로 돌면 상권 컨텍스트 없는 결과이므로 그 사실이 화면에 없으면 실패 |
| **④ 다음 길** | **끝점이다.** 다만 김민수는 아직 가게가 없어 넣을 근거가 0 이다 → **만들 것 ⑥**: 「창업 前 모드」 — 가게 대신 **자리(unit)+업종**으로 돌려, 그 상권의 공개 근거(TRDAR 수요 시간대·블로그 키워드·행사)로 오픈 전 홍보안을 낸다. 지금 화면은 가게 1곳 단위 입력만 받는다 |

## 2. 통과 조건 6개를 단계에 배분한다

| | 통과 조건 | 이 조건을 **판정하는 단계** | 그 단계에서 재는 것 (측정법) |
|---|---|---|---|
| **C1** | 뒤로가기 없이 완주 | **S0→S5 전 구간** (특히 S0·S1 이음매) | 브라우저 뒤로가기·새로고침·주소 직접 입력 **0회**로 S5 까지 간다. 현재 S0 에 다음 길이 없고 S1 의 선택이 안 이어지므로 **레일 재클릭 5회 + 상권 재선택 3회**가 든다 → 재선택 0회가 목표값 |
| **C2** | 결론이 스크롤 없이 보임 | **S2**(Platform Verdict) · **S4**(3-Tier 카드) · **S5**(Program Verdict) | 1440×900 과 390×844 둘 다에서 `scrollY = 0` 상태로 결론 문장 전체가 보인다. S4 는 카드 3장 중 **추천 tier 1장의 회수기간**까지 보이면 통과 |
| **C3** | 콘솔 에러 0 | **S1·S3**(지도 두 탭이 위험원) · 나머지 단계도 누적 관찰 | Playwright `console`·`pageerror` 리스너를 S0 부터 S5 까지 켜 둔 채 완주 — 3거점 × 6단계 전부 0. 지도 SDK 인증 실패·`naver` undefined 가 여기서 잡힌다 |
| **C4** | 지도 렌더 3초 이내 | **S1**(거점 경계) · **S3**(공실 폴리곤) | 탭 클릭 시각 → 첫 폴리곤/경계 오버레이가 지도에 붙는 시각. 각각 3.0초. S3 은 `src === "api"` 로 뜬 뒤를 잰다(샘플 폴백은 빨라도 통과가 아니다) |
| **C5** | 모든 수치가 출처를 말함 | **S1**(실측/합성 배지·앵커) · **S2**(Verdict 출처 줄) · **S4**(입력 출처 배지 4개) · **S5**(생성 근거) | 화면에 뜬 숫자를 세고, 각 숫자 옆·아래에 출처 라벨이 있는지 1:1 로 맞춘다. `추정`·`시드`·`전제(0)` 는 **그렇게 적혀 있으면 통과**(정확도가 아니라 정직성을 잰다) |
| **C6** | 3거점에서 같은 조작이 같은 자리 | **S1~S5 전부**, `yeonnam·sinchon·hongdae` 3회 반복 | 같은 클릭 좌표·같은 순서로 세 번 완주한다. 거점 전용 분기 화면 0개. 신촌은 반경·공실률이 달라 **지도 줌·범례 눈금이 거점마다 다르게 잡히면 C6 실패**로 본다 |

**단계별로 다시 보면** — 한 단계가 지는 조건이 무엇인지가 이 표의 요점이다.

| 단계 | 걸린 통과 조건 |
|---|---|
| S0 서울 | C1 |
| S1 거점 | C1 · C3 · C4 · C5 · C6 |
| S2 Platform | C1 · C2 · C5 · C6 |
| S3 Page | C1 · C3 · C4 · C6 |
| S4 Posting | C1 · C2 · C5 · C6 |
| S5 Program | C2 · C5 · C6 |

## 3. 5분 예산

| 단계 | 배정 | 근거 |
|---|---|---|
| S0 서울 | 0:15 | 첫 화면을 읽고 레일로 손이 가기까지 |
| S1 거점 | 0:45 | 검색 입력 + 지도 이동·요약 읽기 |
| S2 Platform | 1:00 | 결론 1줄 + 근거 3줄을 읽는 시간 |
| S3 Page | 1:15 | 줌·건물 클릭·층 스택/거리뷰 |
| S4 Posting | 1:15 | 자리·업종·권리금 입력 + 세 카드 비교 |
| S5 Program | 0:30 | 결론과 근거 확인(생성 대기는 별도) |
| **합** | **5:00** | 초과하면 시나리오 실패로 본다 |

## 4. 이 시나리오가 성립하려면 만들어야 하는 것 (④ 칸의 총합)

우선순위는 **완주를 막는 순서**다.

| # | 만들 것 | 막고 있는 단계 | 걸린 통과 조건 |
|---|---|---|---|
| **②** | **거점 선택을 앱 공용 상태로** — `#hub=` 를 6개 탭이 공유한다. 지금은 네 탭이 각자 `garosugil` 로 시작해 사용자가 같은 거점을 3번 다시 고른다 | S1→S2→S3→S4 | C1 · C6 |
| **④** | **층별 공실 매물 목록(296건)을 Page 탭 안으로** — 지금은 `#board` 해시 화면에만 있어 레일에서 닿지 않는다 | S3 | C1 |
| **①** | **서울 구 카드 → 거점 진입 링크** — 첫 화면에서 나가는 길 | S0 | C1 |
| **③⑤** | **트랙 간 이어가기 버튼** — Platform 자리 카드 → Page/Posting, Posting 결과 → Program | S2 · S4 | C1 |
| **—** | **Page 층별 매물 ↔ Posting 자리 인벤토리 연결** — 296 vs 12. 자리 수를 늘리는 문제가 아니라 **"층별 공실 296곳 중 조건 적합 12곳"** 이라고 화면이 말하고, 매물에서 계산으로 넘어가게 하는 문제다 | S3→S4 | C1 · C5 |
| **⑥** | **Program 창업 前 모드** — 가게 대신 자리+업종으로 상권 근거만 써서 홍보안을 낸다 | S5 | C5 |

⚠ 위 여섯은 **없는 기능**이다. 이 문서는 그것들이 있다고 전제하고 시나리오를 쓰지 않았다 —
지금 6개 탭으로 김민수가 실제로 걷는 길을 적고, 끊긴 자리에 무엇을 놓아야 하는지만 표시했다.
