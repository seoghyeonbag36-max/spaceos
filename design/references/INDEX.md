# 디자인 레퍼런스 — 무엇을 보고 무엇을 가져오는가

> [plan-design-upgrade-2026-09.md](../../docs/plan-design-upgrade-2026-09.md) **§6 D3** 의 산출물.
> 그 문서 §0-3 의 규칙을 그대로 따른다 — **레이아웃·인터랙션 패턴·정보 위계는 보고 배운다.
> 배포된 JS/CSS 번들은 복사하지 않는다**(라이선스). 여기 적힌 "가져올 것"은 전부
> *우리 토큰·우리 컴포넌트로 다시 짠 결과물*을 가리킨다.
>
> 각 항목의 마지막 칸이 **코드 착지점**이다. 착지점이 비어 있으면 그건 레퍼런스가 아니라 감상이다.

## 이 문서를 읽는 법

PlaceOS 는 지도 위에 **네 트랙(PPPP)** 을 얹는 앱이다. 그래서 레퍼런스도 셋으로 나눠 본다.

| 층 | 우리가 못 하고 있는 것 | 여기서 배운다 |
|---|---|---|
| **A. 지도 ↔ 목록** | 1,133동짜리 목록과 지도가 서로를 모른다 | Zillow · Redfin · 호갱노노 · 네이버부동산 |
| **B. 결론 위계** | 화면이 결론·근거·원자료를 동시에 편다(1069/932/908줄) | Placer.ai · CoStar · 골목상권 · Linear |
| **C. 한글 · 모바일** | 바텀시트 컴포넌트가 있는데 화면이 안 쓴다 | 토스 TDS · 당근 · 네이버지도 |

# 1. 국내

## 1-1. 호갱노노 — *지도가 곧 필터다* ★최우선

<https://hogangnono.com/>

아파트 실거래가를 지도 위에 얹는다. 우리와 **가장 구조가 같은 국내 서비스**다 —
"지도 위 수많은 점 + 좌측 목록 + 상단 레이어 토글"이 그대로 겹친다.

| 관찰한 기제 | 왜 되는가 | **가져올 것 (코드 착지점)** |
|---|---|---|
| 지도 위 카드·필드를 **흰색 + 그림자**로 띄워 지도 레이어와 공간을 가른다 ([출처](https://goeuny.medium.com/%EC%9D%B4%EB%9F%B0-%EC%A7%80%EB%8F%84-ui-%EB%B3%B4%EC%95%98%EB%8B%88-6f3dd7b4844e)) | 지도는 배경이 통제 불가라 테두리로는 안 갈린다. 그림자가 z축을 만든다 | 이미 `--shadow-card` 로 되어 있다 → **유지**. 새 오버레이도 반드시 이 토큰 |
| 필터가 **매매/전세·평형·세대수·금액·용적률·갭·수익률** 등 다축이고, 켠 필터가 칩으로 남는다 | 조건을 기억시키지 않는다 — 화면이 대신 기억한다 | `MapShell` 의 `building-filters` 에 활성 필터 칩·전체 해제가 이미 있음 → 칩에 **결과 수**를 붙인다 |
| **[주변] 레이어**(학교·상권·학원가)를 본 데이터 위에 겹쳐 켠다 | 판단은 한 축으로 안 난다. 겹쳐야 "여기가 왜 비었나"가 보인다 | `MapShell` 레이어 토글이 지금 **배타 선택**(하나만)이다 → 후순위 과제로 남긴다(R6) |
| 지도를 움직이면 목록이 따라온다 | 화면 밖 매물은 사용자에게 존재하지 않는다 | ★ **R2 뷰포트 동기화** — `MapShell.tsx` 에 이미 `zoom_changed` 리스너가 있다. `idle` 을 더해 목록을 현재 화면 범위로 좁힌다 |

**안 가져오는 것**: 가격을 지도 위에 숫자 라벨로 직접 박는 것. 우리 거점은 1,000동대라 라벨이 서로 겹쳐 죽는다(호갱노노는 단지 단위라 밀도가 한 자릿수 배 낮다).

## 1-2. 네이버 부동산 / 네이버 지도 — *우리가 얹혀 사는 집*

<https://new.land.naver.com/> · <https://map.naver.com/>

우리는 네이버 지도 SDK 위에서 돈다([feature-design-system.md](../../docs/feature-design-system.md) §2).
**이 둘과 한 화면에 있어도 안 어색한 것**이 디자인 목표다 — 즉 레퍼런스가 아니라 **제약**이다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| 좌측 **아이콘 레일** + 그 오른쪽 전체가 지도 | 이미 이식됨 — `App.tsx` `rail` · `--rail-w`(2026-08-29). **유지** |
| 매물 클릭 → 좌측 패널이 **목록→상세로 밀려 들어간다**(페이지 이동 아님) | 이미 이식됨 — `MapShell` `b-detail` + `← 건물 목록`. **유지** |
| 거리뷰가 지도와 같은 화면에서 열린다 | 이미 이식됨 — `BuildingViewer` + `lib/naverMap.ts` |
| 줌 단계마다 **표시 단위가 바뀐다**(구 → 동 → 단지 → 매물) | `MapShell` 은 지금 줌 15/16 에서 핀↔폴리곤만 바꾼다. 줌 ≤13 에서 거점 단위 집계로 한 단 더 올리는 것은 후순위(R7) |
| 네이버 그린 `#03C75A` 은 네이버 기능(길찾기·페이)에만 | **제약** — 트랙 색으로 쓰지 않는다. `tokens.css` 주석에 이미 박혀 있다 |

## 1-3. 알스퀘어 RA — *B2B 상업용 부동산 데이터, 국내 최근접*

<https://www.rsquare.co.kr/> · [RA 분석 솔루션 소개](https://www.venturesquare.net/1067054/)

오피스·물류 중심으로 **건물/토지 정보 · 임대 시세 · 공실률 · 거래 이력을 통합 조회**하고,
지도에서 조건을 걸어 주변 경쟁 자산을 비교한다. 2026년에 **약 250만 기업의 재무·등기·공시를
부동산 데이터와 결합**하는 기능을 붙였다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| 한 건물을 열면 **공실률 · 시세 · 거래이력**이 한 카드에 같이 선다 | `MapShell` `b-detail` 이 이미 공실률·수용/영업·업종을 편다. 여기에 **출처·갱신일** 한 줄을 더한다(R8) — B2B 는 숫자보다 출처를 먼저 본다 |
| **주변 경쟁 자산 비교** | `CandidateCompare`(후보 3개 비교)가 이미 있다 → 비교 축에 **앵커 격차(R-ONE 대비)** 를 넣는다(R8) |
| 부동산 데이터 × 기업 데이터 결합 | 우리 대응물은 Platform 트랙의 **GNN 업종 추천**이다. 구조를 베끼지 말고 "이 자리에 어떤 업종"이라는 우리 축을 지킨다 |

**안 가져오는 것**: 오피스·물류 축(전용률·주차대수·기준층 면적). 우리 축은 **1층 상가·층별 공실**이다.

## 1-4. 네모(NEMO) — *상가 임대 거래, 소상공인 접점*

<https://www.nemoapp.kr/>

상업용 부동산 **거래**에 초점. 우리 Posting 트랙(입점 의사결정)의 바로 다음 단계다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| 매물 카드에 **보증금 / 월세 / 권리금**이 고정 순서로 선다 | `PostingConsole` 3-Tier 카드의 항목 순서를 티어마다 같은 자리에 고정(R8) |
| 조건을 넣으면 **"이 조건의 매물 N건"** 을 먼저 숫자로 답한다 | 우리도 필터 결과를 **먼저 수로** 말한다 → R2 의 건수 표시와 같은 착지점 |

## 1-5. 서울시 상권분석서비스(골목상권) · 소상공인 상권정보시스템 — *공공 데이터의 정본*

<https://golmok.seoul.go.kr/> · <https://sg.sbiz.or.kr/>

45종 빅데이터로 자치구·상권별 **생존률 · 평균매출 · 임대시세**를 무료로 준다
([서울 열린데이터광장](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do)).
생활밀접업종을 **외식 10 · 서비스 47 · 소매 43 = 100업종**으로 분류한다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| **업종 분류 체계가 공개 표준**이다 | 우리 GNN 업종 라벨이 이 분류와 어긋나면 지자체 미팅에서 대조가 안 된다 → `ml/` 라벨 매핑 문서화(코드 변경 아닌 확인 과제) |
| 상권을 고르면 **"이 상권은 ○○형"** 한 줄 요약이 먼저 뜬다 | ★ **R3** — `PlatformConsole` 의 상권 정체성이 여러 카드에 흩어져 있다. 결론 1줄을 맨 위로 |
| **영역 면적**을 같이 줘서 매출·유동인구를 면적으로 나눠 볼 수 있게 한다 | 밀도 비교 시 **분모를 명시**한다 |

**이것이 우리의 무료 경쟁자다.** 차별점은 한 줄로 좁혀 말해야 한다 —
공공은 **상권 단위 집계**, 우리는 **건물·층 단위 실측**이다. 화면이 그걸 말해야 한다.

## 1-6. 토스 TDS · 당근 — *한글 위계와 바텀시트*

<https://toss.tech/article/toss-design-system> · [TDS 타이포그래피](https://tossmini-docs.toss.im/tds-react-native/foundation/typography/) · [TDS 컬러 시스템 개편](https://toss.tech/article/tds-color-system-update)

|---|---|---|
| 컴포넌트에 **position** 을 체크리스트 항목으로 둔다(다이얼로그냐 바텀시트냐) | [TDS 컴포넌트 제작기](https://toss.tech/article/tds-component-making) — 안드로이드에서 **바텀시트가 메뉴보다 클릭율 10% 높았다** | ★ **R4** — `design/components/BottomSheet.tsx` 를 **아무 화면도 안 쓴다**. 모바일(≤768px)에서 `MapShell` 사이드패널을 바텀시트로 내린다 |
| 글자가 커질 때 **글자 단위 개행 + 아이콘도 같이 커진다** | TDS 접근성 대응 | 우리 `--fs-*` 5단은 고정 px 이다 → 최소한 **한글 어절 단위 개행**(`word-break: keep-all`)을 전 화면에 건다(R5) |
| 색 시스템을 7년 만에 갈아끼우면서 **역할(semantic) 이름으로만 쓰게** 했다 | [컬러 시스템 업데이트](https://toss.tech/article/tds-color-system-update) | 우리는 이미 `--track-*` · `--ink` · `--muted` 로 역할명이다 → **하드코딩 hex 463곳**을 계속 줄인다 |

# 2. 해외

## 2-1. Placer.ai — *위치 인텔리전스 대시보드, 우리 Platform 트랙의 원형* ★최우선

<https://www.placer.ai/>

유동인구로 **방문수 · True Trade Area · 인구통계 · 교차방문 · 경쟁 벤치마킹**을 낸다.
속성/체인/산업 단위 리포트를 UI 에서 직접 만든다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| **벤치마킹이 기본값**이다 — 한 지점의 수치를 혼자 두지 않고 항상 "경쟁/평균 대비"로 놓는다 | ★ 우리는 이미 **앵커(R-ONE) 격차**를 갖고 있는데 `MapShell` 헤더 한 줄에만 있다 → **R3** 의 근거 칩에 Δ 를 싣는다 |
| **True Trade Area** — 행정경계가 아니라 실제 방문 분포로 상권을 그린다 | 우리 거점 경계는 "우리가 잰 범위"지 상권 경계가 아니다([screen-hub-explorer](../../docs/screen-hub-explorer.md) §1) → 이 **불변 조건을 캡션으로 노출**한다 |
| 리포트가 **결론 문장 → 차트 → 원자료** 순서로 고정 | ★ **R3** — `KeyFinding` 컴포넌트로 표준화 |

## 2-2. CoStar / LoopNet — *상업용 부동산 데이터의 세계 기준*

<https://www.loopnet.com/> · <https://www.costar.com/>

600만+ 물건, 1,100만+ 임대·매매 comps, 3,000+ 마켓/서브마켓.
**property type · status · size · age · rating** 으로 거른다.

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| **저장 검색 + 신규 매물·만기 임대 알림** | 우리 `savedOnly` · `candidate-tray` 는 세션 한정이다("이번 작업 동안 유지") → 저장 조건을 **URL 해시에 실어** 공유·재방문 가능하게(R9) |
| **두 제품을 나눈다** — LoopNet(공개·마케팅) vs CoStar(전문가·comps) | ★ 우리도 같은 분기가 필요하다: **랜딩(공개)** vs **앱(실측)**. [plan §0](../../docs/plan-design-upgrade-2026-09.md) 와 같은 결론 — 외부 사례가 이를 지지한다 |
| 물건 카드에 **중개인·연락처**가 항상 붙는다 | 우리 대응물은 **데이터 출처·갱신일**이다(§1-3 과 같은 착지점 R8) |

**안 가져오는 것**: comps 중심 정보구조. 우리 상품은 거래 이력이 아니라 **공실 예측**이다.

## 2-3. Zillow / Redfin — *지도 ↔ 목록 동기화의 교본* ★최우선

<https://www.zillow.com/> · <https://www.redfin.com/>

Zillow 는 **최대 5개 지역을 한 번에** 검색하고 그 결과를 지도에서도 같은 피드에서도 훑게 한다
([2022 발표](https://zillow.mediaroom.com/2022-07-21-Zillows-new-tool-powers-home-searches-in-up-to-five-areas-at-once,-letting-shoppers-move-as-fast-as-the-market)).
"스크롤 인벤토리 UX 가 가장 낫다"는 평가가 반복해서 나온다
([앱 비교 2026](https://unstar.app/blog/zillow-redfin-realtor-trulia-home-search-apps-ranked-2026)).

| 관찰한 기제 | 왜 되는가 | **가져올 것 (코드 착지점)** |
|---|---|---|
| ★ **호버 동기화** — 목록 카드에 마우스를 올리면 지도의 해당 도형이 뜨고, 반대도 된다 | 1,000개 중 "지금 보는 그거"를 눈이 못 찾는다. 동기화가 그 탐색을 없앤다 | **R1** — `MapShell` 에 `hoveredId` 추가 → 목록 `onMouseEnter` ↔ 폴리곤/마커 `setOptions` 강조 |
| ★ **지도를 움직이면 목록이 그 범위로 좁혀진다** | 목록과 지도가 다른 걸 보고 있으면 사용자가 둘 다 못 믿는다 | **R2** — `idle` 리스너 + `map.getBounds().hasLatLng()` 로 목록 필터 |
| 다중 지역 동시 검색 | 출점팀은 한 동네만 보지 않는다 | **후순위** — 우리는 거점 선택이 단일이다. 66거점 비교는 `HubExplorer` 몫 |

## 2-4. Felt · Kepler.gl · CARTO — *지오공간 레이어 UI*

<https://felt.com/> · <https://kepler.gl/> · <https://carto.com/>

| 관찰한 기제 | **가져올 것 (코드 착지점)** |
|---|---|
| 레이어를 **목록으로 쌓고 각각 켜기/투명도**를 준다 | 우리 4레이어(공실·임대·유동·밀도)가 지금 **배타 선택**이다 → 겹치기는 후순위(R6) |
| 범례가 레이어를 따라 **자동으로 바뀐다** | 이미 되어 있다 — `MapShell` `legend` 가 `layer` 로 분기. **유지** |
| 시간 축이 있으면 **타임 슬라이더**를 지도 아래 고정 | 이미 되어 있다 — `time-bar`(유동인구 시간대). **유지** |

### R10 — 2026-09-13 검증 중 발견

`MapShell.tsx` 의 `PIN_MAX_ZOOM = 15` 는 "줌 15 **이하**면 공실의심만 점으로, 초과면
폴리곤"이다. 그런데 **거점을 열었을 때의 기본 줌은 16 이다**(실측: 타일 URL
`…/styles/basic/…/16/55892/25387.png`, 신사동 가로수길 1440×900).

즉 16 > 15 이므로 기본 화면은 **언제나 폴리곤 모드**고, 840동이 4색으로 전부 칠해진다 —
2026-09-06 디자이너 피드백 「공실을 red-dot 혹은 핀으로」가 지적한 바로 그 화면이다.
핀 모드는 구현돼 있지만 **사용자가 일부러 축소해야만** 닿는다.

- 고치는 법은 한 줄이다: `PIN_MAX_ZOOM` 을 15 → 16.
- **임의로 바꾸지 않았다.** 앱을 여는 모든 사람이 보는 첫 화면이 "건물 색 지도"에서
  "빈 곳만 찍힌 점 지도"로 바뀐다. 어느 쪽이 우리 제품의 첫인상이어야 하는지는
  코드가 아니라 사람이 정한다.
- 결정 전에 볼 것: 줌 15 와 16 에서 각각 캡처해 나란히 놓고, 데모에서 어느 쪽이
  "어디가 비었나"에 먼저 답하는지 본다.

⚠ plan §7-1 의 **7번(4P 플로우 순서)** 은 여기 레퍼런스로 안 풀린다 — 위 어느 서비스도
"네 단계를 순서대로 태우는" 제품이 아니다. 우리 고유 과제로 따로 남긴다.
