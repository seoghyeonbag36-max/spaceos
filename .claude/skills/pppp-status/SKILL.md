# 리드 오케스트레이션: PPPP 전 트랙 점검

너는 SpaceOS **총괄 리드의 오케스트레이터**다. 한 트랙이 아니라 PPPP 전체를 본다. `CLAUDE.md`를 따른다.

## 1) 진행률 — 손으로 세지 말 것

```
python scripts/pppp_status.py
```

트랙별 진행률과 **게이트별 값·근거**를 찍는다. 읽기만 하고 네트워크를 타지 않는다.

거점 축은 `python scripts/chain_status.py --all --next` 가 따로 낸다 —
트랙 진행률이 "어느 거점에서 막혔는지"를 안 보여주기 때문이다. 둘을 같이 읽는 절차는 `loop-engine`.

숫자를 직접 세거나 문서에서 읽어오지 마라. `docs/spaceos-vibe-build-sequence.md` 는
이미 두 번 낡았다(Tier1 을 13, 그 다음 22 로 적고 있었다 — 실제 49). **산출물이 단일
기준이고, 그걸 세는 것이 이 스크립트다.**

읽는 법:

- `[자동]` 은 산출물을 세어 계산한 값, `[선언]` 은 사람이 적어 둔 값이다.
  **선언 게이트는 근거 경로를 보고 여전히 참인지 확인**한 뒤 인용한다. 오늘 바뀐
  영역이라면 특히 그렇다(선언이 낡는 것이 이 프로젝트의 주된 실패 양식이다).
- 트랙 진행률은 게이트 **동일 가중 평균**이다. 가중치가 없으므로 큰 게이트 하나가
  작은 것 여럿에 묻힐 수 있다 — 보고할 때는 %만 옮기지 말고 **막고 있는 게이트를
  같이** 적는다.
- 게이트가 0% 인 항목은 "안 했다"와 "못 한다"가 섞여 있다. 아래 2)에서 갈라라.

## 2) 막는 것의 종류를 구분한다

0%·부분 게이트를 **"안 정했다" / "못 얻는다" / "시간만 필요하다"** 로 나눈다.
셋은 대응이 다르다 — 미착수로 뭉뜽그리면 착수만 하면 되는 것처럼 읽힌다.

| 종류 | 뜻 | 오늘 할 수 있는 것 |
|---|---|---|
| 안 정했다 | 제품 판단이 없다 | **지금 정하면 풀린다** — 최우선 후보 |
| 못 얻는다 | 자료·승인·채널이 없다 | 신청·결정을 오늘 넣어두고 다른 걸 병행 |
| 시간만 필요 | 쿼터·학습시간 | 예약해 두고 잊는다 |

## 3) 오늘 작업 제안

- 진행률 + 오늘 입력(호출 인수 — 집중할 트랙/거점. 비었으면 KPI 우선순위)에 맞춰
  **트랙별로 1개씩, 총 3~5개** 작은 작업을 우선순위와 함께 제안.
- 각 작업에 진입 슬래시 명령을 표기 (예: `/page 유동 레이어 실배선`).
- KPI 기준: ① 기술 완성도(데모 가능 / 정확도 70%+ / 지도·건물 상세 로딩 <3초) ② PMF(B2B 파일럿 5~10건).
- **쿼터성 작업은 먼저 확인한다** — 건축HUB 는 하루치가 사라지므로, Page 수집이
  후보라면 `python scripts/quota_preflight.py` 로 오늘 남았는지부터 본다.

## 4) 출력

- 트랙 표(진행률 · 막고 있는 게이트 · 다음 작업 · 진입 명령) + "오늘의 추천 순서" 한 줄.
- 진행률을 옮길 때 **선언 게이트에 기댄 값이면 그렇다고 밝힌다.**
- 내가 고르면 해당 슬래시 명령으로 전환해 진행한다.

## 게이트를 고칠 때

트랙 구성이 바뀌면 `scripts/pppp_status.py` 의 `*_track()` 함수를 고친다.
**선언 게이트를 새로 추가할 때는 `evidence` 를 반드시 채운다** — 근거 없는 선언은
다음 사람이 검증할 방법이 없어서, 낡아도 아무도 모른다.
